`00-product-design:20`「NeonForge 是为 **DeepSeek** 打造的 AI 问题工作台」——供应商进战略层；而 §1 模型策略明写 provider 可切换（ADR-007/010：DeepSeek 官方／Command Code／OpenCode Zen/Go）。定位、品类、模型选型是三层，现被压成一句。

### C4 · 用户二元性从未在 L0 闭合，但 L5 已经事实分裂

- `00-product-design:73`「不会写代码的人（**V1 主**）」＋`:74`「会写代码的开发者」——同一 V1 两类人，主/次只由一个括号决定。
- 而原则②③所要求的「方案卡＝文件清单＋假设＋**验证计划**」（`:339`、`§3.6`/`§5`）、「证据对账」（`§4.2`）、「宿主边界」（`§5`）**对不会写代码的人不可解**——他无法 review `files[].path` 与 `verificationPlan`。

### C5 · 产品文本的生长方式（元问题）

## 3. L0 定稿（2026-10-05 四裁）

> 四裁原文摘要：**① V1 只服务不会写代码的人，开发者面降 V2；② 定位维持「AI 问题工作台」，provider 下沉模型策略层，**0-1 交付属普通用户诉求保留**，部署／编辑器等开发者面降 V2；③ 北极星只留**问题关闭率（解决确认）**，余三候选降级；④ 执行形状＝**先定 L0 母本，再逐层重写**。

### 3.1 定位（唯一定义处＝本节；其余各处只能引用）

**NeonForge 是 AI 问题工作台**：用户用自然对话说出**当前的问题**，产品通过内在的工程／设计／编排自动推进，交付**可验收的解决**。

- **不含实现选型**：「为 DeepSeek 打造」从定位句移除（C3 结案）——provider 属 §1 模型策略层且可切换（ADR-007/010）。定位／品类／模型策略是三层。
- **品类否定式保留**：不是 IDE（编辑器为中心）、不是 Chatbot（只聊不交付）、不是多模型客户端。
- **成功定义**（ADR-011 同脉）：问题被解决＝命题为真，不是调用返回、不是外壳跑完。

### 3.2 用户（V1 唯一）

- **V1 唯一用户＝不会写代码的人**：说出问题 → 被解决 → 拿到数字产物＋人话说明＋下一步指导。**产品的一切验收口径必须他能给**——他给不出的验收（读懂 `files[].path`、判断 `verificationPlan` 是否可信）一律不得作为 V1 的门槛形式。
- **开发者面＝V2**：可展开技术细节、手动编辑（编辑器）、异常修复闭环（定位→方案→修复→测试→部署→复核→反馈）、部署授权。原 §1.4「两类用户一套内核双视图」**降为 V2 能力**，V1 文本不再把它当现行承诺。
- **0-1 交付留在 V1**（裁定明确：它是普通用户诉求——"我想要一个东西"），但其验收形式必须走人话路径（§3.3 柱③）。

### 3.4 北极星（唯一定义处＝本节）

**问题关闭率（解决确认率）＝被证据对账通过且用户确认解决的问题数 ÷ 发起的问题数。**

其余三个候选**降级但不删除**（"删三个"指的是删掉它们作为北极星的地位）：

| 旧"北极星"           | 新地位                                                | 处置                                        |
| -------------------- | ----------------------------------------------------- | ------------------------------------------- |
| 每周完成写入的任务数 | **过程指标**（写入是手段，不是价值）                  | `07 §1` 定义句删，保留在 Leading Indicators |
| 二次委托率           | **护栏指标**（PMF 信号，Beta 起看）                   | `07` 移到 Guardrail；`marketing:102` 同步   |
| 撤销率               | **删除**——"撤销"一词已于 ADR-023 整体退役，采点无定义 | `marketing:102` 去掉                        |

### 3.5 反指标（随新权限模型重写）

保留三条（不回测数据／不刷活跃／不以机械确认速度为成功），第四条改写：**"不牺牲可控性"的旧口径含『审核在方案层完成后的清单内自动放行不违反本条』——该例外随 ADR-024 F9-3 失效**（清单不再是 allow 的唯一来源，自动放行改由作用域决定）。新口径：任何为提高关闭率而**取消求决（ask）**或**放开机密/高危**的改动，一律禁止（下限档见 ADR-024 决定 4）。

### 3.6 我替你解读的两处（若与原意不符请纠）

1. **0-1 交付留在 V1**——按你"0-1 交付是普通用户诉求"落；我只把**部署／编辑器／技术细节展开／异常修复闭环**降 V2。
2. **二次委托率不作废、降为护栏**——按"北极星只留一个"的字面，其余候选降级而非删除；若你要它彻底移出指标表，我再删。
