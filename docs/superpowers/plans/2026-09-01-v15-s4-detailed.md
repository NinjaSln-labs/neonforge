## Task 4.4：A-015（对账失败用户提示）/ A-016 终核

### A-015 现状

- **来源**：`stage-review-fixes-2026-08-31` Spec P-3（open）
- **现象**：S4 对账不过时系统打回模型重试，但用户侧无任何提示——用户不知道发生了什么
- **修复方向**：对账失败时 → 状态栏/对话内提示「证据对账未通过，正在要求搭档补充证据」

**文件**：`apps/desktop/src/renderer/ConversationPanel.tsx`

### A-015 Step 1：定位对账失败路径

在 `verifyThenResolve(claim)` 内部，对账失败（`ok=false`）时打 `completion.evidence_missing` 事件 + 回填引导。确认该路径已有打点，但用户侧无可见提示。

搜索 `verifyThenResolve` 和 `evidence_missing` 在 ConversationPanel.tsx 中的位置：

```bash
grep -n "verifyThenResolve\|evidence_missing" src/renderer/ConversationPanel.tsx
```

### A-015 Step 2：实现用户侧提示

在 `verifyThenResolve` 调用处（L865 附近），当 `verifyThenResolve` 返回 `evidence_missing` 时，在对话中注入一条可见的系统消息（类似 `protocolResult` 方式）：

```typescript
// 在协议工具 'pending' 分支的 resolution 处理中（L844-848 附近）：
// 当前：protocolResult = '完成声明已提交——系统核验中，等待用户确认'
// 改为：verifyThenResolve 内部 evidence_missing 时，通过 tlog 或状态更新给用户可见提示
```

**方案**：`verifyThenResolve` 是异步函数，在当前实现中 `protocolResult` 在同步 updater 中设置。异步回调无法直接修改 protocolResult。替代方案：

1. 在 `verifyThenResolve` 的 `evidence_missing` 分支中，通过 `tlog` 记录一条系统角色消息（`'system'`）显示在对话中
2. 或修改 `setPendingState` 携带一个 `userHint` 字段，渲染层在状态栏展示

**推荐方案**：在 `verifyThenResolve` 的 `evidence_missing` 路径中，把 `protocolResult` 改成带提示的文本。但 `protocolResult` 在 updater 中已设置... 实际 `verifyThenResolve` 返回的 promise 被 `void` 掉了，没有 await。

更简单的实现：在 `verifyThenResolve` 内部 evidence_missing 时，在它调用的 setPendingState（ok=false 不置 resolution）之前，先 tlog 一条 `conversation.status_change` 事件，渲染层在对话状态栏展示「证据对账未通过，正在要求搭档补充证据」。
