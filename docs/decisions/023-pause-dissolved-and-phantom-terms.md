# ADR-023：「暂停」不建本体——词汇溶解（＋并列清单未思考产物的治理令）

- 状态: **accepted**（2026-10-05 用户裁定方向；本 ADR 由合作负责人落笔，范围＝溶解裁定＋词义定名＋治理令＋残留搬家，不含实现）
- 日期: 2026-10-05
- 起因: 缺口 **G11**（上一批四轴互审新增，我当时建议"暂停要新状态轴"）——**该建议被用户否证**，本 ADR 记录否证与更正
- 相关: ADR-016 规则 1（域归属三问）／**规则 4（错位走溶解）**、ADR-019、ADR-021（I-T1–I-T18）、ADR-022（§3.8 两轴）、`00 §3.7.2` 出口④／`§3.7.5⑤`／`§4`、`00-product-design §1.2/§4.1/§4.2/§4.5 C1·C4·C9`、`10-model-evolution §3D`

## Context（用户裁定原文）

1. 「暂停？我想可能是之前模型想错了。用户按得不是暂停，其实是打断，停止。不是暂停得意思，要不是继续-打断（停止）」
2. 「你列一下暂停得概念是在什么流程里？」
3. 「产品 §4.1 撤销/回滚 是一个概念，我发现之前得 LLM 模型很多都是没有思考得产物」

**清点结果（"暂停"在自家文本/实现里共六处，横跨三根轴）**：

**外部取证（六家，逐条 VERIFIED）**：无人做 token 级续跑。OpenHands `pause()` 明确**不停在飞 LLM 调用**（`local_conversation.py:2719-2727`）、resume＝边界重入；Cline 相位注释逐字「task cancelled / interrupted; Resume Task」（`ExtensionMessage.ts:161`）＝**取消＋保留历史＋开新轮**；LangGraph resume＝**整节点重跑**（`types.py:908`，副作用重放是其代价）；Temporal 是唯一真暂停，但停的是**任务派发**、Activity 照跑完；Codex/Claude Code/Gemini CLI/opencode/Goose/aider 回合级无 pause（Codex 仅 `TurnAbortReason{Interrupted,Replaced}`）。⇒ **工业形状与用户裁定同形：停手处的"暂停"实质是 cancel。**

## Decision

1. **轮次轴只有"继续"与"停止"**，不建 `Paused` 态、不建许可位、不引第三根面（依 ADR-016 规则 4 溶解）。三处落点写进 `00 §3.7.5⑤`：用户侧＝显式打断（`§3.7.2` 出口④）；系统侧死循环＝**无推进的终态化**（`Settled{Failed|Empty}`）＋停手告知；"回复继续就接着做"＝一条普通 `user-input` TurnInput **成新一轮**（决策后重新做——§3.4·C1 同脉）。
2. **No-Hold 句**（同处写明）：**终态或被作废的轮不得被"恢复"——恢复永远是新轮**。这是 I-T2／I-T10 的推论，写下来的目的只有一个：防实现批造出 `resumeTurn()` 这类语义（工业界无人这么做，且 Round＝一次不可分往返＝I-T11 本无落点）。
3. **"撤销"整体退役**（用户追加裁定：「收回授权 实际不需要这个能力，要不用户授权，要不用户拒绝，不存在用户授权后临时撤销收回得概念，授权后搭档在思考执行，用户唯一可做得就是打断」）。三条事实支撑：①**单次批准的撤销＝零承载**——`ApprovalRecord.state` 只有 `queued|pending|approved|denied|failed|expired|uncertain`（`02:186`），approved 之后没有任何回拨入口；②**手动收回信任/规则＝零承载**——领域只有 `clearSessionGrants`（**任务边界自动**清除，由 goalSeq 递增触发），**无 removeRule／无设置项／组件规格零命中**；③**收回文件＝回滚**，唯一机制 `.nf-bak` 按文件（`04:310/:323`、实现 `revertToolCall`/`.nf-toolcall__revert`），代码中不存在第二条 undo 通路。⇒ 授权后的可逆动**只有打断**（`§3.7.2` 出口④）＋**回滚**；"撤销"一词不设任何合法含义。随修五处措辞：`§1.2 原则 2`、`§1.3 表行`（"可撤销/无撤销"→"反悔无处可去，由打断＋回滚承接"）、`§4.1`、`§4.2 L4`（撤"可降级撤销"）、`§4.5 C9`（"不撤销'已经'"→"不回滚"）。
   - **本条是一次自我更正**：我上一批的处置是给"撤销"**定名**为 revoke——那是**把误名搬家而非溶解**（给了空词一个同样无承载的"合法含义"）。用户这句裁定击中的是我的补丁本身，登记为**未思考产物的第二层**：并列清单里挑出一个错词、然后为它编一个定义，比留着它更糟。
4. **治理令（针对"未思考产物"这个病灶，写成可复用的检查形状）**：文档里**任何"A/B/C"式并列清单，每个词单独过 ADR-016 规则 1 第三问——「移除后谁兜底」**；同义复写者删、跨轴者归位、无承载者要么开票要么撤诺。本批按此扫出四例：暂停（溶解）、撤销/回滚（定名）、**备份/回滚**（备份是回滚的手段，同一机制的两半——低危，登记）、**人工接管**（`§4.2` 与 ADR-001 里是"状态栏提示用户手动输入指令"＝呈现，不是状态——归呈现层）；**部署**（见 Decision 6——本例最重：违已裁不变式）。四例之外是否还有，按同一问句继续扫（本 ADR 只裁已扫出的四处，不承诺穷尽）。
   - **2026-10-05 用户追加裁定（治理令的形状改正）**：「别审计了，这两天领域驱动模型设计升级下，发现很多之前没有深追得审计问题。再审计只会再掉出新问题」⇒ **此令不作事后审计轮使用，改为「写时过闸」**：任何新写的权威文本，**落笔时**每个名词必须能答两问——①**移除后谁兜底**②**它属于哪根轴**（等待／推进／焦点／授权／作用域／任务）。答不出者当场删除或当场开票，不得留给下一轮人审。
   - **为什么不排新一轮审计**：这两天每一轮都换一根轴打（承载／取代／单源／可验／权限），所以每轮必有新发现——**"再审一轮"的成本恒定、收益不收敛**。取代它的是一条**可跑的机验清单**（落位批 DoD）：①退役词 grep 必零命中（暂停／撤销授权／部署授权／上一步／`submitIntent`／`queuedIntents`）；②同一律的措辞处唯一（grep 计数＝1）；③不变量↔coverage 行一一对齐；④跨文件引用带文件前缀且目标存在；⑤L1＋双 tsc 绿。
5. **残留搬家（不丢弃）**：①**停手后系统不该自己再开口**——本轮**不建**任何门（用户裁定：只有继续/停止），但这条需求不是零：外部一致证据是**凡有暂停处必建 fence**（OpenHands `_explicit_interrupt_generation` 使自动重启不能越过用户停手，`event_service.py:238-244`；Cline「**FENCE FIRST**：同步置取消栅栏再 await abort」，`sdk-task-control-coordinator.ts:69-109`；Codex 中断后 `clear_pending` 以免在飞批准等待被模型读成拒绝，`tasks/mod.rs:558-560`）。**不解决的确切故障＝我们的催推进／escalate 把用户刚按下的停止顶掉**（这正是 G7「nudge 触发条件」的射程）⇒ 列为 **G7 的必裁子项**，本批不建实现地基（I-T1 之后无 Running 轮时 nudge 会成轮＝现状可复现）。②队列暂停→N2。③"已自动暂停"文案是**渲染层硬编码 assistant 气泡＝未经模型的搭档发言**，违 §4.5 C1/C4（系统轮须走披露条）⇒ 实现批随修，语义已写入 `00 §4` 新行与 `06 stuck.escalated` 注。

## 追加裁定（同日·G12 权限域立案——对本 ADR 两笔的部分推翻）

用户随后裁定：「bash，部署授权，属于 **权限领域驱动模型** 里得……权限应该是分档，高危应该是兜底，普通文件读应该默认允许，**机密文件读需要授权**，改项目仓内应该默认允许，改其它目录文件需要用户授权，**授权应该可记录，可编辑**，应该有**沙箱模式/YOLO模式**等。」由此对本 ADR 两处更正：

1. **Decision 3 的②改判**：「手动收回/降级信任规则＝零承载」这个**事实**成立（领域无 `listRules`/`removeRule`、设置无规则管理入口），但**结论**错了——我当时据此撤措辞了事。用户正面要这项能力 ⇒ 它是**缺设计**而非空词。判据固化为：**"无承载"有两种——空头承诺（撤措辞）与未设计的真需求（开票）；分别是哪一种，看产品负责人有没有正面要它，不能由建模者单方结案。** 现登记为缺口 **G12**，提案＝`docs/design/permission-domain-model-proposal-2026-10-05.md`。
2. **Decision 6 的范围收窄**：本 ADR 只裁了"部署**不是**一档授权/不是一种动作属性"（溶解），**没有**也**不该**回答"部署在权限域里该怎么归档"——那是 G12 候选轴系（动作类型 × 作用域 × 模式 × 规则表，deny 为下限档）的事。**词汇溶解 ≠ 能力设计**；把前者当后者结案，就是本 ADR 治理令要防的那种省事。

## Consequences

- **正面**：不新增态＝不触碰 I-T1/I-T4/I-T5 的定义式（若建 `Paused` 态，`busy ≡ ∃ Running` 与"至多一个非终态轮"都要改写，且要为 Round 内中断造持久化——那是本不需要的复杂度）；产品四处措辞回归到两件实事；实现里那条无人认领的"自动暂停"首次有了领域落点。
- **代价**：措辞随修＝历史文稿（`01`/`00-product-design` 旧版与若干 audits）仍留旧词，只在本批改动处加注，不回改历史。
- **风险登记**：①G11 被误当"已设计"而消失——故 `10-model-evolution §3D` 就地标注"已裁＝溶解"，并把子问题写明去向；②**停止被自动驱动顶掉**在 G7 闭合前是**活缺陷**（不是理论风险），验收批若遇"我按了停止它又自己开口"应计入 G7 而非归属族；③"撤销"定名后，任何把"撤销"用作文件语义的新文本都属违令（grep 可检）。

6. **"部署"不建授权档（用户 2026-10-05 裁定＝溶解进"执行"）**：§1.2 原则 2 的「写入/执行/**部署**逐级授权」与 §4.1「部署授权（L4：备份→热更新→复核→反馈）」撤除——部署类命令（`npm run deploy`/`rsync`/`docker push`/`kubectl`）按 **command-head 判入 `hazardous`**，逐次单独确认、**永不进 session/persistent 信任**；§11 版本范围补一行「专用部署通道／部署工具——V1 不做」。**这条同时消掉一处产品↔领域正面冲突**：`02` 明载「bash 无 path 一律不进入信任；bash/高危永不进入 persistent 持久规则（产品裁定压过竞品 goose 形——ADR-017 §2）」，而产品文本却写出一档"可记住的部署授权"——并列清单里第三个词的代价比前两个大，因为它**违的是已裁不变式**。

- **边界**：本 ADR 不含实现；不含"手动规则管理"扩展（若要做——列出已记住的 session/persistent 规则并允许收回——那是**新能力**，须另开票并请示，不得以"补撤销"之名混进纠偏批）。
