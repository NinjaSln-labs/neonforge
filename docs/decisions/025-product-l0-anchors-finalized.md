# ADR-025：产品设计重构·L0 定稿（用户单一化／定位去 provider／北极星唯一／"柱"退役）

- 状态: **accepted**（2026-10-05 用户四裁；L0 定稿载体＝`docs/product/08-product-master-anchors.md`，本 ADR 只承载裁定、依据与取代关系）
- 日期: 2026-10-05
- 相关: ADR-011（成功＝领域命题成立）、ADR-016 规则 4、ADR-018／019／021／022／023／024、`00-product-design §1.1/§1.2/§1.4/§4.1/§11`、`07-success-metrics`、`.agents/product-marketing.md`、`docs/design/domain-model-reconstruction-design-2026-10-05.md`（概念账本与轴系）

## Context

用户裁定：「这次不只是这些，而是要对整个 neonforge 产品设计进行重构」「我发现之前得很多设计/术语等都是**简单复述我话的半成品，还没有标记需扩展，详细设计**」。五路概念清点（161 条：已详设 49／半成品 61／需扩展 15／纯呈现 6／空头 3）之后定位到病根：**不是下层没做完，是顶层锚没有单源**——最硬的一例是北极星有四个互斥定义（`07:13` 写入数／`07:30` 解决确认率「非写入」／`D0 §1.2` 表"问题关闭率＋二次委托率"／`marketing:102` 二次委托率），其中两个**在同一文件相隔 17 行**。

四裁（2026-10-05，逐字摘要）：**① V1 只服务不会写代码的人，开发者面降 V2；② 定位维持「AI 问题工作台」，provider 属模型策略层不入定位句，0-1 交付是普通用户诉求故留 V1，解决不了问题＝失败；③ 北极星只留问题关闭率（解决确认率），其余降级；④ 执行形状＝先定 L0 母本，再逐层重写。**

## Decision

1. **V1 唯一用户＝不会写代码的人**；开发者面（技术细节展开／编辑器＝可选能力／异常修复闭环／部署授权）**整块降 V2**。推论必须同批生效：**「非技术视图」不再是"可切换的双视图之一"，它就是 V1 的唯一视图**；"一套内核、双视图"（原 §1.4）作为 V1 承诺撤除。
2. **定位句去 provider**：「为 DeepSeek 打造」从 §1.1 移除——模型选型属 §1 策略层且可切换（ADR-007/010）。定位／品类／模型策略分三层。
3. **L0 锚的唯一定义处改设为 `08-product-master-anchors`**：定位 §3.1／用户 §3.2／主张 §3.3／北极星 §3.4／反指标 §3.5。`D0 §1.1/§1.2`、`07 §1`、`marketing` 全部降为**派生引用**——这是 M8（锚唯一性）得以机验的前提。
4. **北极星＝问题关闭率（解决确认率）**；写入数降**过程指标**（留在 §2 领先指标），二次委托率降**护栏**，撤销率**删除**（"撤销"一词已于 ADR-023 整体退役，采点无定义）。`07 §1` 旧定义句与 `:30` 的互斥由本次收口消除。
5. **原则是六条，"柱"自此退役**：§1.2 列 1 解决问题／2 分步授权／3 交付可验证／4 不装能／5 上手不学／6 安静可信。我这两天在 `08`／`10-model`／重构总纲／ADR-024 通篇写的「四柱」是**自造的数**，已全库改词。
6. **L1 承诺表（11 条）作为重构的验收骨架**：**3 条全空头**（P3-1 证据→交付包 acceptance 无生产链／P3-2 失败包无对象／P4-1 不装能无载体）、**2 条半空头**（P2-1 求决卡仍是技术件、P2-2 规则无身份 doctrine）、**6 条成立**。⇒ 面向用户的可验收承诺约三分之一今天没有任何载体，这个数字取代"感觉还差不少"成为重构进度的度量基线。

## Consequences

- **正面**：顶层锚第一次有了单源与机验条件（M8/M9）；北极星与领域语义（交付≠解决、ADR-011 命题成立）对齐；用户单一化让"验收口径必须由用户给出"成为可执行约束，而不是一句原则；"空头承诺＝3/11"成为可追踪基线。
- **代价**：①`D0` 的 §1.4／§3.8／§4.1／§4.2／§11 与 `07`、`marketing` 都要按母本重写（本轮已做 L0 收口与措辞更正，**逐层重写尚未开始**）；②北极星改口径后现有埋点要重绑（关闭率的采点＝`decision.resolved(kind=resolution)` ∧ `verifyCompletion` 通过，需核是否已全链可用）；③开发者面降 V2 后，`01` Flow 4/5 中面向开发者的分支与 `§3.5` diff 审核的技术化表述需重述为"人话路径"。
- **风险①**：0-1 交付留在 V1，但它的验收今天**仍是技术件**（PlanProposal 的文件清单＋验证计划）——若不重写卡面形式，柱③对普通用户继续是空头，这是降 V2 之后**最大的残留矛盾**（P2-1 半空头即此）。
- **风险②**：`08` 成为锚之后，若 `D0` 里仍留旧定义句原文（哪怕带"已失效"注），M8 的 grep 就会命中两处——**重写时旧句必须删除，不得只加注**。
- **风险③**：本轮两次造数（四柱／缺行）证明：**清点本身也会生产半成品**。因此账本里每条"缺什么"都必须带原文行号，且引用前必须开文件读该行（已并入 M 系列与 p000161 教训）。
- **边界**：本 ADR 只裁 L0；L2 契约按柱归组、L4 第0层谓词（`inside(p)`／沙箱拆名／机密表／假推进／回合边界／签名归一）、L5 采点重绑，依用户裁定的次序**逐层再做**，不在本 ADR 射程。
