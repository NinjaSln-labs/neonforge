# ADR-024：权限域立案——新立 Policy BC，三轴一表＋deny 下限档（G12 方向裁定）

- 状态: **accepted（方向裁定）**（2026-10-05 用户四裁；**落位未执行**——**用户已裁定不再追加人工审计轮**：落位批自带可跑机验清单作 DoD，见 ADR-023 治理令形状改正＋本文风险①的处置改法）
- 日期: 2026-10-05
- 正文载体: `docs/design/permission-domain-model-proposal-2026-10-05.md`（v0.2）——本 ADR 只承载裁定、来源、前提与取代关系，不复述模型（防双源）
- 相关: ADR-017（授权窗口・规则三档・journal・四入口——**全部保留**）、ADR-016 规则 1（域归属三问）／规则 4（错位走溶解）、ADR-023（词汇溶解三笔——本 ADR 是它的正解去处）、ADR-021／ADR-022、`00 §2` 判定表／`§3.1`／`§3.5b`／`§3.6`／`§5`、`02 §4.8`、`04 §2.3b`／`§4`、`00-product-design §1.2 原则 2`／`§4.2`

## Context（用户裁定原文）

「bash，部署授权，属于 权限领域驱动模型里得，不应该，而且可以记住得部署授权，现在只有在用户允许后只是本项目内记住，只不过现在权限领域驱动模型设计得实现设计得不够，权限应该是分档，高危应该是兜底，普通文件读应该默认允许，机密文件读需要授权，改项目仓内应该默认允许，改其它目录文件需要用户授权，授权应该可记录，可编辑，应该有沙箱模式/YOLO模式等。」

四裁（AskUserQuestion，2026-10-05）：**F9-3＝清单退为可选优化**｜**F9-1＝机密按路径模式表判**｜**F9-2＝YOLO 不碰机密/高危**｜**F9-5＝新立 Policy BC**。F9-4（记住的射程＝本项目）按原话视为已确认。

## Decision

1. **新立 Policy／Authorization BC**（核心域，裁决执行仍在 main——ADR-017 裁定 5 不动）：聚合＝**PolicyTable**（模式档＋机密路径表＋已记住规则），领域服务＝**decide(action, target, mode, rules) → allow | ask | deny**（纯函数、与模型自评无关）。`00 §2` BC 清单与判定表须补行；Conversation **只消费裁决结果**，不持有策略。三问详情落位时出，本 ADR 只裁归属。
2. **三轴一表，`kind` 单枚举废除**：`ActionClass`（read/write/execute/network）×`TargetScope`（repo/outside/system ＋ confidential 标记）×`Mode`（standard/sandbox/yolo）×`RuleTable`（once/session/persistent 三档沿用 ADR-017）。**`in-plan`／`out-of-plan` 退出动作属性**——它是授权态/优化提示，不是动作性质（一根枚举压三轴＝本域的"族未分"）。
3. **默认档（D3–D6 的正解形状，白名单式）**：`(read, 非 confidential) → allow`；`(read, confidential) → ask`，**且永不进 RuleTable**（记住也不静默）；`(write, repo) → allow`；`(write, outside|system) → ask`（`sandbox` 模式下 → deny）；`(execute|network, 高危集合) → ask/deny`。
4. **deny 是下限档**（D2「高危应该是兜底」）：任何已记住规则、任何模式、任何模型措辞，都不得把已判 deny 抬成 allow；**YOLO 只放宽写范围与执行确认，机密读与高危集合仍至少 ask**（F9-2）。P-1…P-8 不变量草案随落位并入权威文本（编号与 I-T／I-FOCUS 并列时再定形）。
5. **清单退为可选优化（F9-3，推翻重构级）**：`PlannedFiles` 不再是 allow 的唯一来源；方案确认卡**保留**，但其语义收窄为**推进门槛**（对齐目标与范围），**不再兼任授权门槛**。⇒ 必须连带重述三处旧主张，否则文本自相矛盾：`00 §5`「模型只能写清单内」、`00 §2` 判定表「Workspace（计划清单）vs Conversation（写边界）」行、产品主张里的「宿主强制边界（防模型漂移）」。**新表述方向**：宿主边界从"清单白名单"改为**作用域白名单（repo 内）**＋**机密/高危下限档**；越界写与机密读仍需逐次授权。
6. **规则可编辑（D7）**：`PolicyTable` 三操作补齐——`listRules`（可列）／`reviseRule`（可改）／`revokeRule`（单条收回），作用域＝项目；`clearSessionGrants`（任务边界自动清除 session 档）**语义不变、只引用**。**"撤销"一词仍不复用**（ADR-023⑥：收回单次批准不存在；此处叫"收回规则"）。
7. **"沙箱"拆名（先决条件）**：边界谓词与模式档不得共用一名——建议 `WorkspaceScope`（仓内/仓外）与 `Mode.sandbox` 分词；落位前这条必须先在文本里钉死，否则现用「沙箱」的四条不变式（`02:192`／`04:334`／`04:360`／`00:420`）语义当场漂移。

## Consequences

- **正面**：机密读第一次有了拒止路径；"记住"从一次性弹窗变成可治理的规则表（疲劳与失控两个方向同时收）；模式与边界分名后，YOLO 不再是"关掉门控"的同义词；动作性质/授权态/风险档三轴分离，`§3.5b` 那根混轴枚举有了解药。
- **代价**：**F9-3 是推翻重构级**——`00 §3.1/§3.5b/§5`、`04 §2.3b/§4`、`02 §4.8` 需重写，`in-plan` 退出会打到"宿主边界＝清单"这条既有主张的表述；产品 §3.5 diff 审核与 L1–L4 阶梯文案要同步；新 BC 立起来后 `00 §2` 判定表至少加两行、`coverage-matrix` 加 P 行。
- **风险①（落位前置）**：**"清单退为可选优化"最容易被读成"清单没用了"**——但清单仍是**方案确认的内容载体**（用户确认的是文件清单＋假设＋验证计划），只是不再充当 allow 的唯一来源。落位文本必须把这两件事分开写，否则会把"防只说不做/确认驱动"这根柱子一起拆掉。⇒ **处置改法（用户 2026-10-05 裁定后）**：不排人工审计轮，改为**落位文本内建两件事**——①`00 §3.9`（新落位节）内**同处写明**清单的两职拆分（内容载体保留／allow 来源撤除），禁止分放两处；②机验清单：grep「清单」每处必须能判读为两职之一，判不出＝断裂。原拟审计项（轴分离是否彻底／P-2・P-3 机验性／与 ADR-017 三档重叠面）**转为落位批的 coverage 机验行**，不再另开审轮。
- **风险②**：机密路径表是**可编辑事实**，被误改＝静默放行机密；须与规则表同样可列可改可留痕，且默认表随档发布。
- **风险③**：`Mode` 是会话级还是项目级未定（切换的可见性与留痕已由 P-4 约束，但作用域待落位时定形）。
- **边界**：本 ADR 不含实现；不改 ADR-017 的窗口/requestId/journal/四入口；不含 V2 并发下的策略复用（G5）。
