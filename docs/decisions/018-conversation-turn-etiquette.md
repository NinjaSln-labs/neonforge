## Context

S7-1/#7-1 稳定红族的根因已定层为「用户决策后下一模型轮归谁驱动在产品里无权威归属」（阶 C 前置审计 §1）。2026-10-04 的领域模型全局评审进一步定位：**该缺口上游是产品层空白**——产品设计规范 §4 定义了卡片、PENDING、状态机与任务队列，但**从未定义对话回合礼仪**：用户决策之后谁开口、用户此刻打的字算什么、系统自发轮可不可见。四条空白各自派生一族红（回声伪装用户发言 → C2 误击；意图通道靠措辞猜测 → 决策通道二元；排队输入不可见 → 死信不可证；处理中呈现无归宿 → 幽灵占位）。

因此本批不动领域状态字段、不动实现：**先把产品契约补齐**，使阶段 C 的建模有可对照的验收口径（否则 C1 信封字段仍是"给不存在的概念补列"）。

## 对标批（2026-10-04 下午·调研＋契约审计）

契约正文扩到 **C1–C12**（新增 C6 决策点生命终点／C7 输入三态／C8 拒绝投递义务／C9 打断残值／C10 消息四态／C11 忘事可见／C12 并发路由；C3 补可编辑可重排、C4 收敛为"展开原因不倾倒提示词"），验收断言补 a7–a12。外部锚点与冲突面全单＝`docs/audits/conversation-etiquette-benchmark-2026-10-04.md`（**证据只在附件，本 ADR 不复述**——防双源）。

审计抓出一条**自家文档打架**（原判定为"与领域权威分歧"的 B1，实为内部矛盾）：

- 现象：原 `sysPromptConfirmWords.test.ts` 把「sysPrompt 引导词 ⊆ `isConfirmIntent` 词表」做成机器校验——产品在用提示词**教用户打字确认**，与 C2 方向相反；该测试的历史注释记录了起因（#6 真机 2026-08-30：用户按引导打字反触发隐式拒绝，当年解法＝补词表）。
- **反转发现**：`src/renderer/sysPrompt.ts` 规则 **⑳ 早已存在**，逐字「确认只能通过界面确认卡按钮完成……严禁要求用户『输入特定文字/暗号』来确认」。⇒ **C2 不是新方向，是 ⑳ 的产品化接管**；真正的病灶是 ⑮ 的措辞「让用户确认「已解决」」与 ⑳ 自相矛盾，且被那条测试固化。
- 处置（用户裁"改提示词＋翻转该测试"）：⑮ 改「交给界面上的**解决确认卡**由用户点按钮确认（不要要求用户打字回复，见 ⑳）」；测试翻转为「提示词中不得出现「确认/回复/回我「X」」式打字引导 ＋ ⑳ 条款在位」。`isConfirmIntent` 词表本身与其 L1 断言（`agentLoop.test.ts:441-451`）**本批不动**（撤词表的决策资格属阶 C 范围）。
- 出口证据：L1 **769/769** 全绿（含 `sysPrompt.test.ts`／`conversationState.test.ts`／翻转后的新用例）；docs 经 prettier。

未采纳两条竞品做法并记因（附件 §2）：审批超时自动拒（与"拒绝必带 RejectReason"冲突）、披露条展开逐字提示词（噪声＋泄实现）。

## Consequences

- **正面**：一族红获得**产品级判据**而非实现级判据——a1–a12 可直接转成 L1/L3 用例；C1 使回声失去"伪装用户答复"的身份，C2 误击族（p000146 逗号案、isDecisionCardEcho 豁免表、`opts.echo` 来源标记的接线脆弱）从"需要持续打补丁"变为"违反契约"；C4 使 nudge 死信（t000067/p119）成为用户可见缺陷，不再只能靠 timeline 日志取证；**C6/C9/C10 三条直接对上本会话实测过的三个症状**（卡消失不回＝C6、请求被打断后呈现无归宿＝C10/`net::ERR_NETWORK_CHANGED` 案、幽灵"处理中"＝C5/C9）。
- **代价与破坏面**：C1 是明示反转，落地须逐处改写 A 节列出的 **5 处回声断言**（非删除）；C2 收回词表资格须改 `intent-design:215` 的**承载方式**（语义不动、词表退役为补充信息通道），属文档同步；呈现侧新增 4 个组件形态（披露条／排队徽标／过期卡态／消息四态指示），视觉规格待补 `02-components.md`/`05-visual-spec.md`。
- **边界**：本 ADR **不含**实现改动、**不含**领域状态字段（ADR-016 规则 1 已在 §4.5 立节约束中处理）；测批纪律仍遵 ADR-012——本批属"设计动刀"，门槛由用户裁定满足（`02 §4.6` 原则被实现偏离 + 设计方向本身遗漏，达 p000128 门槛）。
- **后继**：阶段 C 按本契约重述落点（原 C1/C2/C3 三条落点 → 改为 Turn 建模 + doctrine 统一 + 拓扑裁定）；`docs/tests/coverage-matrix.md` 待实现落地后补 a1–a6 行（本批不预先登记未实现断言）。

## 契约一致性轴（四轴审计第四路·2026-10-04 晚）

**C2 与 sysPrompt ⑬ 互斥（新击穿，P0）**：⑬ 逐字「候选后引导『或直接告诉我你的想法』——**输入框是主通道，点选与打字等价**」，且 `pending='system_clarify'` 在确认卡族内（`conversationState.ts:132`）。⇒ 按 C2 字面，**用户对澄清提问打字＝补充信息、不推进任何东西**，叠加 C6「卡不因时间消失」⇒ **澄清永久悬置**，除非用户去点候选。修复＝新增 **C2a 澄清作答≠决策**（ask_user 候选/强制澄清属素材采集通道，打字与点选等价有效、作答即收口；C2 只管 goal/plan/resolution 三族）。

其余三条新补条款：**C2b 补充信息投递义务**（C2 只说了打字"不是什么"，没说"之后去哪"——静默收下又不推进＝说了没人理，与 C10 同族缺陷）；**C4a 系统轮不占排队面**（silent 入队既无气泡又无排队条目，用户数不上数，C3"按条可见"失真）；**C12a 待决策期输入归属**（§3.6 任务 A 卡审核＝ADR-013 判非 busy，那"当前正在执行"就无定义——归活动会话含 PENDING 期，排队任务永不接收输入，打字不构成切换意图）。

**两处正面矛盾已修**：① C6 首条未限定族，字面**推翻 ADR-017 决定 4 的"≤approved 存续可决"**（授权记录跨重启仍可批）——现限定"本条只管确认卡族，授权面归 ADR-017"，并要求两族过期文案不同词；② C10"失败不得静默自动重发"混指两对象，与既有行为冲突三层（渲染层 `:3016-3026` 用 `base.slice(0,-1)` **原地替换掉失败气泡**、`:2994` 文案在重试前渲染＝时序倒挂说谎、`gateway.ts:557/:588` 重试仅 console.log 无 tlog 无呈现⇒"最多一次"名不符实），现拆「**输入重发禁自动**」／「**轮重放允许有痕一次＋四条硬条件**」，并登记 `retry.interaction.ts:188-202` 为冲突面（属轮重放，不互斥但须补可观测性）。

**可测性降级**（不充当当前 DoD）：a3/a4/a7/a9/a12 依赖尚不存在的组件→**先定名再断言**；a6 标 L1 但词表分流在渲染层非纯函数→先搬 domain；a2 原断内部状态值而 L3 无 hook/无 `data-instance`→改写为代理判据；断言层级全部归 L3（不归 L4——p000136：visual 基线权威宿主 macOS，禁 WSL `--update-snapshots` 入库，误归 L4 会结构性不可执行）。选择器勘误：契约与 ADR-013 引用的 `.nf-chat__stop` 只存在于注释，真名 `.nf-chat__send--stop`（`:3943`）；C7 不再引用 `Esc`（§六 的 Esc＝关面板/取消操作，键盘打断未实现）。C9 的「§4.9」是悬空引用（第四章止于 4.5）已修。
