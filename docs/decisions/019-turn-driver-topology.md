## Context

S7-1/#7-1 稳定红族已定层为「用户决策后下一模型轮归谁驱动在产品里没有权威归属」。拓扑实测：`ConversationPanel.tsx` 内 **26 个调用点**直调 `send()`（用户/外部 4、按钮回声 8、系统自发轮 13、队列回投 1），`send()` 每次都 `sid = ++sessionRef.current`（`:2734`/`:3041`）立即开启新模型轮，旧轮唯一的自杀点是 500ms poll 里的 sid 比较（`:1993`/`:1995`）；排队消息的 drain 位挂在**链尾 finally**（`:2851`）。

本会话先后试过的两个形状补丁都失败并留下实测数据（A 守卫：族 0 红但 `retry:188` 3/3＋每轮 1 例轮换红；B 回声直送：族 0 红但误杀工具执行链 `core:388`/`factory.self:30`+`:73`/`retry:188` 各 3/3）。两者是同一台机器的两面：**任何在 `send` 单行上的改动都在改全局轮序，而轮序当前没有权威定义处**。

外部佐证（八家竞品源码＋OpenHands 后端＋四个框架，2026-10-04 全量复核）：**在本机抽验的 8 家 CLI/桌面 agent 与 OpenHands 后端中，无一家在"同一回合序列"内允许多条自推进链并发在飞**；一致形态是「意图入队/注入 → 单一仲裁点在回合边界决定下一轮」。但两条读法被证据**收窄**：①**跨回合序列的并发合法且被制度化**（Codex `max_concurrent_threads_per_session`、Claude Code Agent Teams、Cursor `/multitask`、A2A 多 Task）——单消费者约束的单位是回合序列，不是会话；②**抢占本身合法**（Codex `abort_all_tasks(TurnAbortReason::Replaced)` 在 `start_task` 之前同函数内、`debug_assert(turn.task.is_none())` 单槽占位），差别在同步取消、不留迟滞窗。框架侧降级：LangGraph 的 channel 单写者规则与本题**不同构**（正名 double texting，且 OSS 无此特性），AutoGen 的 actor 说法**无"串行 mailbox"原文**支撑且与 arXiv:2308.08155 版本错绑——详见 P8/P9。

## Decision

> 本节正文经 2026-10-04 四轴对抗审计修订（治理授权轴／因果完整性轴／外部证据保真度轴／契约一致性轴）。**修订前稿有两处越界，已就地改正并留痕**：①D2 的"发起权分散"半句原被归入"实现偏离（免设计批准）"，经查现行领域文本**没有任何一句规定"回合发起的消费者应为一个"**（`00 §3.2 要点 1`"槽只有一个"讲的是 pending 槽、不是发起权），故拆分；②Decision 2 的形态措辞原写"入口唯一消费者"，被证据否证为**过窄**（并发合法，只是要挂在正确的单位上）。

1. **性质判定：分三层，不再一句"实现偏离"打包。**
   - **D1＝偏离**（判据 `02 §4.12`「当前回合收口后自动发送」——在入队时刻该短语有确定所指；实现把 drain 挂在任意链 finally，孤儿链照样投递）。
   - **D2a＝偏离**（判据 `04 §3.2:412`「状态机未到下一态——**结构性，非拦截**」＋ `00 §3.2 要点 5` 已裁的"不得用镜像/轮询代理领域状态"原则）：过期链靠轮询迟滞自杀、**且在过期窗内继续写会话状态**，属拦截式实现。
   - **D2b＝模型空白**（"一轮的发起权应收敛到单一仲裁点"）**不是偏离**——无现行文本可引，属新引入的规范概念。⇒ **2026-10-04 用户裁定已授权**（"产品有偏离或缺口就修正产品"），产品层落点＝`00-product-design §4.5 C13`＋断言 a13/a14；**领域侧（Turn 身份／驱动消费者唯一不变量）仍归 C-补模批**，须 ADR-016 规则 1 出域归属卡。原"不得以纠偏之名落地"仍然有效：纠偏批只实现 C13 的实现偏离部分，不借道给领域加字段。
   - **D3＝偏离**，但**引文更正**：原引 `00 §3.2 要点 5`（该句只管 pending）；真正咬住的是 `02 §4.12`「UI `working` 与 UAT `modelBusy` **与上表同源**」——busy 同源是已裁义务，实现用 effect 镜像＋三处手动补清，是这条的违反。
   - ⇒ p000128 门槛的"实现偏离"一侧**只对 D1／D2a／D3 成立**；D2b 落在"设计方向本身遗漏"一侧，需另行批准。
2. **目标形态措辞（按证据改写）＝「每个回合序列至多一个驱动消费者 ＋ 同步取消令牌 ＋ 状态写入单点串行化」**，单位是**回合序列（Turn/Task/thread）**，**不是"会话"**。跨回合序列的并发合法（Codex `max_concurrent_threads_per_session`、Claude Code Agent Teams、Cursor `/multitask`、A2A 多 Task 都这么做），但每个序列必须有①独立身份、②自己的单一消费者、③写入锁/租约。**原措辞"入口唯一消费者"过窄**，会把自家 V2 并行能力（多 Agent/Worktree，范围表已列 V2+）判成违规。
   - **V1 投影（用户裁定 2026-10-04）**：V1 一个会话只有一个回合序列 ⇒ 单位之辩在 V1 **不落差异**，可直接写作「会话内至多一条在飞驱动链」（产品口径＝`§4.5 C13`，与 `§3.6` 串行执行队列同构）。V2 放开并发时才需要回合序列身份。
   - **不变量措辞更正（回核自家设计所抓）**：原写"在飞链数量不变量（G2：count==1）"作为 DoD **不成立**——作废与交接必然有重叠窗（旧链尚未退出、新链已开），literal count 恒可能为 2，桩会自证红。正确措辞＝**「有资格的驱动消费者唯一」**：作废由令牌代次（generation/CAS）判定，**已作废链的写入计数为 0**（断言 a14）。D4 待授权直送＝**批复后执行已批准的动作、不新增轮**（⚠️ v1.3 限定：本句只覆盖"批复"情形；**待授权期用户发新指令**的轮次归属**已于同日裁为 F7＝选项 D**（提案 v1.4 §4 出口③＋`00 §3.7.2`），误用本句去否证"新指令成轮"已在本会话被抓出并更正。〔2026-10-05 互审登记：提案 §8 曾宣布本条 D4 括注"作废"，但只记在提案侧——ADR 本体无对应登记行，现补上〕；网关瞬态重试＝同轮重放（C10-② 有痕一次）；二者都不违反本不变量——写清这三条边界，否则纠偏批会把已裁功能判成违规顺手统一掉（与风险登记同脉）。
3. **准入形态的完备枚举是四种**（拓扑层，非 V1 实现清单）：`submitIntent` 必须返回显式准入结果，可选 **折入现役回合 / 排队下一回合 / 拒绝 admission / 派生为有身份的子执行**——四者都必须经同一仲裁点，**没有一种允许调用点自己 `++sid`**。蓝本＝Codex `TurnInputSubmission{Started, Steered, NotSubmitted}`＋`NotSubmittedReason`（含 `ExpectedTurnMismatch` 代次 CAS）；LangGraph 对该问题的正式名字是 **double texting**，策略四选一 Enqueue(默认)/Reject/Interrupt/Rollback（注意：该仲裁在 LangSmith Deployment，OSS 框架内无）。
   - **对自家设计的射程核对（用户裁定 ④，2026-10-04）**——四形态不能整把抄：
     - **V1 只实现「排队」**（`§4.5 C7` 默认态）；「折入现役」＝ C7「转向」，**V1.5**；「派生子执行」与跨序列并发＝**V2**（用户裁定②：V1 先一条链完整解决问题）。原稿把四形态写成 V1 目标形态，等于**用竞品分布替 V1 范围做主**。
     - **「拒绝且不记录」对用户输入永不合法**：Codex 原文 "declines the input **without recording or enqueueing** it" 与 `§4.5 C3`「任何一态都不得丢弃输入」正面冲突，故本产品只采**有痕拒绝**——作废仅对已失效的内部投递（过期决策点答复/失效回声/被取代的自发轮触发）合法，且必须走 `conversation.stale_input_discarded`（`timeline.ts:144`，ADR-015"不吞不回喂、可见重提示"）。⇒ 已写成条款 `§4.5 C13a`，对标附件的该条引用须加此限定。
4. **阶 C 拆两批**（⚠️ **本条顺序已被 ADR-020 反转：C-补模批（领域设计定稿）→ C-纠偏批（实现回归）**；下列两批的内容与判据不变，仅先后次序作废——原依据"桩时序＋实现落点"被用户否证为范畴混用，见 ADR-020 Context）：
   - **C-纠偏批**（仅 D1／D2a／D3；**显式保留** D4 待授权直送与 D5 催推进/对账引导功能，只收编投递通道）——与 §4.5 C1/C4/C2a/C2b 落地同刀（21 站点重叠）。**D2b 已由用户裁定落在产品层（§4.5 C13）**，故纠偏批现在是"C13 之实现偏离部分的回归"，不再是"待批准的新规范"；但**领域字段仍不在此批**（Turn 身份、驱动令牌、roundOrdinal 归 C-补模批出卡）。
   - **依赖更正**：原写"`roundOrdinal` 需要单一 ++ 点才有单调源，故字段无处可写"**是可写性上的错判**——`driver` 在 26 个调用点**当下皆可知**（echo/nudge/用户输入各带字面语义），纯记录前置批技术上可先做且零轮序风险。真正的依赖是：①**归属语义的消费**（回声去重、"同 answers 一轮至多驱动一制轮"、按 ordinal 断言归属）会改变投递次序，必须与纠偏同刀；②**G2「驱动消费者唯一」不变量在收口前不可断**——不是"数量恒 1"（作废/交接必有重叠窗，literal count 可能为 2，见 Decision 2 的措辞更正），而是"已作废链的写入计数为 0"；在令牌门控尚未覆盖每个 await 恢复点之前，这条断言必红（D4 直送、auto-retry、queue 回投都合法并链）。断言先行即桩全红。⇒ 措辞由"无处可写"改为"**无权威可绑**"；顺序结论不变，依据换成 ①②。
5. **纠偏批 DoD 必须含以下六条**（因果完整性轴给出的最小残留竞态，缺一即族红原样复活）：
   1. **令牌门控"状态写"而非只门控"续跑决策"**：`:2126`（50ms 睡眠）/`:2143`（`streamingSidRef`）/`:2147`（`roundChunksRef`）/`:2362`（`chatRef`）/`:2845`（`workingRef=false`）/`:2849`（`finalizeOrphanStream`）/`:2851`（flush）逐点复核；`runChat` 入口须有令牌复核（现无）；`gateway.streamChat`（`main/gateway.ts:559`）须增 **abort 句柄**——**二批已核实现状为"零取消管道"**：`grep AbortController\|signal` 在 `main/gateway.ts` 与 `ConversationPanel.tsx` **均 0 命中**，作废只靠 sid 比较约定，字节层继续到达 ⇒ 令牌**只能门控状态写**（这正是本条前半句的根据），且"同步取消"是从零新建、不是加固既有机制。否则重叠窗＝流剩余时长＋50ms，名不符实。
   2. **五个共享单槽改挂 round 对象**（`chatRef`/`roundChunksRef`/`streamingSidRef`/`roundStreamRef`/`doneNotifierRef`）——否则旧链醒来抢走 `streamingSidRef`，**新轮**全部 chunk 被 `:401` 守卫丢弃，症状与 RC1a 同签名。
   3. **词表路由与纠偏同刀——按族分流，且有两个承载点**（`:2671-2680` ＋ `:2615`）：若只收口入口而 `isConfirmIntent` 仍在消费时刻判 reject，**S7-1 在单消费者形态下完整复活**（绑定时机从"消费时"变成"仲裁时"，击杀照旧）。⇒ §4.5 C2/a6 列为本批 DoD，不留补模批。**射程核对（用户裁定 ④）纠出原稿两处不足**：① **第二承载点漏登记**——词表不只在即时分流，还在**入队归属冻结** `:2615`（`shouldQueueWhileBusy` 分支内 `!isConfirmIntent(text) ? undefined : {kind, instanceId}`）；只改前者的话，busy 期打字的确认语仍在入队时刻冻结归属、flush 时带 answers 进仲裁点——**同一资格换个地方活着**，两处必须同刀。② **原稿过宽**：该分支的进入条件是 `pending !== 'none' && !== 'approval'`，**`system_clarify` 也在内**（`conversationState.ts:118`），现形态下打字命中词表＝`confirm('system_clarify')`、未命中＝`reject(kind:'direction')`。整支删掉会一并打死 **C2a 明写保留的"澄清打字作答"通道**（sysPrompt ⑬「点选与打字等价」）——正是 C6/C2 那类打死锁的第三个实例。故：确认卡族（goal/plan/resolution）**退役**；`system_clarify` **保留打字作答**但改为"作答即收口该提问＋文本作为素材进下一轮"，不得再落 `reject`；授权面文本批准（独立 regex `:2685`）**不动**（ADR-017 裁定 3 四入口之一，且只做 allow、永不触发 deny）。
   4. **busy 权威层的归属登记（原写"对 ADR-017 的成文例外"——该说法射程错绑，已撤）**：V1 内回合槽忙事实的权威**留在 renderer 的 scheduler 非响应式槽**（同步可读硬约束；搬 main 则跨 IPC、ms 级往返，同步性当场破产）。**但 ADR-017 的射程是授权裁决（preApproval／requestId／journal），全文无一处管 busy**（grep `busy|working|modelBusy` → 0 命中）——busy 的权威在 **ADR-013 裁定 1** ＋ `02 §4.12`「UI `working` 与 UAT `modelBusy` 与上表同源」，按 ADR-018 立节约束属**产品呈现层**概念。**登记"例外"等于替 ADR-017 造出它本没有的射程**，后续审计会反过来按这条"例外"要求把 busy 收进 main——是自造的回洗面。改写法：本条＝**归属声明**（busy 从来不在 main 的裁决面内，因此无需豁免），R3 交接判据不变（main journal `started/done` phase 可覆盖时再评估搬运）。 **（ADR-021 第 8 条：本条已被 I-T5 取代——busy 的唯一措辞源是 `busy ≡ ∃ Turn ∈ {Running}`，本条降为投影条款，不再是并行源。）**
   5. **harness `modelBusy` 同步收编**：改读 scheduler 投影，DOM 读只留呈现断言（否则测试层仍是"UI 现象代理领域状态"的活体违例，busy 族红以新签名出现在验收轮，并被误计为归属族）。
   6. **自然红逐例事件流归因义务**：≥6 轮验收批中**每一例红**附 timeline 签名分类（归属类／挂载类／其他），补齐"归属无权威"从**最简解释**升为**排他解释**所缺的那条证据；locator 消歧为子项（`确认执行` 在计划卡 `:3355` 与强制卡 `:3781` **同名并存**，靠 pending 互斥才不同框——族红验收判据本身用这个 locator，签名分类会被污染）。
6. **原阶 C 前置审计 §4 三条落点（C1 信封／C2 恢复三判／C3 规则归 main）不作废，降为 C-补模批子项**；D2b 一并归入该批。
7. **R3（loop 下沉 main）记 V2**；**R1（只补可观测字段）判不可收口**（归属可观测但不可决定，≤500ms 抢跑窗原样保留）。
8. **纠偏批对 `docs/domain/` 与 `00 §3.2` 零改动（新增硬闸）**：`00 §3.2` 是不变量 1 唯一措辞源（ADR-015 #8），`02/04/coverage-matrix` 全是"只引不重述"；纠偏实施中发现的任何措辞缺口**一律回流 C-补模批**＋出域归属卡＋用户终裁。若把新拓扑顺手写进 `00 §3.2`，等于**用实现回洗权威文本**，G 表"模型空白"的判定当场失去可证伪性，p000128 的"偏离侧免批准"通道沦为改设计的后门（治理授权轴指出的唯一措辞源回洗风险；ADR-012 不管文档，故须本条显式设闸）。
9. **本节范围限定（二批裁定后更新）**：Decision 1 的**性质判定**、Decision 4 的**批次划分**、以及原三项待裁（D2b 授权／V1 并发边界／ADR-018 终审）**均已由用户裁定**（见首部二批裁定行）。仍属合作负责人提案要素、可在开工前被推翻的：**Decision 2 的形态措辞细节**与 **Decision 5 的六条 DoD**（其中 5-3／5-4 本批已按"回核自家设计"修订）。形态措辞的 V1 投影不再有方向争议——V1 单链已由裁定钉死，措辞只剩技术形状。

## Consequences

- **正面**：族红的处置从"再审一轮补丁形状"转为"按既有权威文本回归"——判据是现行文档原句，不是新发明；A/B 两轮的实测数据首次获得统一解释（同一台机器的两面）；§4.5 C1/C3/C4/C7/C10 五条契约从此有实现地基（投递模式与消息状态需要一个持有者才能成为数据）。
- **代价**：纠偏批改动面大（26 站点收敛＋`maybeContinue` 语义收窄＋busy 改派生）；**轮序变动预期打到 ≈6–8 例把轮序当标定的桩**（`retry:188`/`core:388`/`factory.self:30`＋`:73` 等）——须按 `02 §4.12`＋`04 §3.2:412` 逐条重标并附证据，**禁止以"让它绿"为目标改断言**（阶 C 审计 §4.5 口径不变）。
- **风险登记**：D4 待授权直送例外与 D5 催推进功能在收口通道时最容易被"顺手统一掉"——两者均为已裁语义，纠偏批的 DoD 须各含一条"仍在位"的断言。**二批新增两条风险**：① 对标件里的 Codex "declines without recording" 与"多回合并发合法"若不带上 C13a／V1 单链限定就会被当 V1 依据抄进实现（已在 Decision 3 钉住，`conversation-etiquette-benchmark-2026-10-04.md` 的对应引用行需随补限定）；② 本 ADR 曾写的"busy＝对 ADR-017 的成文例外"已撤——若后续稿子里再出现"例外"字样，即为回潮，按 P10① 的 grep 证据驳回。
- **边界**：本 ADR 只裁性质与批次顺序，**不含 scheduler 的接口设计**（属 C-纠偏批的提案，须另出并过 ADR-016 规则 1）；不含实现改动。**V1 范围已由用户钉死**：一条链完整解决问题，无子执行、无回合并发。
- **测批纪律**：ADR-012 全程有效——落地前后仍走「整轮测批 → 汇总 → 用户裁决 → 另开修批 → 另开回归」。
