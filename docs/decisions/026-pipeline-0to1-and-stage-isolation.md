# 026 — 0→1 阶段流水线与阶段隔离硬闸（含外部 agent 调遣规则）

- Status: accepted
- Date: 2026-10-05（用户四项裁决①–④＋角色分工改写指令）
- 相关：`AGENTS.md` 角色分工节（摘要面）；`.agents/skills/pipeline-0to1/`（推进机制）；`.agents/skills/agent-dispatch/`（调遣机制）；ADR-012（测完再修——本件将其推广为跨阶段隔离）；`docs/neonforgeV1.0.0/ARCHIVE-INDEX.md`（新树入口）

## Context

1. 用户裁定角色分工：产品有两位负责人——用户负责方向（最终裁定权），AI 负责补充（穷举盲区）、纠偏（冲突直说）、**把控完整 0→1 流程直至交付**。AI 的职责不是「实现」一个词，而是一条流水线：规划设计→审计→计划制定→详细设计→实现落地→测试验收（用户原始六段），并要求「各段独立互不串通」、按 DDD 思维组织。
2. 旧树病灶提供了反面证据：九轮修订逐层叠加只加不核（北极星四处互斥、p000161「声明≠事实」、p000160「落位≠落地」）——根因是阶段间没有工件冻结与出口闸，讨论态直接渗进权威文本。
3. 同场裁定：旧树全部产物（含 `08` L0 定稿与 ADR-025 的产品锚）**降为经验件**，新版从段0 从零开始设计（「这版从零开始设计，先弄清楚要提供什么样的产品」）。ADR-025 在旧树的历史状态不变，但新树不继承其 L0。
4. 对用户六段的纠偏（经用户逐项裁决确认）：①「审计」不是链上一段而是横切闸；②缺段0 问题定义、段8 部署发布、横切经验沉淀；③「规划设计」须拆产品定义与领域战略设计两层。

## Decision

### D1 流水线：9 段＋2 横切

| 段 | 名称 | 产出物（唯一载体） | 出口闸 |
|---|---|---|---|
| 0 | 问题定义与范围 | 问题陈述＋goals/non-goals＋术语种子 | **用户裁定** |
| 1 | 产品定义 | 产品轴裁定→新树 L0 母本 | **用户裁定**＋独立审计 |
| 2 | 领域战略设计 | 子域分类＋上下文地图＋通用语言表 | **用户裁定**＋独立审计 |
| 3 | 领域战术设计 | 聚合/不变量/领域事件目录 | AI 自查（ddd-model-review）＋独立审计 |
| 4 | 计划制定 | 分阶段计划＋每阶段 stage-spec（DoD 断言） | AI 自查＋独立审计 |
| 5 | 详细设计 | 模块接口/数据契约/时序 | AI 自查＋独立审计 |
| 6 | 实现落地 | 代码＋单测 | AI 自查（双 tsc＋L1＋lint＋脱敏闸） |
| 7 | 测试验收 | stage-spec DoD 逐条执行结果 | **用户裁定**（stage-gate PASS 为前提） |
| 8 | 部署发布 | 版本号＋CHANGELOG＋tag＋分发件 | AI 自查。**定义入射程、建设后置**（裁决③：详细设计排在段7 首次 PASS 之后启动） |
| 横切A | 独立审计 | 每段出口审计报告→`docs/audits/` | 结论一律回**用户裁定** |
| 横切B | 经验沉淀 | `.handoff`（CLI）＋坑＋ADR | handoff check |

闸分档依据裁决②：用户亲裁段 0/1/2/7＋全部审计结论；段 3/4/5/6/8 AI 过闸＋报告备案。

### D2 阶段隔离四条铁律（「独立互不串通」的机制化）

1. **工件即接口**：下一段输入＝上一段冻结的产出文件；会话口头约定不算输入，声明必须先核 diff（p000161）。
2. **禁止跨段作业**：设计段不写代码；实现段发现设计错→回退到设计段改工件、重新过闸，不就地打补丁（ADR-012 的跨阶段推广）。
3. **审计独立态**：审计者只读工件＋权威文本，不引用会话记忆；由异构执行者承担（子代理或外部 agent，见 D3）；同一回溯路径最多 3 次，第 3 次仍触发升级为「需人工介入的架构决策」。
4. **闸红不放行**：出口闸结果经 handoff CLI 记录；红了下一段不得开工。

### D3 外部 agent 调遣（生产力池，不限于审计）

工具池（CLI 名＝形状快照，2026-10-05 本机已验）：`mcode`／`command-code`／`pi`／`qodercn`。各 CLI 跑哪个模型、非交互旗标与限制——**派单时以中央 agent-dispatch 技能现场探测为准，本行不作依据**（模型与旗标随工具升级而变，写死即漂移；见技能第 0 步与 ADR-026 裁决④软链外挂）。

- 角色不限：实现、bug 定位、修复、审计、批量扫描、调研皆可派；**分配不固定**，按任务性质/负载/上下文新鲜度自由搭配（用户裁定）。
- 两条硬约束：①**不自审**——干活者与审其产出者必须不同执行者；**与当前主同一模型／渠道者不审主会话亲笔**（同源偏见防线。2026-10-05 追加裁定：当前主可为 `mcode`／`command-code`／`qodercn` 任一、随会话轮换，非固定 qodercn；操作细则＝现场探测＋`currentTool`/`currentModel` 入参，见中央 agent-dispatch 技能）。②**产出过闸才入库**——代码类在独立 worktree/分支生成，主会话复核 diff＋跑段6 闸后才合入；报告类落盘后由主会话署名采纳才算数。外部 agent 是执行者不是裁定者，合并权与闸责任在主会话。
- 任务书＝冻结工件路径＋明确产出格式，不给会话上下文；bug 定位者只产出定位报告不直接改码（定位与修复分离）。
- 安全约定：外部 CLI 只接收已入库/可公开的工件；`.handoff/`、`.scratch/`、凭据文件一律不给。

### D4 落地载体（三层）与本仓限定

- `AGENTS.md` 角色分工节＝摘要面（每会话自动加载）；本 ADR＝全文权威；两个技能＝机制封装。
- 裁决④（**2026-10-05 修订：两技能迁出本仓、集中托管**）：`pipeline-0to1` 与 `agent-dispatch` 原「只建本仓、随仓入库」，现改交 `agent-skills` 集中仓统一管理，本仓仅在 `.agents/skills/<name>` 落**相对软链**（→ `../../../agent-skills/<name>`，git mode 120000，用相对路径避用户名入 blob）。**原裁决两点实质仍守**：①「不进全局」＝仍不入用户全局 `~/.agents/skills/`（`agent-skills` 是兄弟仓、非全局目录）；②「太重、不是所有仓都合适」＝由「软链可选挂载」承接——哪仓要用才加链，clone 本仓不带 `agent-skills` 则链悬空、不强制携带。**`agent-skills` 仓不归本仓管辖**（用户 2026-10-05 裁定）：其内容与提交在该仓自管，本仓只引用、不维护、不代其记账。

### 边界（不在本决策内）

- 产品定义的内容本身（13 轴裁定）归段0/段1 工件，不在本 ADR。
- 段8 的工具链详设（打包/签名/分发通道）后置。
- 旧树 ADR-001–025 的语义不因本件改写；本件只定流程与隔离。

## Consequences

- 正面：讨论态与权威文本物理隔离（工件冻结）；每段产出有独立复核（横切A）；外部算力可用且受控（D3）；规则三层落地不依赖会话记忆。
- 负面/代价：每段出口多一道审计动作（轻量段可用 pi 批扫降低成本）；流程变重。**2026-10-05 用户改判（裁决后追加）：小修补没有豁免通道**——原「单文件无语义裁定修补可不走流水线」的豁免条**作废**；一切变更一律走流水线，小修补（typo/脱敏/格式）从段6 进入，段6 闸与横切B 记录照走，仅免去上游段的工件产出。
- 后续：①建两个本仓技能（`.agents/skills/pipeline-0to1`、`agent-dispatch`；后迁 agent-skills 软链外挂，见 D4 裁决④）；②AGENTS.md 角色分工节改写为流水线摘要；③段0 开工时产出第一份问题定义工件；④首派外部 agent 前验证 command-code/pi 的非交互旗标。
