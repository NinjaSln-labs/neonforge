## 背景

契约件 V1-S2 的 E5 要求本阶段偿清 S1 审计 F-2 的登记针：「忙时发起（在飞位占用）⇒ 拒方输入 ⇒ `QueueList` 出现可见位置的**端到端**断言」。同一文件的边界节与详设 §11 又把「对话／输入入口」排在 **S4/S6**（用户 2026-10-05 裁的三缺口认领面）。两条不能同时成立。

实测前提（本会话新鲜取证，非推断）：

- `grep -rn "nf?.turn|neonforge?.turn|turn\.start" apps/desktop/src/renderer/` → **零命中**；
- `apps/desktop/src/renderer/StreamBar.tsx:7`＝`const start = () => setStreamId(\`s-${Date.now()}\`)`——「发起流」只置本地 state，不发任何桥调用；
- 呈现层现有输入控件只有 `ConfigPage` 两项、`DecisionCard` 的拒绝理由框、`ScopePanel` 的 entries textarea（`grep -rln "<input|<textarea" apps/desktop/src/renderer/*.tsx`），**没有一处是「用户发起一轮输入」的入口**。

⇒ 「端到端」缺的不是测试技巧，是**被测面本身还不存在**。三种写法里：造一个输入入口＝越界到 S4/S6 射程（且要回段5 改两份上游工件）；夹具直接注入 queue 分支再断 `QueueList` 渲染＝把假绿写进闸（断言的对象不是用户动作）。两者都比少一针贵。

## 决策

1. **E5 改判延后 S4**，S2 内显式记 **blocked＋理由**（不判红、不预绿、不沉默）。
2. **E4 下限 8 → 7**：原下限里含 E5 那一针；随动后 7＝E1 三条＋E2 三条＋E3 一条（实落数由 stage-gate 现场数，不照抄本数）。
3. **表 N 轴 6 注记**由「C1 E2E 跨层一针延后 S2」改为「**延后 S4**」并附本件编号；契约件 F6 相应写明**该注记不转 ✅**。
4. **承接面归 S4 契约件**：S4 出件时必须①先立「输入／发起入口」的实现任务，②把 E5 原条文（忙时发起⇒拒方输入⇒队列可见，端到端）作为该阶段的 DoD 承接项，③表 N 轴 6 的 S4 列同批回填。
5. 契约件头部那句「上游登记针（本 spec 必须消化，不得再延后）」加例外注记——**这句话本身就是本次矛盾的源头**，留着不改等于让后来者照假话执行。

## 后果

**＋** 段6 不越界、不开假针；S2 出口的 `- [ ]` 全数要么绿要么显式 blocked，F7 可诚实勾。
**＋** E5 的债**没有消失**，只是改挂到有能力偿还它的 S4，并在表 N 与 ADR 双处留痕，S4 出件时会被迫对上。
**−** S2 的 L3 净增由计划中的 8 降到 7；「C1 E2E 跨层」这一格从 S1 起连续两个阶段未偿（S1→S2 blocked→S4），追溯表上会留一条长账。
**−** 契约件内部矛盾属**我（主会话）在段5 写件时的缺陷**：边界节写了排除项，DoD 又把它写成必偿项，出口异构审计（10 单）也没抓到这一条——已作为码审／出口审计的一条判据补进 S2 出口审计任务书（查「DoD 与边界节是否互相打架」）。
