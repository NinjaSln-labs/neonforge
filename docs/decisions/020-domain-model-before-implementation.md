# ADR-020：领域模型先行——C-补模批前置于 C-纠偏批（反转 ADR-019 Decision 4 的顺序）

- 状态: **proposed**（顺序反转已由用户裁定；模型本体待 F1–F4 终裁）
- 日期: 2026-10-04
- 取代: `docs/decisions/019-turn-driver-topology.md` **Decision 4 的批次顺序**（性质判定 D1／D2a／D2b／D3、六条 DoD、Decision 8 硬闸、R1/R3 处置**均不变**）
- 相关: ADR-016 规则 1/4、ADR-018、ADR-019、`docs/design/turn-driver-domain-model-proposal-2026-10-04.md`（本 ADR 的正文载体）、`00-product-design §4.5 C13`、`00 §3.2`

## Context

ADR-019 Decision 4 把阶 C 拆成「C-纠偏批 → C-补模批」，依据经四轴审计更正后写成：**归属语义的消费会改投递次序**＋**G2 不变量在收口前不可断**，故模型字段"无权威可绑"，须等拓扑收口后再补模。

用户 2026-10-04 晚否证了这个方向判断：**「现在的重点是领域设计进化；领域设计没落地，实现修改就没有依托」**，并明确**「当前的实现只是参考——设计进化后与实现冲突就推翻重构；实现若偏离设计，以后有填不完的坑」**。

复核我自己的推理，错在一处**范畴混用**：

- 「不变量在收口前不可断」是**测试桩的时序约束**（a13/a14 现在打桩必全红）；
- 「字段无处可绑」是**实现落点约束**（没有单一 ++ 点就没有单调源）；
- 二者都不构成**建模约束**。我却把它写成"模型必须后于实现收口"，等于让待被纠正的实现反过来给设计排期——正是本轮被指出的倒置。更刺眼的是：我自己在 ADR-019 里写的更正结论"**无权威可绑**"，字面上说的就是"实现缺一个可绑的权威模型"，**它恰恰是补模必须先行的证据**，我却把它当作后行的理由。

另有一条同族病：本会话多轮以"实测行号取证"为主要方法（这是治理坑 p000157/p000158 的来源），到阶 C 门口时我已经把"能不能改代码"当成了"该不该建模"的判据。

## Decision

1. **顺序反转**：`C-补模批（设计定稿）→ C-纠偏批（实现回归）→ 断言转正`。模型批准前**不开**纠偏批的实现刀；实现批一律对着已批准的领域模型做，与现形态冲突处按提案 §9 推翻重构，**不写兼容层、不以"改动面大"缩小模型**。
2. **模型本体载体**＝`docs/design/turn-driver-domain-model-proposal-2026-10-04.md`（Turn 实体／Step／Intent／AdmissionResult／DriverLease／身份四轨／不变量 I-T1–I-T9／九张域归属卡／现状冲突八条登记）。本 ADR 批准时**只裁顺序**；概念集与 F1–F4 由用户终裁后另立 ADR（或本 ADR 转 accepted 并附批准范围）。
3. **测试桩时序不变**：a13/a14 仍不预先桩红（ADR-012 与本仓"无实现地基的断言先入账"纪律）——**顺序反转改的是建模排期，不是桩的排期**。这两件事必须分开说，否则下次审计会把我这次的更正当成新的错位。
4. **实现只作参照**（用户裁定的方法论化）：领域提案写作时允许引现行代码作"冲突登记"（提案 §9）与"先例旁证"，但**禁止**以"现状做不到／改动面大／需要先验证代码"作为削弱模型边界的理由；若需要知道现状，记为待重构事实，不做 L3/代码级可行性校验。
5. **ADR-019 其余判定全部存活**：D1／D2a／D3 的偏离性质、D2b 已授权并落 `§4.5 C13`、六条最小残留 DoD（其③词表族分流与④busy 归属声明仍有效，但**归属结论现在由本模型的 I-T5 给出**，DoD 相应降级为"实现要求"）、Decision 8 硬闸（**改述**：模型批准前对 `docs/domain/` 与 `00 §3.2` 零改动；批准后走提案 §12 的落位批，落位批是**授权过的领域修订**，不构成回洗）。

## Consequences

- **正面**：实现批第一次有了可绑的权威——C13 从产品承诺获得领域持有人；S7-1 族的"下一轮归谁"从"由实现抢"变为"由不变量定"；R3（loop 下沉 main）与 V2 并发（派生子执行、折入现役）都有了射程内的位置，不必在实现期临时发明概念。
- **代价**：模型先行意味着**实现批的改动面扩大且不可预估为"小刀"**——按提案 §9 八点冲突，`ConversationPanel.tsx` 的驱动面属重构级；这正是用户接受的方向（"填不完的坑"的替代方案）。
- **风险登记**：①模型先行容易滑向"纸面自洽但无法取证"——以九张域归属卡＋I-T1–I-T9 每条给违背形态来对冲；②反转后 F1–F4 若久拖不裁，实现批比原顺序更早上不了线，故本 ADR 附**待裁清单**而非泛泛推进；③`00 §3.2 要点 1`「槽只有一个」与新"至多一个活动轮"存在被混读的风险（提案 §7 末段已设侵占禁令，落位批须原文写明）。
- **边界**：不含实现设计（scheduler 接口、26 站点收敛手法属实现批）；不含 UI 组件规格（披露条/徽标/四态指示仍按 §4.5 派生待办①前置定名）；本 ADR 不新增领域状态字段的**落位**，落位在批准后的第二批。
