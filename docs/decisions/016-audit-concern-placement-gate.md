# ADR-016：审计域归属闸门（Concern Placement Gate）

- 状态: accepted
- 日期: 2026-10-03
- 相关: ADR-012（测批纪律，同族流程裁定）、ADR-015 案（v2r 引入 window.seq → 十五轴"双钟"攻防 → 用户裁定序号属时间线日志域）、00 §2（BC 职责边界判定表——本闸门的判据源）

## Context

第十五轴对 ApprovalWindow 提案的击穿攻击（"window.seq 与 decisionInstanceSeq 双钟分叉"）被用户裁定为**域归属错位派生的伪问题**：序号是时间线日志域的排序关注，本不该作为 Conversation 域身份存在；攻击场景全部在该错位成立。暴露两个结构性缺口：①提案可把任意字段塞进领域状态而无人问"为什么在这层"；②对抗审计的天性是**在被给定的框架内**把最坏情况打满——框架本身的概念错位，它不但不会质疑，反而会用高质量场景把它固化（garbage framework, sophisticated attacks）。

## Decision（四条规则）

1. **提案义务——域归属卡**：领域模型修订提案**每引入一个状态字段/概念**，落 §对账表时逐条附三问：权威域是谁（Conversation / Workspace 执行 / 时间线日志 / Infra / renderer 呈现）？为何必须在此层？移除后谁兜底？判据＝00 §2 BC 职责边界判定表。答不出＝该概念不得进提案正文。
2. **审计义务——前提复核先于场景攻击**：任何轴（尤其击穿轴）构造攻击序列**之前**，必须先对被审文本的每个新概念出"归属判定"；若某攻击场景只有在该概念被跨层挪用/误置时才成立，**首要发现判"错位"（severity 高于击穿本身）**，该场景作废并注明依赖误置前提。
3. **裁定出口**：错位成立＝结构性问题走"溶解"路径（概念归正确层，衍生攻防全部重述），不得以"裁决哪个更好"的方式保留误置概念继续设计。
4. **裁定来源不豁免（适用于所有来源）**：**任何**裁定/结论——用户当场裁定、我方自我裁决（"审计裁定""执行裁定"类）、对抗审计的发现、竞品调研的建议、产品文档既有断言、历史 ADR 的事实前提——其承载的**事实前提**（"X 属于 Y 域"、"身份用 Z"、"现状是 W"）一律须独立取证确认（对照现有实现与竞品事实基面），不得因来源权威或"当时觉得对"而直接采信。出口三：确认成立（判"成立"）、补隐含前提（出条款）、推翻（回溶解路径）。**适用范围**：① 未来条目——docs/decisions/ 全部新 ADR 与 .handoff 决策条目登记时须标注其事实前提及取证状态；② 现行有效工件——被后续修订引用前先补"前提台账"（前提→证据→状态：已验证/凭印象）；③ 历史过程文物不回改（同本 ADR 代价条款）。首例执行＝ApprovalWindow v3.1（"序号归日志域"经 timeline.ts:12 确认成立；"requestId 身份"发现重启撞号洞，补签发唯一性条款）。

## Consequences

- 正面：杜绝"用攻击复杂度供养一个放错层的小概念"（本轮 v2→v2r→v2s 三稿的钟之纠缠即成本样本）；00 §2 判定表从静态文档升为可执行门禁。
- 代价：提案与每轮审计多一步归属核对（分钟级）；历史提案/审计报告不回改（v2r 系过程文物，v3 与本报告承载结论）。
- 边界：本闸门管**层/域归属**，不管实现对错——argsFingerprint、D5 退役放飞、恢复语义等本轮有效发现证明审计价值本身成立，根治偏差≠削弱对抗强度。
- 全量适用（2026-10-03 用户裁定"需应用到所有"）：规则 4 覆盖一切来源；现行工件前提台账首次清查见 `docs/audits/adr016-premise-sweep-2026-10-03.md`（13 条前提：11 已验证、2 归档确认、零推翻、1 补隐含前提即 v3.1 条款）。
