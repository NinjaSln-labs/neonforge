# 012 — 测完再修（测试轮禁止临修 · 硬闸）

- Status: accepted
- Date: 2026-09-30（同日修订：汇总后须汇报用户裁决，不得自行开修）
- 相关：handoff 坑 p000127（本 ADR 的索引别名，正文勿另写）；曾加 p000135 为重复强调 → 关闭并指向本条

## Context

e2e / UAT 过程中「Fail 一档立刻打补丁再跑下一档」会：破坏整轮取证、用局部绿冒充收口、与根因汇/关单口径冲突。  
原坑 p000127（2026-09-28）已写「只记录、整轮后再汇」，但未标硬闸、且曾被多处复述成多源；2026-09-30 关单轮仍测中连修违规。  
补充裁定：整轮汇总之后，处置权在用户——agent 汇报汇总并等待裁决，不得自行进入开修。

## Decision

权威正文仅本 ADR。其它文件只许引用编号 ADR-012 / p000127，禁止再写一套细则或另开例外清单。

### 硬闸（未满足则不得改代码 / harness / 产品配置）

1. 测试轮进行中（UAT tiers/personas、e2e、L1–L5 回归、冒烟、用户指定的整轮脚本）：发现问题只记录（症状、脚本名、rc、日志/timeline 路径）。不改产品、不改 harness、不改断言、不顺手修。
2. 整轮跑完后：统一整理汇总（症状 → 原根簇 → 证据）。
3. 将汇总汇报给用户，等待裁决（修哪些 / 不修哪些 / 是否拆单 / 是否改设计门槛）。未获用户当轮裁决前，不进入处置或开修。
4. 获准后的处置轮与测试轮分离；修完另开回归轮，回归轮再次适用本闸。
5. 不得：Fail 一档立刻补丁；用单档或局部 smoke 绿关闭整轮未决；把「测中连修」写进修复方案当合法进度。

### 唯一例外（仍须写入当轮汇总，并在汇报中标明）

- 用户当轮明示「先修 X」（即已裁决该项）；或
- 环境死阻塞导致无法继续采集证据（无法换机 / 无法跳过），且仅做恢复取证所必需的最小环境动作（不算产品功能修复）。

## Consequences

- 正面：取证完整；处置前有用户裁决；与关单口径同构。
- 负面：汇总到开修之间多一轮等待——有意。
- 违规处置：停止临修或停修；补汇总并汇报用户；交接记一笔（引用本 ADR），不另起平行规则。
