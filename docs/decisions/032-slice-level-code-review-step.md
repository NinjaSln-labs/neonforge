# 032 — 段6 内循环增「码审（切片级 code review）」：全部产出过异体审查，用户不逐行复核 diff

- Status: accepted（用户 2026-10-06 指出「之前的设计流程里没有 code reviewer」，并对两问亲裁＝**层级＝切片级**／**范围＝全部产出（含主会话亲笔）**）
- Date: 2026-10-06
- 相关：ADR-026（段序／横切独立审计／铁律②／禁跨段）；ADR-031（拆单纪律，本步骤沿用其数值上限与止损）；ADR-030（本步骤首个适用切片 S2/S2a 的接口件）；`.agents/skills/agent-dispatch/SKILL.md`（硬约束 1 不自审／4 同源不审亲笔）；`.agents/skills/code-review`（两轴承载体）

## 背景

段0–段8 流水线（ADR-026）里有三类检查，**没有一类是「代码级审查」**：

1. `stage-gate`（段6 出口闸）＝逐条执行契约件 DoD，射程＝**可机械判定**的断言。
2. 横切独立审计（每段出口）＝段级一致性，对象主要是**工件与实现的整体对应**。
3. 主会话「复核 diff＋跑闸」＝**合并权**（agent-dispatch 硬约束 2 的要求），不是独立审查角色——产出者若是主会话自己，这一环就是同源自审。

2026-10-06 S2a 外派执行班给出三个「缝里过去」的实例：

- **G-1 闸自己失明**：`tests/static/noLegacyImport.test.ts` 解析 `- [ ] A2.x` 取归档面名单，S1 出口闸把 DoD 勾成 `- [x]` 后名单解析成空集＝永远绿的空闸。闸不可能自查自己的锚点前提（发现者＝该测试自带的可红自证针，不是任何审查角色）。
- **断言无可杀性**：S2a Task 2 落了 `amend()` 的两支 I-17 前置，但①缘由支**无正面用例**（只有第 1 条以 `dp.resolution` 读 `undefined` 撞 TypeError 顺带杀到）。这是「删掉一支守卫，测试还全绿」那一类缺陷——DoD 的「≥4 条」计数判据对它完全无感。
- **plan 三处执行期缺陷**：夹具误把 `DecisionPoint.resolve()` 当返回聚合本体；`freezeVersion` 的 `Object.freeze` 产 `readonly[]` 与接口面 `ScopeEntry[]` 冲突（TS2322）；T1/T2 拆界未定（I-8 支落在哪个任务）。三处都由**执行者当场撞出来**，写 plan 与派单的主会话没有独立检查面。

同时：用户明确「我复核 diff 没有什么作用」——逐行读 diff 需要的是上下文而非判断位；把劳动压回用户等于没有审查者。

## 决策

**1. 段6 内循环增一个步骤：码审（切片级）**。每个实现切片（S2a／S2b／后续阶段同构切片）在**其任务全部合入之后、该段出口闸（契约件 F 组）之前**，派**异构 agent** 跑两轴审查：

- **Standards 轴**＝AGENTS.md 纪律、相关 ADR（本例＝ADR-030 案 A）、详设接口面（签名／载荷键集／冻结词表）、plan 边界（有无越界改动、有无顺手扩面）。
- **Spec 轴**＝契约件 DoD 的对应项是否真被实现承载，外加闸测不出的码级质量：**断言可杀性**（删一支守卫会不会仍全绿）、**注释与实况一致性**（假陈述／已失效的「→S2」类措辞）、**双源**（同一条事实的第二份拷贝）。

**2. 审查对象＝全部产出，含主会话亲笔**。外部 agent 的码、以及主会话自己写的码／测试／plan 订正／编排口，同过一关。承载体＝`.agents/skills/code-review`（两轴并行 subagent）。

**3. 审查者资格照 agent-dispatch 硬约束 3＋4**：强模型按用户当场认的算；**同源不审亲笔**——审主会话亲笔者不得与当前主同模型／同渠道（当前主＝`qodercn@Qwen3.8-Flash` ⇒ 取 `mcode@MiniMax-M3` 一类异质执行体；`qodercn@Qwen3.8-Max` 同渠道，只可派**活**、不可审主会话亲笔）。

**4. 拆单与预算照 ADR-031**：每单判据 ≤3、复跑 ≤1 类、工件 ≤4、`--max-turns` ≤15、墙钟 10 分钟档（软线），一个切片按两轴拆 2 单、可并行；D4b 的执行权限前置照给（一次性 worktree），但**码审只读不改码**——产 finding，不产补丁。

**5. finding 处置＝主会话逐条署名采纳／驳回＋理由**，报告落 `docs/reviews/<切片>-<日期>.md`（**由主会话落笔**——外派审查者的产出落 `/tmp/<单号>/`，采纳后写进仓内；外部 agent 不直写仓内文件，承 ADR-031 D4）；**成立项修入后复跑该切片闸**（与既有纪律「采纳修入必复审」同族，不新立条款）。**结论仍由用户亲裁**（流程 3 不变，本 ADR 不移交裁定权）。

**6. 不替代任何现有闸**：`stage-gate` 管可机械判定的 DoD，出口异构审计管段级工件一致性，本步骤管码级质量。三者判据不重叠即不互相反查（防双源，同 §4 谓词／聚合分工的口径）。

**7. 用户位子在结论层**：不逐行复核 diff。要用户看的只有两样＝finding 的采纳结论与段序推进（含 push 授权）。

## 后果

**＋** 主会话亲笔首次有异体检查面；上面三个实例按新步骤本应在切片内被抓，而不是靠运气（G-1 那条靠自证针、另两条靠执行者撞墙）。
**＋** 外派执行模式下主会话的负载从「逐行读 diff」转为「判 finding」，与合并权分离，审查不再是同一双眼睛。
**−** 每切片增 1–2 单成本（约 10–25 分钟＋finding 往返）；段6 出口闸时长基本不变。
**−** 流程增一环就要防它空转：finding 为 0 也须留痕（报告在、判据实测输出在），不允许「审了＝过了」的口头结论。
**−** 审者不合资格时按 ADR-031 D7 归因分岔换体重派，不悄悄降级去审。
**随动项（已同步 2026-10-06）**：段表权威正文 `pipeline-0to1` 在本仓是软链、真身在 agent-skills 仓——那边已把本步骤接进段6（commit `17b4649`，技能版本 1.1.0：段表闸列＋内循环独立成行＋推进流程段6 子项＋拦截条件各一条）。该技能是**通用库技能**（多仓共用），所以条款写成条件式「调用方仓立有此纪律时」，报告落点与纪律来源都不写死具体仓路径与 ADR 编号——技能只负责按调用方约定**触发与拦截**，不替别的仓裁定纪律内容。
