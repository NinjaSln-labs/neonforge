# ADR-021：采纳轮次与驱动权领域模型（Turn/Step/Intent/DriverLease，I-T1–I-T16）

- 状态: **accepted**（2026-10-04；产品负责人授权自裁后由合作负责人落笔采纳。批准范围＝概念集＋不变量；**领域文本落位在第二批**）
- 日期: 2026-10-04
- 正文载体: `docs/design/turn-driver-domain-model-proposal-2026-10-04.md`（v1.1）——本 ADR 只承载裁定、来源、归因与取代关系，不复述模型全文（防双源）
- 相关: ADR-020（顺序反转，本 ADR 是其第①步的完成）、ADR-013／015／016／017／018／019、`00 §3.2/§3.4`、`02 §4.2/§4.12`、`04 §1.1:14`

## Context

产品侧 C13「单一推进点」已由用户裁定写入 `§4.5`（ADR-018 accepted），但领域侧无承载物：无 Turn 概念、无驱动权归属、无 Intent 值对象（提案 §1 的 G1／G2／G3）。后果是**产品承诺没有持有人**——「上一轮已作废为什么还在改状态」这句话在领域里无主语，实现只能靠抢（谁先 ++ 谁说话）。

ADR-020 已把批次顺序反转为"模型先行"。本 ADR 完成模型采纳。

**采纳前的两轴设计校验（不看代码可行性）**：单源化轴 5 条发现、不变量轴 9 条发现。三条 P0 同源，且都是**我自己的老毛病第三次复发**：

| 次  | 错写                                                                               | 被谁否证                                                                                                                 |
| --- | ---------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| 1   | §4.5 C6「跨重启旧卡不可批」未限定族                                                | 字面推翻 ADR-017「≤approved 存续可决」（四轴契约一致性轴抓出）                                                           |
| 2   | §4.5 C2／a6「一切活卡」收回词表资格                                                | 打掉 ADR-017 裁定 3 的授权面文本恰一批准入口（回核自家设计抓出）                                                         |
| 3   | 本提案 v1-draft「决策后不留复活」抬为轮级一般律＋待授权直送写成 `AdmittedNow` 新轮 | `00 §3.4`＋ADR-017 裁定 4＋ADR-019 D2 **三源一致**反对：批复＝同一条记录二次执行、同轮续跑、不新增轮（两轴校验同时抓出） |

⇒ 根因是同一个：**把确认卡族的规则写成"一切卡"的规则**（族未分）。本仓决策面至少三族（确认卡族／`system_clarify` 澄清族／授权窗记录），任何"卡／轮／批复"级的新律，落笔前必须先过族分拣。这条已入坑库（p000158 射程查／族查／承载点查），本 ADR 记为第三次实证。

## Decision

1. **采纳概念集**：Turn（模型轮）／Step（推进步）／Driver（驱动消费者）／DriverLease `{turnId, generation}`／Intent（发送意图）／AdmissionResult（准入五态）／Void／Settle——定义与关系约束以提案 §2、§5 为准。
2. **采纳本体判定**：Turn 为 **Conversation 聚合内实体**，与会话级 PENDING 同宿主同事务边界（提案 §3）。
3. **采纳生命周期与两族出口分离**（提案 §4）：确认卡族 `Suspended → Settled{Resolved}` ＋新轮；**授权面 `Suspended → Running` 同轮续跑**（只引用 `00 §3.4`／ADR-017，不重述）。
4. **采纳身份四轨**（提案 §6）：`turnId`／`generation`／`decisionInstanceSeq`／`requestId` 正交互不替代；R3「身份 doctrine 分裂」定序为**缺第一轨**，非"多轨之过"。
5. **采纳不变量 I-T1–I-T16**（提案 §7），含 v1.1 新增的 I-T10（跨轮批复效果不回写原轮）／I-T11（Step≡Gateway 请求 1—1、重放 ≤1 有痕）／I-T12（Turn 绑 activeTask 不漂移）／I-T13（`submitIntent` 串行、turnId 即准入全序序数）／I-T14（准入序＝队列序，唯用户重排可改且留痕）／I-T15（非终态轮至多一个活动决策点实例）／I-T16（每回合序列至多一个非终态轮；I-T1 系其 V1 投影）。
6. **采纳域归属卡八张**（提案 §8，ADR-016 规则 1 三问齐）——`Turn`/`Step`/`DriverLease`/`QueuedIntent`/`Intent`·`AdmissionResult`/`turnId`·`generation` 持久化/`busy`/取代关系登记。
7. **F1–F4 以"单源化"为唯一准绳裁决**（提案 §10）：F1 实体非聚合根；F2 turnId/generation 唯一资格源、渲染层游标退役为纯呈现投影（判据可机验）；F3 stale 判定不复合化（每判定只有一个权威输入）；F4 卡片点击只产一条 `decision-followup` Intent、回声折入其呈现标记。
8. **取代关系**：ADR-019 Decision 5-4「V1 busy 权威留 renderer＝归属声明」被 **I-T5 取代**（busy 唯一定义式）；ADR-013 裁定 1 的枚举表与 `02 §4.12`「同源」义务降为 I-T5 的**展开与投影**，不再是并行措辞源。ADR-019 其余判定（D1／D2a／D2b／D3 性质、六条 DoD 的实现要求部分、Decision 8 硬闸改述、R1／R3 处置）存活。
9. **实现只作参照**（用户裁定方法论化）：提案 §9 的八点冲突全部登记为**待推翻重构**，禁写兼容层，禁以改动面大小反向裁剪模型。

## Consequences

- **正面**：C13 第一次有了领域持有人；族红的判据从实现级（补丁形状）升到不变量级（I-T1–I-T16 每条自带违背形态，可逐条判定）；R1（Turn 非一等公民）／R3（身份 doctrine）／R4（结构性保证虚假）三条模型级根因在本批闭合；R5（呈现即权威）由 I-T5 的 busy 定义式收口一半（Timeline 与领域状态的权威分工仍待落位批写明）。
- **代价**：实现批（原 C-纠偏批）改动面按 §9 八点评估为**重构级**，且不能再预估为小刀——这是"领域先行"的必然代价，用户已接受（"实现偏离设计以后有填不完的坑"）。
- **风险登记**：①I-T13/I-T14 把"全序"写成不变量，落位时若与 §3.6 任务队列的排序口径不对齐会出现第二个序源——落位批必须同批改 `§3.6` 引用；②I-T15 把澄清族推给 ADR-015，落位批需在 `04` 显式引注，否则"至多一个活动实例"会被读成"同轮不能有两张卡"而误删 `system_clarify` 透传；③本 ADR 批准的是模型，**领域四文尚未改**——若实现批在落位批之前开工，等于回到"无权威可绑"，故顺序为 `采纳 → 落位 → 实现`。
- **边界**：不含实现设计（scheduler 接口、26 站点收敛手法属实现批）；不含 UI 组件规格（披露条／排队徽标／过期卡态／四态指示按 §4.5 派生待办①先定名）；不含 §4.5 契约文本改动（C13 已覆盖，本批无需回头改产品）。
- **测批纪律**：ADR-012 全程有效；a13/a14 仍不预先桩红，随实现批同批转正。

## 附·采纳后更正（同日两轴互审后追加；模型文本随之升至 v1.3）

本 ADR 采纳的是 **v1.1**；随后用**双向互审**（产品→领域 与 领域→产品）再攻一遍，抓出四处需更正，均属本 ADR 批准范围内的事实/命名修正，**不改变裁决方向**：

1. **两处同名异指改名（新增裁决 F5/F6）**——轮内单位 v1.1 叫 Step，与 `03`/`02 §4.8` Session Timeline BC 的记录单位「步骤」（更细粒度）撞词；发送意图 v1.1 叫 Intent，与 `04 §3.6` `IntentConfirmationServices` 的"确认意图"撞词。现定名 **Round** 与 **TurnInput**（服务 `submitTurnInput`，另立 `TurnAdmission` 服务组，不塞进 §3.6）；既有值对象 **`TurnProgress` 改名 `RoundProgress`**（其字段实为往返级，混有 Task 级累积量）。粒度阶梯唯一：**`Task ⊃ Turn ⊃ Round ⊃ 动作`**。
2. **待授权情形由两种拆回三种**（本 ADR Decision 3 的射程扩大）——①确认卡落定→`Settled{Resolved}`＋新轮；②授权批复→**同轮续跑**；③**待授权期发新指令**→**先有痕解算窗内未决请求并释放槽**、原轮 `Settled{Superseded}`、再准入新轮。新增 **I-T17**（取代必须"先解算、再终态化、再准入"——槽未释放就准入＝**假推进**）。
3. **本 ADR Context 表格第三行的引证需更正**——我写"v1-draft 把待授权直送写成 AdmittedNow 新轮，被 ADR-019 D2「不新增轮」否证"，方向对了一半：该括注说的是**出口②（批复）**，被我拿去否证**出口③（新指令）**属张冠李戴；`02 §4.12` 原文只说"可直接处理"，**从未裁定轮次归属**。ADR-019 Decision 2 已就地加限定注。
4. **`turnId` 不得自称"序数"**——`02 §4.8`＋ADR-016 已裁「序号与排序归 Timeline `seq`」，v1.1 的"turnId 即准入全序的序数"复活了被溶解的写法。现改为**两序不互推**（排序归 seq，turnId 只管归属），I-T13 同步改写。

**F7 已关闭（同日用户认可选项 D）**：待授权期新指令＝**焦点轴换人**（未决记录 `pending→queued`、释放槽、推进、槽空时 `drainQueued` 重弹），决定轴不写任何值——**`00 §3.2` 不变量 1 的冻结射程一字未改**，C 选项作废、不再需要动唯一措辞源。落点＝提案 v1.4 §4 出口③＋I-T17/I-T18。裁定依据是一条实现事实：`DecidableApprovalState = {queued, pending}`（可决性不区分二级）＋`drainQueued` 每次重算 ⇒ queued/pending 是**被物化的派生态**。该发现超出轮次射程，已升为缺口 **G10**（进化文档 §3D）。
**采纳范围据此收缩一句**：本 ADR accepted 的是概念集＋不变量＋归属卡；**F7 既关闭，落位批对 `00 §3.2` 只需加一句辨析（槽管等人／轮管推进，互不吞并），不改不变量 1；`02 §4.12` 待授权段改为引用 I-T17/I-T18。**
