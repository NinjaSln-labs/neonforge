## 维度一 · 内部一致性

**F01｜P1｜§7.4 与 §7.1、§11 轴7｜自违其自设纪律**
- 证据：§7.4「"沙箱""高危"在段2 成谓词前**不进任何条文**（段0 裁定 D 纪律）」；但同节 §7 开头「形态＝作用域显式＋授权闸，**不做 OS 级沙箱**」，§11 轴7「不做 **OS 沙箱**」。
- 影响：L0 一边声明「沙箱不进任何条文」，一边在条文里三次使用「沙箱」——自设硬约束当场被自己违反，审计无法判定该词是否已越权。
- 建议：§7.4 的禁入清单与正文用词对齐（要么把「不做 OS 级沙箱」改为不含该词的表述如「不做操作系统级隔离」，要么把该词纳入段2 先行谓词）。

**F02｜P2｜§7.1 对 §0 §4 术语种子的外延改写**
- 证据：L0 §7.1「显式声明作用域（**可触的仓库/目录/命令面**）」；段0 §4 术语种子「作用域（Scope）｜一次委托允许 AI 触及的边界（**文件/命令/网络**）」。
- 影响：外延不一致——L0 去掉了「网络」、新增「仓库/目录」。若为有意收窄（V1 不控网络），未注明；否则属对上游术语的静默改写。
- 建议：显式说明是方法论保留「网络」还是有意移除，并在文字中标注与段0 种子的差异。

**F03｜P2｜§6 能力流与 §8 生命周期分段不对齐**
- 证据：§6「接委托→AI 作用域内推进→对话通道→拍板→证据→验收收尾→**时间线**」；§8「**发起→推进→拍板→核验→收尾**」。
- 影响：段名（「证据」vs「核验」）、段数（§6 含对话/时间线，§8 无）不同构；§8 自称「与北极星同构」，但两处生命周期的口径未收口，为后续追溯埋双写风险。
- 建议：以一处为准，另一处改为引用。

## 维度三 · 纪律合规

**F07｜P1｜旧树引用缺 `@be6e299` 标记（ARCHIVE-INDEX 硬纪律1 ＋ R6 缓解）**
- 证据（逐处）：
  - §4:49「旧树病灶警示（永不再犯）：北极星曾有四个互斥定义…本文件是唯一源」——引用旧树结论无标记；
  - §5:53「（旧树 `07:13`"每周完成写入数"已证伪）」——具名旧树文件引用无标记；
  - §2:26「问题证据来源＝旧树三年实测经验层」；§2:27「旧树 UAT persona 池…」——无标记；
  - §8:79「旧树教训（只作经验）：对话做容器…」——无标记。
- 影响：违反 ARCHIVE-INDEX 第 3 节硬纪律1（「引用必须带 `@be6e299`」），同时正是段0 R6（旧树经验被误当依据回洗）的缓解条款所防之情形；审计无法机械判定这些陈述是「经验」还是「被当成现行依据」。
- 建议：凡涉旧树内容处统一补 `@be6e299`（含 `07:13` 等加显式路径转义）。

**F08｜P1｜「假推进」在谓词成立前进入原则/指标（硬纪律3）**
- 证据：§3 原则4「在动看得见在动、卡住看得见卡住，**无假推进**」；§4 护栏②「卡死/**假推进**事件数」。
- 影响：ARCHIVE-INDEX §3.3 明确「感觉词…（`假推进`…）未成谓词前不得进入不变量条文」，段0 §4 亦点名「假推进＝旧树未成谓词的典型感觉词」。「无假推进」是原则式不变量措辞，且被当作可计数指标——未成谓词即不可判定。
- 建议：原则/指标改用可判定表述（如「无新 timeline 事件的时间窗事件数」），或遵从 D 纪律把定义权留段2 后再进条文。

**F09｜P2｜「伪自主」新感觉词未登记**
- 证据：§5「**伪自主类**：无人盯守时长、自动通过率。」
- 影响：与「假推进」同类，未被纳入段0 术语种子或 ARCHIVE-INDEX §3.3 清单，来源不明。
- 建议：登记入术语种子或改用描述性表述。

**F10｜P2｜§10 自称「不复述」实则枚举；§7.3 复述 C3（单源倾向）**
- 证据：§10「C1–C7 全量继承，**不在此复述**（单源）：桌面 Electron／多 provider 网关／…／单人＋AI 流水线节奏」——已逐条复述内容；§7.3「凭据纪律继承段0 约束 C3：只走 env/本机凭据文件，AI 产出与日志不落凭据值」。
- 影响：与约束 C1–C7「应为引用不复述」相抵触，复述即产生第二措辞源（正是旧树病灶形状）。
- 建议：§10 只留「见 00 §3」指针，删除枚举；§7.3 改纯引用。

**F11｜P2｜§7.2/§7.1 引入未登记谓词**
- 证据：§7.2「触碰**破坏性操作**（删文件、force push、装依赖等）」；§7.4 只禁入「沙箱/高危」，未含「破坏性操作」；§7.1 括注定义「作用域」。
- 影响：以举例方式实质定义了新谓词，而裁定 D 将谓词定义权留段2；列举本身即定义外延。
- 建议：改为产品层描述并标注「待段2 成谓词」，或在 §7.4 的禁入清单中同步列明。

**F12｜P2｜PUBLIC 文档引用本地私有台账 id（死指针）**
- 证据：§4:48「Langfuse/PostHog 候选（**d000090**）」；§9:84「旧发布轴三票 **t000011–13** 维持冻结」。
- 影响：ARCHIVE-INDEX 载明 `.handoff/` 本地私有、禁止入库、调阅走 CLI；在 PUBLIC 入库文中引用其 id，读者无法溯源，且等同把私有台账 id 带入公开面。
- 建议：移除或改写为不带私有 id 的陈述。

## 维度四 · 可验证性

**F13｜P2｜北极星含未定义量词「短周期」**
- 证据：§4「二次委托率：已收尾委托中，用户在**短周期内**再发起新委托的比例（按件计，dogfooding 可测）」。
- 影响：核心指标边界不可判定，指标无法在段4/5 绑已知采点。
- 建议：给「短周期」一个可操作阈值（dogfooding 下可先取经验窗）。

**F14｜P2｜过程指标①「问题关闭率」中「问题」未界定**
- 证据：§4「问题关闭率（以可核验证据收尾 vs 放弃/失败…）」。
- 影响：与术语种子（委托/证据）未接，「问题」在 L0 无归属，计数口径不定。
- 建议：明确「问题」＝委托单的何种收尾状态。

**F15｜P2｜§4 采点原则声称「现成可采点」，未登记指标↔事件映射**
- 证据：§4「每个指标绑一个现成可采点＝timeline 事件流（注册表 `apps/desktop/src/domain/timeline.ts`）」；但北星/3 过程指标/3 护栏共 7 项均未指明对应事件名。
- 影响：无法从 L0 机械核对「7 个指标是否都有现成事件」；对 §5 反指标同理，可操作性悬空。
- 建议：补一张「指标→timeline 事件类型」对照（可留段4 细化，但 L0 应至少声明映射存在性）。

**F16｜P2｜定位陈述中的感觉词作「承诺」还是「理由」未区分**
- 证据：§1「敢把活儿交出去，也敢把注意力移开」；§3「信任的地基」。
- 影响：这些属定位修辞/理由尚可，但若被后续段当作承诺会不可判定。
- 建议：标注其为定位语，非可验收承诺。
- （正面：§1「每个'完成'可追溯到证据、每个拍板有独立通道、每次等待有归宿」、§4 护栏③「崩溃恢复成功率」、§5 反指标等主体承诺**可判定**，未发现「好用/智能/流畅」类承诺。）
