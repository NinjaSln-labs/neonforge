## 0 结论前置

1. **当前驱动拓扑＝实现偏离，不是设计选择。** 竞品八家中**零先例**采用"多入口各自直接发起在飞链＋轮询发现过期"；全部是「意图入队/注入 → 唯一消费者在回合边界决定是否起下一轮」。框架层（LangGraph Pregel/BSP、AutoGen actor）把"共享状态单写者"做成硬约束。
2. **但纠偏的措辞必须精确**：不是"消除抢占/禁止代次作废"——Codex 恰恰用 `abort_all_tasks(Replaced)` 做 turn 级抢占，并用 CancellationToken＋generation 语义。**偏离点是"抢占的形态"**：竞品＝单一入口持有＋**同步取消**；我们＝26 个入口各自异步 ++sid、旧链靠 500ms 轮询迟滞自杀，**在被判过期期间仍在写会话状态**。
3. **因此阶 C 拆两批**：C-纠偏批（D1–D3，照既有权威文本回归，无需新设计）→ C-补模批（G1–G3，须 ADR＋域归属卡）。顺序是依赖不是偏好：`roundOrdinal` 只有在发起权收成一处之后才有单调源可写。
4. 一条与本表同源的反例记录在案：opencode 的合法形态是 **busy 直接报错拒绝**而非排队（`run-state.ts:56-73`）——说明"入口单消费者"有 `queue-admission` 与 `admission-refused` 两种，**两者都成立，但都要求单一仲裁点**。我们采排队（§4.5 C3 已裁），不是唯一正解，是有据的选择。

## 5 两批的判据与风险

**C-纠偏批**（D1–D3；保留 D4/D5 语义）

- 形态目标：`send()` 拆为 `submitIntent(kind, text, answers?, reason?)` → 入队＋上屏；唯一 scheduler 在回合边界决定是否发起下一轮，并**持有同步取消令牌**（取代 26 处异步 `++sid`＋500ms 迟滞发现）。`maybeContinue` 缩为"本回合内的工具等待"，不再跨回合裁决。busy 改为 scheduler 的派生投影（订阅），删三处手动同步清。
- 风险＝**轮序变动**：A/B 实测证明它会打到 `retry:188`／`core:388`／`factory.self:30`＋`:73`（≈6–8 例桩把轮序当标定）。本批与 A/B 的**实质区别**：可以指着 `02 §4.12`＋`04 §3.2:412` 说"新轮序才是被规定的轮序"——桩重标是**按权威文本重标**，不是"为了让它绿"。此区别必须写进 DoD，否则又会滑成 014→015 那条补丁链。
- 验收（沿用 §4.5 已改写口径）：≥6 轮整项目冷启 0 红 ＋ TMP 确定性复现不再红 ＋ 事件流中不再出现"同轮内新实例被随后的 reject 打掉" ＋ 挂载类与归属类分开计 ＋ **孤儿链不得再 flush**（D1 专项断言）。

**C-补模批**（G1–G3）

- 需 ADR＋`00/02/04/06` 四份同步（`00 §3.2` 是不变量 1 唯一措辞源，牵动面最大），每条新概念出域归属卡三问（权威域／为何在此层／移除后谁兜底）。
- 硬依赖：必须在纠偏批之后——G1 的 `roundOrdinal` 需要单一 ++ 点才有单调源；现形态下每条链各自 ++sid，字段无处可写。
