## 1. 持久化架构（方案丙，用户 2026-10-07 裁）

**单一持久化文档**（`configStore` 模式单文件，路径注入、`0o600`、原子替换），两段：

```jsonc
{
  "schemaVersion": 1,
  "log": [ /* EventEntry[]：seq＋event，append-only，authoritative */ ],
  "snapshots": {
    "delegations": [...], "scopes": [...], "decisionPoints": [...],
    "turns": [...], "queue": {...}, "evidence": [...]
  }
}
```

**三条口径（本文件的宪法）：**

1. **`log` 是权威**：`snapshots` 是**同事务物化视图**，不是第二权威（同一文件、同一次原子替换，无第二 DB/文件）。
2. **载入 = 读快照 ＋ 用 log 重放校验**：重放 7 聚合所得与 `snapshots` **逐字段比对**——一致 ⇒ 采信快照（快路径）；不一致 ⇒ `RecoverableSpec` 不过 ⇒ `DelegationRestored(恢复结果=失败＋原因)`、**拒绝恢复**（契约 B4）。快照是**加速＋校验**，不替代重放。
3. **`save()` = 把该聚合的物化视图写进 `snapshots` 段**，与本次 `append` **同一次原子落盘**（契约 A3）。

**为何非事件字段能活**：`Turn._expiredWrites`（I-13 计数器）**不在 log 闭集**（段3 §5 尾注：不入 timeline），故它只住在 `snapshots.turns`。这是快照段存在的**第一理由**（纯重放方案甲会丢它）。

**升级路径**（段3 §6 登记、V1 射程外）：出现跨进程写者时引入 outbox——本件不预设，登记位见 §10。

## 2. 7 聚合持久面（签名归本件；实现落 `src/domain/repos/persistent/**`）

**接口不变**（契约 A1）：`repos/index.ts` 的 7 接口**逐名冻结**；持久实现类替换内存实现，装配点 `domainRuntime.ts` 换 new。

**每聚合加一对快照方法**（聚合侧、纯函数、无 IO）：

| 聚合 | 快照方法 | 快照字段（＝重建所需全部状态） |
|---|---|---|
| Delegation | `toSnapshot(): DelegationSnap` / `static fromSnapshot(s): Delegation` | `delegationId, intent, state, reopenCount` |
| Scope | `toSnapshot()` / `fromSnapshot` | `delegationId, versions[]{seq,entries,amendmentRef}`（整条链） |
| DecisionPoint | `toSnapshot()` / `fromSnapshot` | `decisionPointId, delegationId, turnId, requestReason, resolution` |
| Turn | `toSnapshot()` / `fromSnapshot` | `turnId, delegationId, triggerSource, terminal, expiredWrites`（**含非事件字段**） |
| InstructionQueue | `toSnapshot()` / `fromSnapshot` | `queueId, items[]{itemId,delegationId,inputId,origin,state,turnId}` |
| EvidenceItem | `toSnapshot()` / `fromSnapshot` | `evidenceId, delegationId, type, provenance, payloadRef, firstInspected, inspectionCount` |
| TimelineLog | （**不加快照**：log 段本身即其持久形） | `EventEntry[]` |

> **§2 字段表完备性自检**（防同型漏项）：本表＝该聚合**全部实有状态**。逐聚合对 `src/domain/**` 的 `private`/`readonly` 字段点过数——Delegation `{delegationId,intent,_state,_reopenCount}`（`Delegation.ts:31-34`；`awaitingUser` 是 `_state` 取值已含）；Scope `{delegationId,versions[]{seq,entries,amendmentRef}}`（`Scope.ts:34`＋`:17-19`）；DecisionPoint 五字段（`DecisionPoint.ts:43-47`）；Turn `{turnId,delegationId,triggerSource,terminal,expiredWrites}`（`Turn.ts:25-30`；`token` 由 (delegationId,turnId) 派生故省略）；InstructionQueue `{queueId,items[]}`＋QueueItem 六字段（`InstructionQueue.ts:61-62`／`:19-24`）；**EvidenceItem 补 `firstInspected/inspectionCount`**（`EvidenceItem.ts:70-71`，C-03）。

**TimelineLog 载入**（D-05）：按 `doc.log` 序逐条 `record()`，seq 自然重生成、`nextSeq` 随之复位；**不新增公开构造面**；等价性由 §4.1 判据1（seq 良构）前置保证。

**持久实现**（`src/domain/repos/persistent/`）：一个**通用 JSON 文档仓储**（`PersistentStore`）持文档读写＋原子替换；7 个 Repo 类各包一层（`save` 写对应 `snapshots` 段、`find*` 读内存投影）。**投影（内存态）与文档同进程共存**：读走内存投影，写走「改投影＋落文档」（写失败回滚口径见 §4.2）。

> **ponytail：** 不做通用 ORM/迁移框架；`schemaVersion` 只作读侧守卫（未知版本 ⇒ 拒绝加载＝A4）。

## 3. 存储格式与迁移策略（计划 §8 移交项 2）

- **格式**：单 JSON 文档（上 §1），`JSON.stringify(doc, null, 2)`，`mode: 0o600`。
- **路径**：构造注入（`NF_TEST_USERDATA` 可注入，沿 `configStore`；测试全用临时目录＝契约 A6），生产＝`app.getPath('userData')/domain/state.json`。
- **原子写**（契约 A5）：写 `state.json.tmp` → `rename` 覆盖（同目录原子替换）；半写 `.tmp` 不被读侧观察。
- **损坏容错**（契约 A4）：文件缺失/截断/非法 JSON/`schemaVersion` 未知 ⇒ 读侧不崩溃；**有数据却读成空＝红**——即：文件存在但解析失败 ⇒ **拒绝加载并报错**（走 B4 失败路径），不静默清空。
- **迁移策略**：V1 无历史格式（首个持久化版本），`schemaVersion=1`；**不预设未来迁移器**（YAGNI），未知版本一律拒绝加载（fail-closed）。

## 4. RecoverableSpec 与恢复服务（段3 §8；契约 B3/B4/C1/C2/C3）

### 4.0 重放折叠（`src/domain/replay.ts`，纯函数）——口径2 的执行主体

**签名**：`replay(log: readonly EventEntry[]): Snapshots`（无 IO、纯函数、可独立测试，与段3 §8「纯谓词」纪律同形；产出与 `doc.snapshots` **同形** ⇒ 口径2 的「逐字段比对」＝一次深层深比较）。

**聚合侧不新增公开构造面**：重建一律走 `Aggregate.fromSnapshot(replay(log)[聚合段])`，**7 聚合不加 rehydrate 构造口**（§2 只加那一对快照方法）。

**逐事件折叠规则**（18＋2 事件 × 影响面）：

| 事件 | 折叠动作（写入 snapshots 哪段哪个字段） |
|---|---|
| DelegationCreated | `delegations+={delegationId,intent,state:'created',reopenCount:0}`；`scopes+={delegationId,versions:[v1(seq=1,entries=[])]}`（initial v1 链） |
| InputAcknowledged | 无聚合态变更（归宿只读） |
| TurnStarted | `turns+={turnId,delegationId,triggerSource,terminal:null,expiredWrites:0}` |
| TurnEnded | `turns[turnId].terminal = terminal` |
| DecisionRaised | `decisionPoints+={decisionPointId,delegationId,turnId,requestReason,resolution:null}` |
| DecisionResolved | `decisionPoints[dp].resolution = {value,option?,ts}` |
| DecisionDenied | `decisionPoints[dp].resolution = null`（保持未决；拒绝理由不进聚合） |
| ScopeAmended | `scopes[delegationId].versions += 新版本（seq/entries/amendmentRef）` |
| ChangeProduced | 无聚合态变更（证据采集由 EvidenceRecorded 落） |
| EvidenceRecorded | `evidence+={evidenceId,delegationId,type,provenance,payloadRef,firstInspected:false,inspectionCount:0}` |
| EvidenceInspected | `evidence[id].inspectionCount+=1`；首次⇒`firstInspected=true` |
| CompletionClaimed | `delegations[id].state='pendingVerify'` |
| DelegationAccepted | `delegations[id].state='accepted'` |
| DelegationRejected | `delegations[id].state='rejected'` |
| DelegationReopened | `delegations[id].state='reopened'`；`reopenCount=payload.reopenCount` |
| DelegationClosed | `delegations[id].state='archived'` |
| InstructionQueued | `queue.items+={itemId,delegationId,inputId,origin,state:'queued',turnId:null}` |
| InstructionAdmitted | `queue.items[itemId]={state:'admitted',turnId:payload.turnId}` |
| **SessionInterrupted**（S3 新增） | `turns[turnId].terminal='中断'`（**B-01 正解**：无需新事件、闭集 22 不动、快照与重放天然一致；与段3 §5 尾注「不另立事件」同向） |
| **DelegationRestored**（S3 新增） | 无聚合态变更（恢复结果只读） |
| StallDetected / DelegationAbandoned | `never`（S5 接线前不出现） |

**代价（自检纪律）**：§2 字段表＝该聚合**全部实有状态**——逐聚合对 `src/domain/**` 的 `private`/`readonly` 字段点数（本次实测见 §2 表注）。

### 4.1 `RecoverableSpec(persistedState)` — `src/domain/spec/recoverable.ts`

纯谓词：`recoverable(doc): { ok: true } | { ok: false; reason: string }`。判据：
1. `doc.log` 良构（seq 单调、无重号跳号、事件名∈22 闭集——**名单单源＝`EVENT_NAMES`**；**不做运行时荷载键校验**：键集由 `PayloadMap`＋判别式 `Pair<T>` 编译期钉死，运行时另持键表＝二源）；
2. `doc.snapshots` 良构（7 段可 `fromSnapshot` 重建）；
3. **`replay(doc.log)` ≡ `doc.snapshots`**（逐字段深比较；不一致 ⇒ `{ok:false, reason:'snapshot≠replay'}`）。

### 4.2 恢复服务 `RestoreDelegation` — `src/main/recovery.ts`（形态归本件）

时序（计划 §8 移交项 3）：

```
启动 → 读文档
  ├─ 文档缺失 ⇒ 空态重建（新库，非恢复）
  └─ 文档存在：
       ① RecoverableSpec 判（§4.1 三判据）
         不过 ⇒ 拒绝恢复；DelegationRestored(恢复结果=失败＋原因)（B4）；聚合不上线 ▸ 结束
         ok   ⇒ 采信快照，聚合上线（fromSnapshot）
       ② 经 TurnRepo.findInFlight()（I-1 既有读侧）判「未收口在飞轮」：
          非 null ⇒ 同一次落盘内：轮聚合 terminal='中断' ＋ append SessionInterrupted（B2/B5/C1/C3）
                    —— 两者同事务（段3 §6「委托/轮聚合＋timeline」；单文件一次原子替换）
          null   ⇒ 不追加（B2 反支）
       ③ DelegationRestored(恢复结果=成功)（经 append；草稿由 `Delegation.restore(result)` 产，见 §5）
```

**丢失范围三值**（契约 C1）：下界＝**追加 `SessionInterrupted` 之前**的 `log` 末 seq N；上界＝N+1；`log` 为空 ⇒ 字面 `"不可判定"`（枚举值，**不留空/不 undefined**）。**注**：上界与本事件自身 seq 同号是**有意**——在飞的字节流从来没有 seq，故可表达的丢失范围只能退化；此即 I-12「不可计算」的常态来源。

**在飞流不重放**（契约 C2）：恢复**只**重建账本态，不产生任何 chunk/stream 续接事件。

**重复恢复＝no-op**（契约 B3）：第二次恢复不追加事件、不改状态。

**写失败方向的投影回滚**（B-02 口径）：持久落盘（`rename`）抛错 ⇒ 调 `TimelineLog.rollbackTo(追加前 lastSeq)` 且**不 save 投影**（严格事务）；与 `InMemoryTimelineRepo.append` 现有回滚路径同型（`timeline.ts:299-302`）。
