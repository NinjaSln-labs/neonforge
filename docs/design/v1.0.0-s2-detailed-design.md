## 2. Scope 聚合与 AmendScope（I-8／I-17）

```ts
// src/domain/authorization/Scope.ts —— 追加面（现有 initial/version/entries/covers 签名不变）
export class Scope {
  // 唯一版本追加口。前置＝I-17；违反抛 DomainError('I-17'|'I-8')，抛则零写入、零事件。
  amend(dp: DecisionPoint, entries: ScopeEntry[], ts: string): { scope: Scope; draft: EventDraft }

  // 只读面（E3 呈现用）：整条链，seq 升序；返回值全部冻结，改写旧版本无路径（A3）。
  get chain(): readonly ScopeVersion[]
}
```

- **入参＝决策点本体，不是它的 id**：I-17 的判据输入是「缘由＝作用域修正 ∧ 已批准」这两个事实，只给 id 就得反查仓储（破坏「纯聚合命令可独立测试」，同 ADR-029 D3 的取舍理由）。
- **三条前置，逐条对应不变量**：①`dp.requestReason.reason === '作用域修正'` ②`dp.resolution?.value === '批准'`（`'拒绝'`/`'选项'`/未决一律拒——批准权仅用户，段2 X8）③`dp.decisionPointId` 未被任何 `amendmentRef` 用过（I-8 同决议只产一版本）。①②③任一不满足 ⇒ 抛且不追加。
- **追加而非替换**：`chain.push({ seq: 末位+1, entries: 冻结副本, amendmentRef: dp.decisionPointId })`；`seq` 由聚合自己算，调用方给不进来越序（I-8 单调）。同实例返回自身（Repo 已持引用，`save` 幂等），与 S1 的 `initial()` 共用同一构造路径（CC-05 出生口统一的正解）。
- **VO 冻结**：`ScopeVersion.entries` 与链元素 `Object.freeze`；现 `get entries()` 直接吐内部数组引用，本阶段改吐冻结副本（A3「就地改写旧版本的路径命中＝0」由类型面＋运行时冻结两面承载）。
- 决策点**作废**后不再产版本＝S5（`DelegationAbandoned` 消费），S2 只保证「未决/拒绝/选项」三支拒绝。

## 4. Specifications（全外延，I-7 扩面）

```ts
// src/domain/spec/requiresApproval.ts —— 形参不变（op, scope, list）；ADR-029 D3 的 scope 本体保留
if (op.category === '作用域修正') return true // ③类恒真：修正必经拍板（I-17 的命令前置由 Scope.amend 复核，两处不同源＝谓词判「要不要拍板」，聚合判「拍板够不够」）
if (!scope.covers(op.entryKind, op.resource)) return true // ①作用域外
return op.hits !== null && list.includes(op.hits) // ②清单命中
```

- 真值表 3×2×2 面（C2 ≥6 条）：作用域外∪清单命中∪修正 任一真⇒真；作用域内∧未命中∧非修正⇒假。`op.hits` 非 null 但不在清单⇒不算 ②（清单是闭集，S-3 守它不被就地改写）。
- **谓词不判「有没有已批准决议」**（那是 §2 聚合前置），因此 ③类恒真不代表修正一定成功——两处各司其职，不合并、不互相反查（合并即双源）。

## 5. 编排：谁消费决议（段3 §6「作用域修正」行＝事件驱动）

```ts
// src/main/domainRuntime.ts —— 新增编排口（main 侧唯一调用 Scope.amend 的地方）
amendScope(input: { delegationId: string; decisionPointId: string; entries: ScopeEntry[] }):
  { version: number } | null   // null＝决议不在场/未批准/已用过（I-17 抛，接线层转命令回执，不崩进程）
```

时序＝`decision:resolve(批准)` 之后由**用户动作**显式发起（§7 通道），不在 resolve 处理器里自动追加：①保持 `DecisionPoint` 公开命令只有 `raise`/`resolve`；②避免「卡片渲染时机与决议消费」耦合进同一事务（S5 作废面来时这条边界要复用）；③I-8 决议丢失＝无版本，天然成立。决议在场性经 `rt.decisionPoints.findById` 读，Scope 与 append 同事务写（§6）。

**【上游冲突登记 2026-10-06｜待用户亲裁】**段3 §6 跨聚合一致性表「作用域修正」行原文＝触发事件 `DecisionResolved(缘由=作用域修正)→ScopeAmended`、一致性策略「**事件驱动（授权域内 Scope 消费决议）**」、同事务范围「Scope 聚合＋timeline」、幂等「同 decisionPointId 只产一个版本」。本件 §5 取**命令式消费**（用户发起 `scope:amend`，聚合读决议事实），与该行的读法冲突，故在此显式登记、不静默偏离：

- **冲突根因**＝新 entries 在上游没有载体。`DecisionRaised`/`DecisionResolved` 的载荷键集**禁增禁减**（段3 §5／S1 详设 §6 契约面），修正后的条目内容因此无法随决议事件流抵达 Scope；若强行加键＝回段3 改冻结件（铁律②第六次，且动到 22 事件载荷契约面）。
- **案 A（本件采用）**＝命令式消费：决议是事实，`amend` 命令读它作前置（I-17），事件流仍只由 `Scope.amended` 草稿经唯一机制口落账。同族先例＝S1 已实现的上表「拍板→续推进」行（`ipcDomain.ts` 的 `decision:resolve` 处理器内 `markAwaitingUser`，同样是接线层消费点而非订阅器），该行「事件驱动（推进订阅）」在 S1 出口闸与异构审计下未被判红——实现形态归段5/段6 的判断**已在仓内立过例**。
- **案 B（不作建议）**＝回段3 给 `DecisionResolved` 载荷加 entries 键、改回真订阅。代价＝动上游 22 事件契约面＋违反「载荷键禁增禁减」的既有裁定，收益只有措辞整齐。
- **判据不受影响**：A4（无决议不产版本）、A5（批准权仅用户）、B2（同事务）、I-8 幂等（`amendmentRef` 查重）在案 A 下逐条可测；改判案 B 时本件 §5/§7 需重写、契约件不动。
- 裁案 A 后本登记转 ADR（实现形态裁定），F8「无新语义裁定」相应改为引用该 ADR 编号。

## 7. IPC 通道与 renderer 切分（§7 面的 S2 增量）

```
scope:chain   (delegationId) -> ScopeVersionDTO[]      # 只读；当前版本＝末元素，历史全部可查（E3）
scope:amend   (delegationId, decisionPointId, entries) -> { version } | { rejected: true, why }
```

- 两通道进 `DomainChannel` 联合；`scope:amend` 是唯一新增**写**通道，处理器内只做「取聚合→调 `rt.amendScope`→经 `rt.log` 落账」，命令回执携拒绝理由（I-5/I-15 留痕口径，不进 timeline）。

- 桥面 `preload.ts` 加 `scope: { chain, amend }`，`types.d.ts` 的 `NeonforgeBridge` 同步；`ScopeEntryDTO` 复用 `delegation:create` 里既有的 `scopeEntries` 形状，不另造第二套。
- **`ScopePanel.tsx`（新建一块）**：当前 entries 只读＋「提出修正」→ 走 `decision:raise(requestReason={reason:'作用域修正', operation, requestedBy})`；批准后面板内编辑的新 entries 交 `scope:amend`。零核心聚合 import（S-1 保持绿）。
- **`DecisionCard.tsx`（改）**：缘由节点加 `data-cause={reason0.reason}`（L3 选择器面，E1 三类各一条）；卡片底部加一行留痕＝`lastResolution` 的「决议值＋拒绝理由（有值才渲染，无值不留空占位）」（E2）。单卡纪律不变（多待决项完整呈现属 S6）。

**S-3 承载体**（`tests/static/s3HighImpactList.test.ts`，沿 S-1/S-2/G-1 的「复用 vitest 跑静态判据、零新工具」选型）：

**正式 glob（偿清 `Scope.ts` 天花板，不引依赖、不做通用匹配库）**：`matches(kind, pattern, resource)` 按资源类型分流——

| kind | 命中规则 | 正例 | 反例 |
|---|---|---|---|
| 仓库／目录 | 按 `/` 分段：`**`＝全放行；尾随 `/**`＝深度不限前缀；段内 `*`＝恰好一段 | `src/**` 命中 `src/a/b.ts`；`docs/*/x.md` 命中 `docs/a/x.md` | `src/**` 不命中 `test/a.ts`；`docs/*/x.md` 不命中 `docs/a/b/x.md` |
| 命令 | 首 token 精确相等，或 `prefix*` 前缀 | `git status`；`npm*` 命中 `npm install` | `npm*` 不命中 `nodepm x` |
| 网络 | host[:port] 精确，或 `*.domain` 后缀（只匹配点边界） | `example.com:443`；`*.githubusercontent.com` | `*.github.com` 不命中 `evilgithub.com` |

隐藏测试文件 `tests/unit/scope.covers.test.ts`（A7 ≥6 条，上表正反例逐行落格）。原 `ponytail:` 注释随偿清删除——天花板已不存在，留注释即失真。
