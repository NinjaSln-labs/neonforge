## 2. Scope 聚合与 AmendScope（I-8／I-17）

```ts
// src/domain/authorization/Scope.ts —— 追加面（现有 initial/version/entries/covers 签名不变）
export class Scope {
  // 唯一版本追加口。前置＝I-17；违反抛 DomainError('I-17'|'I-8')，抛则零写入、零事件。
  amend(dp: DecisionPoint, entries: ScopeEntry[], ts: string): { scope: Scope; draft: EventDraft }

  // 只读面（E3 呈现用）：整条链，seq 升序；返回值全部冻结，改写旧版本无路径（A3）。
  get chain(): readonly ScopeVersion[]
}
```

- **入参＝决策点本体，不是它的 id**：I-17 的判据输入是「缘由＝作用域修正 ∧ 已批准」这两个事实，只给 id 就得反查仓储（破坏「纯聚合命令可独立测试」，同 ADR-029 D3 的取舍理由）。**边界声明（F-2）**：本件取「聚合命令读聚合外的值对象」，与段3 §8 头注「**纯谓词**可独立测试」的射程不同——那条约束只管 `spec/` 下的谓词（§4 的 `requiresApproval` 仍不收仓储、不收决议），聚合命令本就以其它聚合的公开只读面为输入（S1 的 `admissionCheck(op, scope, list)` 同形），不构成「谓词不再纯」。
- **三条前置，逐条对应不变量**：①`dp.requestReason.reason === '作用域修正'` ②`dp.resolution?.value === '批准'`（`'拒绝'`/`'选项'`/未决一律拒——批准权仅用户，段2 X8）③`dp.decisionPointId` 未被任何 `amendmentRef` 用过（I-8 同决议只产一版本）。①②③任一不满足 ⇒ 抛且不追加。
- **追加而非替换**：`chain.push({ seq: 末位+1, entries: 冻结副本, amendmentRef: dp.decisionPointId })`；`seq` 由聚合自己算，调用方给不进来越序（I-8 单调）。同实例返回自身（Repo 已持引用，`save` 幂等），与 S1 的 `initial()` 共用同一构造路径（CC-05 出生口统一的正解）。
- **VO 三层深冻结（F-7）**：①链元素对象 `Object.freeze`；②`ScopeVersion.entries` 数组 `Object.freeze`；③数组内每个 `ScopeEntry`（`kind`/`pattern` 两字段）逐个 `Object.freeze`——浅冻结只挡①②，`entries[0].pattern = 'x'` 仍能逃逸，而 A3「旧版本只读可溯」要堵的正是这一手。`amend()` 写入前对入参 entries 做**逐条拷贝再冻结**（不 freeze 调用方对象：外来数组属接线层，改写它不是领域事实）。现 `get entries()` 直接吐内部数组引用（实测成立），本阶段改吐冻结副本；A3 两面承载＝类型面 `readonly`＋运行时 `Object.isFrozen` 断言。
- 决策点**作废**后不再产版本＝S5（`DelegationAbandoned` 消费），S2 只保证「未决/拒绝/选项」三支拒绝。

## 4. Specifications（全外延，I-7 扩面）

```ts
// src/domain/spec/requiresApproval.ts —— 形参不变（op, scope, list）；ADR-029 D3 的 scope 本体保留
if (op.category === '作用域修正') return true // ③类恒真：修正必经拍板（I-17 的命令前置由 Scope.amend 复核，两处不同源＝谓词判「要不要拍板」，聚合判「拍板够不够」）
if (!scope.covers(op.entryKind, op.resource)) return true // ①作用域外
return op.hits !== null && list.includes(op.hits) // ②清单命中
```

- 真值表 3×2×2 面（C2 ≥6 条）：作用域外∪清单命中∪修正 任一真⇒真；作用域内∧未命中∧非修正⇒假。`op.hits` 非 null 但不在清单⇒不算 ②（清单是闭集，S-3 守它不被就地改写）。
- **谓词不判「有没有已批准决议」**（那是 §2 聚合前置），因此 ③类恒真不代表修正一定成功——两处各司其职，不合并、不互相反查（合并即双源）。
- **既有双源登记（F-14）**：`作用域修正` 这个字面同时是 `DecisionPoint.ts` 的 `RequestCause` 成员与 `requiresApproval.ts` 的 `OperationCategory` 成员（两处 `=== '作用域修正'` 比较，§2 前置①与 §4 ③类各引一处）。这是 **S1 已入库的事实层双源**，本阶段**不动、不合并**（合并＝改上游词表，超 S2 射程）。风险与处置：将来任一侧改写即两处判定错位——由 §9 新增一条同源词表断言（`tests/unit/scope.vocabulary.test.ts`：两联合的成员集在运行时以枚举数组形式逐字相等）承担，闸在 L1、不新增依赖。**本件不为此开新不变量编号**。

**正式 glob（偿清 `Scope.ts` 天花板，不引依赖、不做通用匹配库）**：`matches(kind, pattern, resource)` 按资源类型分流——

| kind | 命中规则 | 正例 | 反例 |
|---|---|---|---|
| 仓库／目录 | 按 `/` 分段：`**`＝全放行；尾随 `/**`＝深度不限前缀；段内 `*`＝恰好一段 | `src/**` 命中 `src/a/b.ts`；`docs/*/x.md` 命中 `docs/a/x.md` | `src/**` 不命中 `test/a.ts`；`docs/*/x.md` 不命中 `docs/a/b/x.md` |
| 命令 | 首 token 精确相等，或 `prefix*` 前缀 | `git status`；`npm*` 命中 `npm install` | `npm*` 不命中 `nodepm x` |
| 网络 | host[:port] 精确，或 `*.domain` 后缀（只匹配点边界） | `example.com:443`；`*.githubusercontent.com` | `*.github.com` 不命中 `evilgithub.com` |

**实现量声明与伪代码（F-6，v0.2 补）**：本会话实测现 `matches()` 对 §8 表的**三条正例判不过**——`docs/*/x.md`→`docs/a/x.md`、`npm*`→`npm install`、`*.githubusercontent.com`→`a.githubusercontent.com`（现实现只有 `**`／尾随 `/**`／字面相等三支）。所以 A7 不是「补个注释」的量，是一支约 20 行的分流函数＋caller 签名改动，写进 §1 item 1 的实现量里：

```ts
// Scope.ts —— 分流面（covers 的调用点全仓只有 requiresApproval 一处，caller 随动成本可忽略）
const segEq = (p: string, r: string) =>
  p === r || (p.includes('*') && new RegExp('^' + p.replace(/[.+?^${}()|[\]\\]/g, '\\$&').replace(/\*/g, '[^/]*') + '$').test(r))

function matches(kind: ResourceKind, pattern: string, resource: string): boolean {
  if (pattern === '**') return true
  if (kind === '命令') return pattern.endsWith('*') ? resource.startsWith(pattern.slice(0, -1)) : resource === pattern
  if (kind === '网络') {
    if (!pattern.startsWith('*.')) return resource === pattern
    const dot = pattern.slice(1)               // '*.github.com' → '.github.com'（点即边界）
    return resource.endsWith(dot) && resource.length > dot.length
  }
  const ps = pattern.split('/'), rs = resource.split('/')
  return pattern.endsWith('/**')
    ? rs.length >= ps.length - 1 && ps.slice(0, -1).every((p, i) => segEq(p, rs[i]))
    : ps.length === rs.length && ps.every((p, i) => segEq(p, rs[i]))
}
```

`covers(kind, resource)` 的 `kind` 形参它本来就有（现签名 `(kind, resource)`），改动＝把 `kind` 往 `matches` 透传，现实现是 `matches(pattern, resource)` 丢掉了 kind——**caller 侧零签名变化，改的是 `matches` 自身 arity**（F-5 更正我 §1 那句「covers 新增 kind 形参」：`covers` 早收 kind，不需要动）。命令支不收 argv——首 token 由调用方传入，领域层不做 shell 解析（超射程）。
