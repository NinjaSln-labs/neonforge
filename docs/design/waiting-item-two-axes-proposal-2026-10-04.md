## 1. v1 被否证的三点（先记账，防换个人再来一遍）

| # | v1 主张 | 否证证据 | 处置 |
| --- | --- | --- | --- |
| 1 | 等待项分三型（求决／待进／待启） | **澄清族 `system_clarify` 塞不进**：产品 `§4.5 C2a` 明载"属对话素材采集，不是决策点"，作答即收口、打字与点选等价；若归求决型，则同轮它与底层确认卡共存（ADR-015 #3／I-T15）**当场否证**我写的"至多一个 front" | 三型**取消**（见 §3） |
| 2 | 同上 | **处级"待审核"塞不进**：产品 `§3.3`「待审核: N 处」→已暂存→写入（＝漏报 N1 ChangeReview），N 条**并存**等用户逐条接受，既违 I-FOCUS-1，也没有决定轴值可填 `staged` | 同上，并确认 **N1 是独立聚合**（不由本提案兼并） |
| 3 | 决定轴五值（undecided/resolved/settled/expired/uncertain） | 这条轴自己犯了 v1 诊断 `§3.6` 的病——把**用户决定／执行结果／时效／不可证**四种来源的事实压进一根轴；`uncertain` 既是决定终结又是**新求决项的发端**（ADR-017 `resolveUncertain` 唯一出口），单轴表达不了 | 决定轴**不新建**（沿用既有 ADR-017 字段面），本提案只管焦点 |

**结论**：G10 的真实需求不是"给所有等待项建一个超类型"，而是**三句话能写完的东西**——焦点是派生的、同一时刻只有一件事在向用户发问、各族的次序按既有律走。建 `WaitingItem`＋`kind` 枚举后，`kind` 字段过不了 ADR-016 规则 1 的"移除后谁兜底"一问（无人兜底，各文档本可一句写清），反而把 N2/G4 三张票拴成一张。

## 2. 本提案只做三件事

1. **焦点轴派生化**：`front/back` 是**派生视图**，不得作为权威字段存储（`queued/pending` 的焦点含义去物化）。
2. **槽独占律成文**：把散在 `00 §3.2 要点 5`、ADR-017 文本恰一入口、I-T17/I-T18 里的同一事实收敛成一条正面规则。
3. **次序律显式化**：把"现在轮到谁"从实现搬到文本（**确认卡族 ＞ 授权记录**这一级**不是新裁定**，是 `00 §3.2 要点 5` 的既有事实的正面写法）。

## 3. 判据换掉：不是"等谁的动作"，而是"是否占会话的唯一发问通道"

v1 用"等谁"分型，导致澄清族／Problem.awaiting-input／一键安装 各处同时属两型。正解是**通道独占性**：

> **一个会话同一时刻只有一条"向用户发问"的通道**（＝§3.2 的槽）。能占这条通道的只有**决策卡族**（goal/plan/resolution ＋ 授权记录）；其余一切"等待"都不占通道，各自按自己既有的序规则走。

由此：

| 等待事实 | 占通道？ | 次序/存续规则（**沿用既有，不新建**） |
| --- | --- | --- |
| 确认卡族（goal/plan/resolution） | **是**（唯一） | ADR-015 实例寻址；C6 不因时间消失、跨重启旧实例不可批 |
| 授权记录（窗内 N 条） | **是**（但**让位**于确认卡族） | ADR-017 单窗 N 可寻址、`requestId`、存续可决、跨重启按恢复三判 |
| 澄清族 `system_clarify` | **否** | C2a 素材采集通道；与底层卡共存由 ADR-015 #3 委派透传承载（**不新建律**） |
| 待准入输入 `QueuedInput` | **否** | I-T13/I-T14 准入全序与 FIFO；C3 按条可见 |
| 排队任务（§3.6 `○`） | **否** | §3.6 对象序（＝N2 TaskQueue 独立票） |
| 处级待审核 diff（§3.3） | **否**（多条并存） | N1 ChangeReview 独立票 |
| Problem `awaiting-input`／"一键继续" | **否** | `02 §4.13` 台账态；呈现按 C4 族 |
| 交付验收（delivered/closed/adjusting） | 经**解决确认卡**占通道 | 走第 1 行规则（它是确认卡族的 resolution 项，不另立） |

⇒ **"待审核"必须按两处分裁**（审校 P0-3）：任务级 `◉` 是**解决确认卡的队列呈现**（映射到第 8 行），处级 `待审核 N` 是 **N1 的独立聚合**——两者都不是新等待型。

## 4. 不变量（只留可证伪的四条 ＋ 一条落位义务）

| # | 不变量 | 依据（既有文本） |
| --- | --- | --- |
| **I-FOCUS-1 通道独占** | 同一时刻至多**一个**占通道的等待项处于 `front`；其余占通道项为 `back`——**`back` 不降低其可决性**（仍可经按 `requestId`／按实例 id 的显式入口答复） | `00 §3.2 要点 1/5`＋ADR-017 单窗 N 可寻址 |
| **I-FOCUS-2 次序律** | `front` 由纯函数决定：**确认卡族 ＞ 授权记录**；同族按**入态序**；跨型不参与竞争。**入态序的输入必须显式给**（不可跨 BC 读 Timeline `seq`——那会让纯函数输入不闭合；也不可复辟领域序数——`02 §4.8`／ADR-016 已裁"序号归 seq"）。落位时定为：**入态序由各聚合自身的既有单调量提供**（授权窗＝入窗序、确认卡＝`decisionInstanceSeq`），**不新增全局计数器** | 第一级＝`00 §3.2 要点 5` 正面化；第二级避 `02 §4.8` 坑（审校 P1-5） |
| **I-FOCUS-3 焦点派生化** | `front/back` 不作权威存储。**可证伪形式（审校 P2-7 修正）**：焦点**只经唯一投影入口可读**，非投影层（含判定路径）读到焦点位即违规——原句"谁忘了重算"换成"谁绕过了投影入口"，才有判据 | 单源化准绳；`drainQueued` 每次重算＝它本就是派生态 |
| **I-FOCUS-4 换焦不改决定** | 焦点移动**不得写入决定轴任何值**；未决项跨移动仍存续可决；换焦必须可见 | I-T18（本条是它在通道的普遍形式，I-T18 反过来成为本条的特例） |
| **I-FOCUS-5 伪焦点禁止（审校 P1-6 补）** | `front` 必须满足**可答复性**：跨重启后旧确认卡实例不可批（C6／ADR-015 `restorePending`），而授权记录存续可决（ADR-017 恢复三判）——**两族跨重启语义相反**，故 `deriveFocus` 的输入必须含各家的**有效性判定**，否则会算出"点了没用的伪焦点" | C6＋ADR-015＋ADR-017 三判 |
| （落位义务，非不变量） | 换焦发事件留痕——审校 P2-10 指出 v1 把它写成不变量是重犯 ADR-021 刚切开过的错（事件写失败不改变通道事实），故降为义务，落 `06` 事件表 | I-T4/I-T8 同一分法 |

**反模式警示（审校 P2-8 补，必须写进落位文本）**：`I-FOCUS-5` 的"恰一可决才认文本批准"里的"恰一"＝**可决集基数为 1**，**不是**"恰一个 front"。把两者混为一谈会让窗内 3 条未决时文本批准误生效＝**行为改变**，这是去物化唯一可能引入回归的点。

## 5. 对 ADR-017 的关系：精化去物化，不推翻

- `ApprovalRecord` 的**决定面**（approved/denied/failed/expired/uncertain、`requestId`、四入口、journal 三判、`uncertain` 禁自动重放）**一字不动**。
- 现有 `state: queued | pending` 的**焦点含义去物化**：`queued/pending` 仍是存储字段（兼容旧档），但其**语义降为"投影快照"**，权威判据改由 `deriveFocus` 提供；读到旧档时**以重算为准**，不信存的值。
- `DecidableApprovalState = {queued, pending}` 改述为**"未决即可决"**（基数判定与焦点无关），避免新实现把它读成"只有 pending 可决"。
- **恢复三判与去物化不打架**（审校 P2-8）：可决集本就含二级，三判作用在决定轴 × journal 上。

## 6. 过度设计自检：如果只做一半

**最小半案**＝只做 ①`queued/pending` 去物化＋②次序律成文（I-FOCUS-2）＋③`00 §3.2 要点 5` 改引用式。
**放弃的东西**：统一词汇（N2/G4 各自写自己的序规则，不做映射表）。
**损失**：无正确性损失——`kind` 字段与超类型的"移除后谁兜底"答案是"无人"，所以全案本来就没在买什么。**因此本提案就按最小形做，不再升回超类型。**

**与 N2/G4 的关系改为"平行不前置"**：G10 解绑后，N2 TaskQueue 与 G4 Message 生命周期各自独立成票（v1 把它们拴在 G10 上是审校打中的第二个错）。

## 9. 随本票必须修掉的落位缺陷（第一路审校打的 P0/P1，逐条登记）

1. **P0 `drainQueued` 双源**：`§3.2 要点 5` 写"槽释放 ⇒ drainQueued"（无条件），`§3.7 出口③` 写"槽再空**且无活决策点**时升回"——新轮 Running 期间槽即空且无活决策点，按要点 5 卡会立即重弹并复置 `approval`，冻结新轮执行＝正是 I-T17 要防的假推进。**修法**：`要点 5` 加「且无 Running 轮」谓词（这是呈现派生条款的精化，不触不变量 1 本体；`要点 6` 的"不改写本节"须同步收窄为"不改写要点 1–4（尤其不变量 1）"），`出口③` 改纯引用。
2. **P1 busy 第三源**：见 §8-2。
3. **P1 `Rejected` 射程不一致**：`§3.7.2` 生命周期图对一切 TurnInput 开放 `Rejected` 无注，而 `04 §2.11`／`06 §1.0`／C13a 都写"对用户输入永不"——图上加引用式限定。
4. **P1 改名令未执行到的处**：`04 §3.1` 注释仍是"本轮输出结构化提议／上一轮工具失败"（点名要改的没改）；`02 §4.3`「上一轮工具执行失败」是第五处、清单漏列——补入 §3.7.5 清单并实改。
5. **P1「回合边界」定义不含出口③**：产品 C13 只写"现役链收口／被打断之后"，而取代式准入发生在 Suspended。修法二选一已定：**产品 C13 补"被取代之后"**（产品有缺口就修产品，用户既有授权口径）。
6. **P2 引用悬垂**：`00 §3.7.3` 引"§4.8"、I-T9 引"§4.12"未带文档前缀（两者实为 `02`）；`02 §4.12` 引"§4.5 C13"未注明是产品文档——统一加前缀。
7. **P2 终态数不一致**：I-T4 列六（含 Voided），`06` 与 `10` 说"五终态"——统一为"五 `Settled` 子态 ＋ `Voided`"，Voided 走 `turn_voided`。
8. **P2 `10 §6` 谎称已执行**：表内残留 `StepProgress`／`intent_queued`／`intent_rejected`（实落 `RoundProgress`／`input_queued`／`input_rejected`）——行内容与实落对齐。
9. **P2 主事件方向**：C13a 要求走既有 `stale_input_discarded`（ADR-015 landed），`06 §1.0` 却把 `input_rejected` 定为主、stale 为投影——**反向**。裁定：`stale_input_discarded` 为**过期答复作废的主事件**（既有、不动），`input_rejected` 只用于**非 stale 的内意图拒绝**（如被取代的 nudge 触发），两者不重叠。
10. **P2 措辞夹带**：I-T1 括注"故亦作至多一个非终态轮"不是本体推论而是 V1 射程注（I-T16 已标 V1 不可断言）——拆成独立注；`§3.7.1` 说"判据 §2 判定表第一行"实为新补那行；出口表"授权批复"行重述了 §3.4/ADR-017 细节，宜只引编号。
