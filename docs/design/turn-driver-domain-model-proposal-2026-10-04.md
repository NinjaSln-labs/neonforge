# 轮次与驱动权领域模型提案（Turn / Step / Intent / DriverLease）

- 版本: **v1-draft**（2026-10-04）
- 性质: **领域设计提案**——只定义本体、生命周期、身份、不变量与归属；**不含实现改造方案**（ADR-016 规则 1 走卡，用户终裁后才谈落位）
- 射程声明: 现行实现**只作参照，不作约束**。本提案与现形态冲突之处一律登记为「待推翻重构」（§9），不以"现在做不到"缩小模型边界——那是实现迁就设计反被设计迁就实现的倒置。
- 相关: ADR-018（§4.5 C1–C13 产品权威）、ADR-019（驱动拓扑裁定与批次划分；其顺序部分由 ADR-020 反转）、ADR-013（busy/silent）、ADR-015（决策点实例寻址）、ADR-016（规则 1 域归属卡）、ADR-017（授权窗口/requestId）、`00 §3.2/§3.6`、`02 §4.2/§4.12`、`04 §1.2/§3.1`

---

## 1. 缺的是什么对象

产品层已经把"谁在什么时候开口"写死成 C1–C13（ADR-018 accepted），其中 **C13 单一推进点**是本提案的锚。但领域侧没有承载它的东西：

| 代号   | 缺口                                                                                                            | 现状表述能力                                                                     |
| ------ | --------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------- |
| **G1** | 没有 **Turn（模型轮）** 这个一等公民——领域里只有 Task（目标推进单元）、Message（呈现）、PendingDecision（等待） | 「上一轮已经作废了，为什么它还在改状态」这句话在领域里**无法成立**，因为没有主语 |
| **G2** | 没有**驱动权**的归属——"谁有资格发起下一个模型往返"在领域里无人持有                                              | C13 是产品承诺，领域侧**无对应物**＝承诺没有持有人                               |
| **G3** | 没有 **Intent（发送意图）** 值对象——`send(text, opts)` 是调用形态，不是领域概念                                 | 「排队／打断／折入／拒绝」四态（C7）无法被讨论，只能被 if-else                   |

三条的共同后果：**轮次归属在产品里可被要求、在领域里不可被表达、在实现里只能被抢**（谁先 ++ 谁说话）。

## 2. 通用语言（ubiquitous language）

| 术语                     | 定义                                                                           | 用户可见对应                                       |
| ------------------------ | ------------------------------------------------------------------------------ | -------------------------------------------------- |
| **模型轮 Turn**          | 搭档的一次完整"开口"：自被准入起，到收口或作废止，其间由**唯一驱动消费者**推进 | 一条搭档气泡（含其多段产出与工具卡）；"处理中"呈现 |
| **推进步 Step**          | Turn 内的一次模型往返（一次 Gateway 请求及其工具执行的总和）                   | 气泡内的续写、工具执行条                           |
| **驱动消费者 Driver**    | 持有租约、有权发起下一个 Step 的执行体                                         | 不可见（领域内部）                                 |
| **驱动租约 DriverLease** | `{turnId, generation}`——Turn 的推进资格；`generation` 递增即整体作废           | 不可见                                             |
| **发送意图 Intent**      | 待准入的输入：文本/结构化载荷＋来源标记＋归属绑定                              | 用户气泡、卡片点击、系统触发                       |
| **准入 Admission**       | 仲裁点对 Intent 的裁决：立即成轮 / 排队 / 有痕拒绝 / （V2）派生                | 排队中徽标、失败态、重提示                         |
| **作废 Void**            | 使某 Turn 的租约失效的单点动作（显式打断或抢占）                               | 停止按钮生效；被打断轮留下残值（C9）               |
| **收口 Settle**          | Turn 的正常终局（四子态见 §4）                                                 | 气泡定格、"处理中"消失                             |

**关系约束**：`Task 1—N Turn`；`Turn 1—N Step`；`Turn 0—1 决策点实例产生`（一个轮至多弹一张新卡）；`Intent N—1 Turn`（多数 Intent 不成轮，成轮者各自只由一个 Intent 触发）。

## 3. 本体判定：Turn 落在哪一层

**判定：Turn 是 Conversation 聚合内的实体（非聚合根），与会话级 PENDING 同宿主。**

理由（判据＝`00 §2` BC 职责边界判定表）：

1. 「谁推进下一轮」是**推进决策**，推进决策归 Conversation（判定表第一行：Conversation 决定「能不能动」）；
2. 轮次资格与会话级单一 PENDING 必须在**同一事务边界**内检查——`00 §3.2 要点 2` 的"用户决策是下一个状态的唯一输入"，其"下一个状态"若无轮次身份，就是无主语的真命题；
3. 与既有选型一致：`04 §1.1:14` 已定 Task 与 pending「结构合并」以免双聚合同步开销——Turn 独立成聚合会重新引入该开销，且没有任何跨聚合不变量需要它独立。

**明确否掉的方案**：Turn 作聚合根（无独立事务边界需求，且恢复/持久化会被迫另立一套与 Problem/task-log 竞争的存档）；Turn 作 Message 属性（Message 是呈现层产物，把资格挂在呈现上＝`00 §3.2 要点 5` 已裁过的"UI 现象代理领域状态"）。

## 4. Turn 生命周期

```
Intent ──[submitIntent 仲裁]──→ 准入裁决（§5）
   │
   ├ 立即成轮 ─→ Turn(turnId=++唯一源, generation=1) : Running
   └ 排队      ─→ QueuedIntent（持久于会话队列，可撤回/编辑/重排＝C3）→ 到边界再走准入
Running: 每个 Step 前复核租约（generation 等值）
   ├─ 产出推进（工具执行 / 结构化提议 / 证据 / 提问）        → 继续 Running
   ├─ 决策点弹出（deriveDecisionPoint 求值为非 none）        → Suspended（等人——不计 busy，ADR-013）
   ├─ 无进一步可推进且非挂起                                → Settled{Completed}
   ├─ 零产出（请求 done 而无内容）                          → Settled{Empty}
   ├─ 请求失败 / 被中止                                     → Settled{Failed}
   └─ 显式打断 或 被新决策抢占                              → Voided（generation++，租约失效）
所有终态：恰好一个，且必须释放 busy（I-T4）
Suspended ──[用户决策]──→ 该轮 Settled{Resolved}（决策落地＝轮终局）＋ **新轮**由决策后续意图发起（C1/C13）
```

**要点四条**：

- **续链不是新轮**：`maybeContinue` 式自推进、工具链多步、强制推进（ProgressGuarantee require-advance/require-action）全部是**同 Turn 内的 Step**。此前把它们当"另一条链"处理，正是"两套引擎互相抢占"的语病根源。
- **决策后不留复活**：用户在卡上落定 → 旧轮 `Settled{Resolved}` → 下一句由**新 Turn** 的搭档开口（C1「下一句由搭档开口」＋C13）。领域上禁止"恢复挂起前的动作续跑"——`00 §3.4` 已定「用户决策后模型**重新做**，不是恢复 pending 前的动作」，本模型把它从"动作层"抬到"轮次层"。
- **Voided 不是撤销已完成**：残值（已写文件、已产出内容、已跑验证）保留可查（C9）；回滚是独立事件（快照回滚），不得混入作废语义。
- **Suspended 不计 busy、Running 必计 busy**：ADR-013 的 busy 表在领域里获得定义式表达（I-T5），不再靠呈现层猜。

## 5. Intent 与准入（G3 的答案）

```
Intent {
  payload: Text | DecisionEcho | SystemTrigger
  source:  'user-input' | 'decision-followup' | 'card-echo' | 'nudge-progress'
         | 'nudge-reconcile' | 'recovery-interrupt'      // 来源是一等属性，不是调用点位置
  binding?: DecisionAnswer {kind, instanceId}             // ADR-015 答复携带
  requestId?: string                                      // ADR-017 授权执行携带（D4 直送）
}

submitIntent(intent) → AdmissionResult
AdmissionResult = AdmittedNow(turnId)     // 立即成轮
              |  Queued(position)         // 排队，下一边界准入（V1 唯一非即时态）
              |  Rejected(reason)         // 有痕拒绝（只对内意图，见 C13a）
              |  Folded(turnId)           // 折入现役轮——V1.5（§4.5 C7「转向」）
              |  DerivedExecution(turnId) // 派生为有身份的子执行——V2
```

**来源与准入的对应**（V1 射程）：

| source                               | V1 准入默认                                                                                      | 说明                                                                                                                        |
| ------------------------------------ | ------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------- |
| `user-input`                         | Running 时 `Queued`；Suspended 时按 §4.5 C2 判为补充信息（不成轮）；**待授权时**可 `AdmittedNow` | D4「待授权直送」不是例外通道，而是**仲裁策略**——旧形态把它做成"调用点自己 ++"，模型上它只是"当前无 Running 轮 ⇒ 可立即成轮" |
| `decision-followup`                  | `AdmittedNow`                                                                                    | 用户决策落定后的搭档自述轮；无用户气泡（C1）                                                                                |
| `card-echo`                          | 不产 Intent（只作呈现，C1）或 `AdmittedNow` 且标 `source='card-echo'`                            | 二者必择一，禁止既当发言又当驱动——ADR-018 C1 反转的模型化                                                                   |
| `nudge-progress` / `nudge-reconcile` | `AdmittedNow`（须当前无 Running）＋**必附披露条**（C4）                                          | 催推进／对账引导                                                                                                            |
| `recovery-interrupt`                 | 先 `Void` 现役轮，再 `AdmittedNow`                                                               | 显式恢复打断（ADR-013），唯一合法的抢占发起方                                                                               |

**作废与抢占**（Codex `abort_all_tasks(Replaced)` 先例，ADR-019 P6）：抢占是**仲裁点的动作**——`Void(现役轮) → AdmittedNow(新 Intent)` 在一个原子步骤内完成，`generation++` 同步生效。禁止任何形式的"发起方自行宣告作废"。

## 6. 身份 doctrine（四轨正交）

| 身份                    | 语义单位           | 签发者                                             | 单调性来源                         | 消费方                                 |
| ----------------------- | ------------------ | -------------------------------------------------- | ---------------------------------- | -------------------------------------- |
| **turnId**              | 一次开口           | 仲裁器（`submitIntent` 的 `AdmittedNow`/出队准入） | **领域内唯一 ++ 点**（I-T3）       | 租约、Timeline 关联、归属取证、a13/a14 |
| **generation**          | 同一轮的第几代资格 | 作废动作（`Void`）                                 | 单调递增，CAS 比较                 | 每个 Step 前的租约复核                 |
| **decisionInstanceSeq** | 决策点**实例**     | `setPending`（ADR-015，不动）                      | 实例推进（kind/结构签名变化才 +1） | 答复寻址与 stale 门                    |
| **requestId**           | 授权请求记录       | main `needApproval` 分支（ADR-017，不动）          | 跨进程跨重启唯一                   | 执行核验、journal 对账                 |

**四轨不可互替**——它们回答四个不同的问题：_哪一轮_（turnId）、_这轮还有效吗_（generation）、_答复打的是哪张卡的哪一次呈现_（instanceSeq）、_批准的是窗里哪一条_（requestId）。所谓「身份 doctrine 分裂」（领域评审 R3）的病根不是有多套身份，而是**缺了第一轨**，于是渲染层的 `sessionRef/sid` 长期代行 turnId＋generation 双职——一个私有 UI 游标同时是取消令牌，这正是"发起权分散"的实现形态。

**原则**：`turnId`/`generation` 由领域签发后，渲染层若仍需消息游标，只能作**纯呈现投影**（改名、不承载任何裁决）。跨重启：`turnId` 续号取持久会话内最大值（`generation` 随之重置为新轮的 1），与 ADR-017 的 requestId「跨进程跨重启唯一」同理，不复用、不回拨。

## 7. 不变量

| #        | 不变量                                                                                                                                | 产品/领域对应                       | 违背的典型形态                                |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------- | --------------------------------------------- |
| **I-T1** | 一个 Turn 至多一个驱动消费者；**V1 内一个会话至多一个非终态 Turn**                                                                    | C13／§3.6 串行队列                  | 多站点各自开轮；续链与用户输入并发            |
| **I-T2** | 租约失效（generation 不等）后，该轮的一切状态写入为 no-op                                                                             | C5／`04 §3.2:412`「结构性，非拦截」 | 轮询迟滞自杀、过期窗内继续写会话状态          |
| **I-T3** | `turnId` 只在准入点递增；任何调用点无权自增                                                                                           | C13                                 | `const sid = ++sessionRef` 散落               |
| **I-T4** | 每个 Turn 恰好一个终态，且终态必然释放 busy 与呈现收口                                                                                | C5／a5                              | 零产出不 finalize（幽灵"处理中"）             |
| **I-T5** | `busy ≡ ∃ Turn ∈ {Running}`（Suspended/idle 不计）；UI `working` 与 UAT `modelBusy` 是它的投影                                        | ADR-013 裁定 1／`02 §4.12` 同源     | effect 镜像＋手动补清                         |
| **I-T6** | `Queued` 意图的终局只有三种：成轮 / 用户撤回 / 有痕作废；**不存在第四种（静默丢弃）**                                                 | C3／C13a                            | 入队后被顶掉且无感知                          |
| **I-T7** | 一个用户决策至多触发一个后续 Turn；同一 `binding` 的意图不得重复准入（代次 CAS）                                                      | C1／β 案"双发射器"                  | 证据引导与协议 nudge 同读一个滞后状态各开一轮 |
| **I-T8** | 轮次归属必须可取证：每个 Turn 的产生/终态/作废都发 Timeline 事件，且该轮所有事件携 `turnId`                                           | C10 取证义务／a1–a14 的地基         | 只有 sid 比较痕迹、事后无法归因               |
| **I-T9** | pending（会话级 PENDING）冻结优先于轮次推进：有活 pending 时不准入任何新轮（待授权例外按 §5 的策略处理，其本质是无 Running 轮可让位） | `00 §3.2 要点 2`                    | pending 期模型动作"做了白做"却真的执行了      |

**与唯一措辞源的边界（防侵占）**：I-T9 只是**引用** `00 §3.2`（不变量 1 唯一措辞源，ADR-015 #8），不重述、不改写、不与之并列另立。本模型新增的是"轮次"这一维度，不是第二条 PENDING 语义——**槽只有一个**说的仍是 pending 槽，与本提案的"至多一个活动轮"是两件事（前者管等人，后者管谁在推进），落位时须显式写明，禁止互相吞并。

## 8. 域归属卡（ADR-016 规则 1——逐概念三问）

| 概念                             | 权威域                                                             | 为何必须在此层                                                                             | 移除后谁兜底                                           |
| -------------------------------- | ------------------------------------------------------------------ | ------------------------------------------------------------------------------------------ | ------------------------------------------------------ |
| Turn（实体）                     | **Conversation BC**                                                | 推进决策与轮次资格是"能不能动"的一半（另一半是 pending）；判据 `00 §2` 第一行              | 无人兜底——发起权退回调用点即"抢"，C13 无从谈起         |
| Step                             | Conversation（领域记录）／Gateway（执行事实）                      | 一次往返的**决策**在 Conversation，**字节**在 Gateway 通用域                               | Gateway 已有请求事实；缺的是"它属于哪一轮"的归属       |
| DriverLease（turnId+generation） | **Conversation BC 持有，执行载体（渲染层进程）持有副本并逐点复核** | 资格判定是领域规则，载体只能服从；与 ADR-017「裁决在 main、呈现投影在 renderer」同构的分层 | 若无领域持有＝取消令牌退化为 UI 游标（现状病根）       |
| QueuedIntent 队列                | Conversation BC                                                    | 排队是会话级待决内容，跨呈现存续（C3 可撤回/编辑/重排＝要持久）                            | 现由渲染层私有数组承载——本模型升格为领域概念           |
| Intent（值对象）                 | Conversation BC                                                    | 它是"待准入的输入"，准入是推进决策                                                         | 无                                                     |
| AdmissionResult（值对象）        | Conversation BC                                                    | 同上，是仲裁的输出                                                                         | 无                                                     |
| turnId / generation 持久化       | Conversation BC（随会话存档），Timeline 记录副本                   | 续号需要跨重启单调源；Timeline 是事件真相源但不是资格来源                                  | `00 §3.2` 与 Problem 快照已有同构做法                  |
| **busy**                         | **领域派生量**（∃ Running Turn），呈现层与 UAT 只投影              | I-T5 的定义式；`02 §4.12` 同源义务的落点                                                   | 若不建派生而是继续镜像，族红以新签名复活（ADR-019 D3） |

> 卡外一项**有意不落领域字段**：§4.5 的"排队中徽标／披露条／四态指示"是呈现概念（ADR-018 立节约束），本提案只给它们提供数据源（I-T6/I-T4/C10），不把它们做成状态成员。

## 9. 现行实现与模型的冲突登记（参照，不是约束）

以下与 §1–§8 冲突，一律视为**待推翻重构**项，模型不因它们"改起来难"而让路：

1. 26 个调用点各自开轮（发起权分散）⇒ 违反 I-T1/I-T3。
2. 私有 UI 游标兼作取消令牌、靠轮询迟滞自杀 ⇒ 违反 I-T2（且是 `04 §3.2:412`「结构性非拦截」的偏离）。
3. 续链与工具链被当作独立链处理 ⇒ 违反 §4「续链不是新轮」。
4. `working`/`modelBusy` 靠 effect 镜像维护＋散点手动补清 ⇒ 违反 I-T5（ADR-013 同源义务）。
5. 排队意图住在渲染层私有数组、drain 挂在链尾 finally（任意链、含孤儿链）⇒ 违反 I-T6 与 §4.5 C3。
6. 零产出轮不 finalize、失败轮原地抹气泡 ⇒ 违反 I-T4 与 C10。
7. 措辞词表在消费时刻判 reject（S7-1 族根因）⇒ 违反 §5（准入按 source，不按措辞）与 C2。
8. Timeline 无轮次维度（`assistant_start` 载荷仅 `forceTool`）⇒ 违反 I-T8。

> 勘误一条（属文档事实错误，非模型冲突）：`02 §4.12` 与 ADR-013 引用的停止按钮选择器 `.nf-chat__stop` 不存在，真名 `.nf-chat__send--stop`——落位批一并改（p000157）。

## 10. 待用户终裁的四个分叉（其余为可推翻的细节）

| #      | 分叉                                                                             | 我的推荐与理由                                                                                   | 若否定的后果                                                   |
| ------ | -------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------ | -------------------------------------------------------------- |
| **F1** | Turn 作 Conversation 内**实体**（§3）还是独立**聚合根**                          | **实体**——无跨聚合不变量需求，且与 `04 §1.1:14` 结构合并选型一致                                 | 需另立 Turn 的持久化与恢复语义，与 Problem/task-log 竞争真相源 |
| **F2** | `sid` 退役为**纯呈现游标**（turnId 接管资格）还是彻底删除                        | **退役不删除**——消息渲染需要游标，但它必须改名且不承载裁决                                       | 删除则呈现层需另找 diff 锚；若保留现职＝模型被架空             |
| **F3** | stale 判定是否升级为复合 `{turnId, kind, instanceId}`                            | **不升级**——ADR-015 的门已足够，复合会把轮次耦合进决策点寻址（新故障面）；turnId 只用于归属取证  | 若升级，需同步重设计 restorePending 补水路径，工作量显著上升   |
| **F4** | `card-echo` 是**不产 Intent**（纯呈现）还是产一条 `source='card-echo'` 的 Intent | **产 Intent 但来源一等标记**——按钮确需驱动推进，否认它就得为驱动另造通道（重蹈 silent 冒充打断） | 若不产，卡片点击后的推进必须借 decision-followup，语义会变模糊 |
