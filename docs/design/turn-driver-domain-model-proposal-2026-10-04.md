# 轮次与驱动权领域模型提案（Turn / Step / Intent / DriverLease）

- 版本: **v1.1**（2026-10-04；v1-draft 经两轴设计对抗校验后修订——单源化轴 5 条、不变量轴 9 条。**P0 三条同源**：我把确认卡族的规则写成了轮级一般律，误伤授权面——本仓第三次同族错误「族未分」，见 §4 与 P3）

## 1. 缺的是什么对象

产品层已把"谁在什么时候开口"写成 C1–C13（ADR-018 accepted），其中 **C13 单一推进点**是本提案的锚。领域侧没有承载它的东西：

| 代号   | 缺口                                                                                          | 现状表述能力                                                             |
| ------ | --------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------ |
| **G1** | 没有 **Turn（模型轮）** 这一等公民——领域里只有 Task（目标推进单元）、Message、PendingDecision | 「上一轮已经作废了，为什么它还在改状态」这句话**无法成立**，因为没有主语 |
| **G2** | 没有**驱动权**的归属——"谁有资格发起下一个模型往返"无人持有                                    | C13 是产品承诺，领域侧无对应物＝**承诺没有持有人**                       |
| **G3** | 没有 **Intent（发送意图）** 值对象——`send(text, opts)` 是调用形态，不是领域概念               | 「排队／打断／折入／拒绝」四态（C7）无法被讨论，只能被 if-else           |

共同后果：**轮次归属在产品里可被要求、在领域里不可被表达、在实现里只能被抢**（谁先 ++ 谁说话）。

## 2. 通用语言（ubiquitous language）

| 术语                     | 定义                                                                   | 用户可见对应                                 |
| ------------------------ | ---------------------------------------------------------------------- | -------------------------------------------- |
| **模型轮 Turn**          | 搭档的一次完整"开口"：自准入起至收口或作废止，其间由唯一驱动消费者推进 | 一条搭档气泡（含多段产出与工具卡）；"处理中" |
| **推进步 Step**          | Turn 内的一次模型往返（一次 Gateway 请求及其工具执行的总和）           | 气泡内的续写、工具执行条                     |
| **驱动消费者 Driver**    | 持有租约、有权发起下一个 Step 的执行体                                 | 不可见（领域内部）                           |
| **驱动租约 DriverLease** | `{turnId, generation}`——推进资格；`generation` 递增即整体作废          | 不可见                                       |
| **发送意图 Intent**      | 待准入的输入：载荷＋来源标记＋归属绑定                                 | 用户气泡、卡片点击、系统触发                 |
| **准入 Admission**       | 仲裁点对 Intent 的裁决（五态，§5）                                     | 排队中徽标、失败态、重提示                   |
| **作废 Void**            | 使某 Turn 的租约失效的单点动作（显式打断或抢占）                       | 停止按钮生效；被打断轮留下残值（C9）         |
| **收口 Settle**          | Turn 的正常终局（四子态，§4）                                          | 气泡定格、"处理中"消失                       |

**关系约束**：`Task 1—N Turn`（I-T12）；`Turn 1—N Step`（I-T11）；`Turn 0—1 活动决策点实例`（I-T15——**v1.1 修订**：原写"一个轮至多弹一张新卡"被 ADR-015 #3 的 `system_clarify` 递归透传否证，强制澄清与底层确认卡可同轮共存、kind 变化再推实例）；`Intent N—1 Turn`。

## 3. 本体判定：Turn 落在哪一层（F1＝已裁）

**判定：Turn 是 Conversation 聚合内的实体（非聚合根），与会话级 PENDING 同宿主。**

判据（`00 §2` BC 职责边界判定表）：

1. 「谁推进下一轮」是**推进决策**，推进决策归 Conversation（判定表第一行：Conversation 决定「能不能动」）；
2. 轮次资格与会话级单一 PENDING 必须在**同一事务边界**内检查——`00 §3.2 要点 2` 的"用户决策是下一个状态的唯一输入"，其"下一个状态"若无轮次身份，就是无主语的真命题；
3. 与既有选型一致：`04 §1.1:14` 已定 Task 与 pending「结构合并」以免双聚合同步开销——Turn 独立成聚合会重新引入该开销，且没有任何跨聚合不变量需要它独立。

**明确否掉的方案**：Turn 作聚合根（无独立事务边界需求，且恢复/持久化会被迫另立一套与 Problem/task-log 竞争的存档真相源——违反单源化）；Turn 作 Message 属性（把资格挂在呈现上＝`00 §3.2 要点 5` 已裁过的"UI 现象代理领域状态"）。

## 4. Turn 生命周期

```
Intent ──[submitIntent 仲裁（串行，I-T13）]──→ 准入裁决（§5）
   ├ 立即成轮 ─→ Turn(turnId=++唯一源, generation=1) : Running
   └ 排队      ─→ QueuedIntent（会话队列；可撤回/编辑/重排＝C3）→ 到「回合边界」再走准入
Running: 每个 Step 前复核租约（generation 等值）
   ├─ 产出推进（工具执行 / 结构化提议 / 证据 / 提问）→ 继续 Running（新增 Step）
   ├─ 请求瞬态失败且有重放预算 → 同 Turn 新增 Step（I-T11：不新开轮、不违终态唯一）
   ├─ 决策点弹出（deriveDecisionPoint 非 none）→ Suspended（等人——不计 busy，ADR-013）
   ├─ 无可进一步推进且非挂起 → Settled{Completed}
   ├─ 零产出（请求 done 而无内容）→ Settled{Empty}
   ├─ 请求失败（重放预算尽／被中止）→ Settled{Failed}
   └─ 显式打断 或 被抢占 → Voided（generation++，租约失效；残值保留 C9）
每个 Turn 恰好一个终态（I-T4）
```

**挂起态的两族出口必须分开写（v1.1 的 P0 修订）**：

- **确认卡族（goal/plan/resolution）**：`Suspended ──[用户决策]──→ Settled{Resolved}`，随后由**新 Turn** 继续（C1「下一句由搭档开口」＋C13）。依据 `00 §3.4`：用户决策后模型**重新做**，不是恢复挂起前的动作——决策改变状态，动作跟随状态重新生成。
- **授权面（approval）：不套用上式。** 批复的领域语义是"同一条记录被二次执行"——凭窗内 `requestId` 恢复**同一轮**的推进（`Suspended → Running`，原动作续跑）。这是 `00 §3.4` ＋ ADR-017 裁定 4（`argsFingerprint` 等值必同一动作）的既有裁决，**本模型只引用不重述**。v1-draft 把批复写成"新轮"，同时撞三处一致反对：I-T1（Suspended 未终态＋新 Running＝两个非终态轮）、I-T9（有活 pending 却准入）、ADR-019 D2 原句「D4 直送＝执行已批准动作、不新增轮」。
- 窗内**未决**请求跨轮的去向由 I-T10 承载。

**要点三条**：

- **续链不是新轮**：自推进、工具链多步、强制推进（ProgressGuarantee `require-advance`／`require-action`）全部是**同 Turn 内的 Step**。此前把它们当"另一条链"处理，正是"两套引擎互相抢占"的语病根源。
- **Voided 不撤销已完成**：残值（已写文件、已产出内容、已跑验证）保留可查（C9）；回滚是独立事件（快照回滚），不得混入作废语义。
- **busy 是派生量不是字段**：`busy ≡ ∃ Turn ∈ {Running}`（I-T5）——因此终态不需要"释放 busy"这个动作（v1.1 从 I-T4 删该语：派生量无需释放）。

## 5. Intent 与准入（G3 的答案）

```
Intent {
  payload: Text | CardEcho | SystemTrigger
  source:  'user-input' | 'decision-followup' | 'nudge-progress'
         | 'nudge-reconcile' | 'recovery-interrupt'
  binding?: DecisionAnswer {kind, instanceId}   // ADR-015 答复携带
  //  授权批复不进 Intent 通道：它经 approvalDecided 写窗内记录（ADR-017 四入口的单一收敛函数），
  //  其驱动效果＝同轮续跑（§4 授权面出口），不是准入一个新轮。
  //  卡片回声也不单独成条 Intent（F4）：它作为 decision-followup 的呈现标记折入。
}

submitIntent(intent) → AdmissionResult
  AdmittedNow(turnId)      // 立即成轮
| Queued(position)         // 排队至下一个「回合边界」（V1 唯一非即时终）
| Rejected(reason)         // 有痕拒绝——仅对内意图；对用户输入永不（C3／C13a）
| Folded(turnId)           // 折入现役轮＝C7「转向」——V1.5
| DerivedExecution(turnId) // 派生为有身份的子执行——V2（I-T16）
```

**「回合边界」是本模型的唯一定义词**（引 §4.5 C13，不另释）：现役轮终态、作废、或现役轮处于可让位的挂起态时才算边界——v1-draft 的"到边界再走准入"与 `02 §4.12`「当前回合收口后自动转发」是同一义务的两种词，现收敛为一个。

**来源与准入的对应（V1 射程）**：

| source                              | V1 准入默认                                                                                                       | 说明                                                                                                                                                   |
| ----------------------------------- | ----------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `user-input`                        | 有 Running 轮 → `Queued`；无 Running 轮且无活 pending → `AdmittedNow`；有活 pending（槽被占）→ 按 I-T9 **不准入** | **待授权期（因授权而 Suspended）用户打字＝文本批准入口（ADR-017 四入口之一）或补充信息（§4.5 C2），不产新轮**——v1-draft 写成 `AdmittedNow` 是 P0，已改 |
| `decision-followup`                 | `AdmittedNow`                                                                                                     | 确认卡落定后的搭档自述轮；无用户气泡（C1）。**卡片点击只产这一条 Intent**（F4 裁决：回声作为呈现标记折入，不产第二条——一次交互至多一个驱动输入，I-T7） |
| `nudge-progress`／`nudge-reconcile` | `AdmittedNow`（须当前无 Running）＋**必附披露条**（C4）                                                           | 催推进／对账引导                                                                                                                                       |
| `recovery-interrupt`                | 先 `Void` 现役轮，再 `AdmittedNow`                                                                                | 显式恢复打断（ADR-013）——唯一合法的抢占发起方                                                                                                          |

**抢占**（先例：Codex `abort_all_tasks(Replaced)` 在 `start_task` 之前同函数内）：`Void(现役轮) → AdmittedNow(新 Intent)` 是**仲裁点内的一个串行步骤**（I-T13），`generation++` 同步生效。**禁止**任何形式的发起方自行宣告作废。

## 6. 身份 doctrine（四轨正交；F2／F3＝已裁）

| 身份                    | 语义单位           | 签发者                                    | 单调性来源                                    | 消费方                                 |
| ----------------------- | ------------------ | ----------------------------------------- | --------------------------------------------- | -------------------------------------- |
| **turnId**              | 一次开口           | 仲裁器（准入成轮的**唯一** ++ 点）        | I-T3；且 **turnId 即准入全序的序数**（I-T13） | 租约、Timeline 关联、归属取证、a13/a14 |
| **generation**          | 同一轮的第几代资格 | 作废动作 `Void`                           | 单调递增，CAS 比较                            | 每个 Step 前的租约复核                 |
| **decisionInstanceSeq** | 决策点**实例**     | `setPending`（ADR-015，不动）             | kind／结构签名变化才 +1                       | 答复寻址与 stale 门                    |
| **requestId**           | 授权请求记录       | main `needApproval` 分支（ADR-017，不动） | 跨进程跨重启唯一                              | 执行核验、journal 对账                 |

四轨回答四个不同的问题：_哪一轮_／_这轮还有效吗_／_答复打的是哪张卡的哪一次呈现_／_批准的是窗里哪一条_。**领域评审 R3「身份 doctrine 分裂」的病根不是有多套身份，而是缺第一轨**——于是渲染层私有游标 `sid` 长期代行 turnId＋generation 双职：一个 UI 游标同时是取消令牌，正是"发起权分散"的实现形态。

- **F2（已裁）**：`turnId`/`generation` 由领域签发后成为**唯一**轮次资格来源；渲染层游标**退役为纯呈现投影**（更名，不删——消息渲染仍需游标）。判据可机验：**「不承载裁决」＝其值不得进入任何准入或 stale 判定路径**。跨重启：`turnId` 续号取持久会话内最大值，`generation` 随新轮重置为 1——与 ADR-017 的 requestId「跨进程跨重启唯一」同理，不复用、不回拨。
- **F3（已裁）**：stale 判定**不复合化**——保持 ADR-015 的单一身份门（`kind + instanceId` 归决策点寻址，`turnId` 归轮次归属）。复合看似更严格，实为**让一个门同时查两件不同的事**，并把轮次耦合进决策点寻址（新增故障面，且需重设计 `restorePending` 补水路径）。单源化的正解是**每个判定只有一个权威输入**，不是把所有身份叠在一起比。

| **I-T16** | **新增（V2 射程）**：每个**回合序列**至多一个非终态 Turn；派生子执行是**独立序列**、自有租约——**I-T1 是它在 V1 的投影**（V1 内会话＝单一序列）                                                                               | ADR-019 Decision 2／§4.5 C13                        | V2 放开并发时把 I-T1 读成"会话级"而判自家违规                                                                             |

**与唯一措辞源的边界（防侵占）**：I-T9 与 §4 授权面两处**只引用** `00 §3.2`／`00 §3.4`（不变量 1 唯一措辞源，ADR-015 #8），不重述、不改写、不与之并列另立。本模型新增的是"轮次"这一维度，不是第二条 PENDING 语义——**「槽只有一个」说的仍是 pending 槽，与本模型的「至多一个非终态轮」是两件事**（前者管等人，后者管谁在推进），落位时须原文写明，禁止互相吞并。

## 8. 域归属卡（ADR-016 规则 1——逐概念三问）

| 概念                             | 权威域                                                                                                                                                                                 | 为何必须在此层                                                                           | 移除后谁兜底                                                                             |
| -------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| Turn（实体）                     | **Conversation BC**                                                                                                                                                                    | 推进决策与轮次资格是"能不能动"的一半（另一半是 pending）；判据 `00 §2` 判定表第一行      | 无人兜底——发起权退回调用点即"抢"，C13 无从谈起                                           |
| Step                             | Conversation（领域记录）／Gateway（字节事实）                                                                                                                                          | 一次往返的**决策**在 Conversation，**执行字节**在 Gateway 通用域                         | Gateway 已有请求事实；缺的是"它属于哪一轮"的归属                                         |
| DriverLease（turnId+generation） | **Conversation 持权威**，执行载体（渲染层进程）持**投影副本**并逐点复核                                                                                                                | 资格判定是领域规则，载体只能服从；与 ADR-017「裁决在 main、呈现投影在 renderer」同构分层 | 无领域持有＝取消令牌退化为 UI 游标（现状病根）                                           |
| QueuedIntent 队列                | **Conversation BC**                                                                                                                                                                    | 排队是会话级待决内容，跨呈现存续（C3 的撤回/编辑/重排需持久）                            | 现由渲染层私有数组承载——本模型升格为领域概念，数组降为**投影副本**（与 F2 游标同款条款） |
| Intent／AdmissionResult          | Conversation BC                                                                                                                                                                        | 待准入的输入与其裁决，都是推进决策                                                       | 无                                                                                       |
| turnId／generation 持久化        | Conversation BC（随会话存档），Timeline 记副本                                                                                                                                         | 续号需跨重启单调源；Timeline 是事件真相源但**不是**资格来源                              | `00 §3.2` 与 Problem 快照已有同构做法                                                    |
| **busy**                         | **Conversation 的派生量**（I-T5 唯一定义式）；呈现层与 UAT 只投影                                                                                                                      | 把 ADR-013 的枚举表与 `02 §4.12` 的"同源"义务收敛为一个定义式                            | 继续镜像＝族红以新签名复活（ADR-019 D3）                                                 |

## 9. 现行实现与模型的冲突登记（参照，不是约束）

以下与 §1–§8 冲突，一律视为**待推翻重构**项，模型不因它们"改起来难"而让路：

1. 26 个调用点各自开轮（发起权分散）⇒ 违反 I-T1／I-T3。
2. 私有 UI 游标兼作取消令牌、靠轮询迟滞自杀、过期窗内仍写会话状态 ⇒ 违反 I-T2（且是 `04 §3.2:412`「结构性非拦截」的偏离）。
3. 续链与工具链被当作独立链处理 ⇒ 违反 §4「续链不是新轮」。
4. `working`/`modelBusy` 靠 effect 镜像维护＋散点手动补清 ⇒ 违反 I-T5（ADR-013 同源义务）。
5. 排队意图住在渲染层私有数组、drain 挂在链尾 finally（任意链、含孤儿链）⇒ 违反 I-T6／I-T14 与 §4.5 C3。
6. 零产出轮不 finalize、失败轮原地抹气泡、网关暗数重试 ⇒ 违反 I-T4／I-T11 与 C10。
7. 措辞词表在消费时刻判 reject（S7-1 族根因）⇒ 违反 §5（准入按 source，不按措辞）与 C2。
8. Timeline 无轮次维度（`assistant_start` 载荷仅 `forceTool`）⇒ 违反 I-T8。

> 勘误一条（属文档事实错误，非模型冲突）：`02 §4.12` 与 ADR-013 引用的停止按钮选择器 `.nf-chat__stop` 不存在，真名 `.nf-chat__send--stop`——落位批一并改（p000157）。

## 10. F1–F4 裁决（准绳＝单源化；来源＝产品负责人授权自裁）

| #      | 裁决                                                                                                                        | 单源化理由                                                                                    | 若不如此的后果                                           |
| ------ | --------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------- | -------------------------------------------------------- |
| **F1** | Turn＝Conversation 聚合内**实体**（非聚合根）                                                                               | 轮次资格与 pending 同宿主同事务边界；独立聚合根会另立一套与 Problem/task-log 竞争的存档真相源 | 双真相源＋双聚合同步开销，且与 `04 §1.1:14` 既有选型冲突 |
| **F2** | `turnId`/`generation` 为**唯一**资格来源；渲染层游标退役为纯呈现投影（更名不删，判据＝其值不进入任何准入或 stale 判定路径） | 取消令牌只能有一个来源；现状病根正是 UI 游标代行双职                                          | 游标保留现职＝模型被架空，C13 仍无持有人                 |
| **F3** | stale 判定**不复合化**（`kind+instanceId` 管决策点寻址，`turnId` 管轮次归属）                                               | 单源＝每个判定只有一个权威输入；把四套身份叠进一个门是**制造第二耦合**，不是收紧              | 需重设计 `restorePending` 补水路径，决策点寻址被轮次污染 |
| **F4** | 卡片点击只产**一条** `decision-followup` Intent，回声作为其呈现标记折入                                                     | 一次交互至多一个驱动输入（I-T7）；若既产回声 Intent 又产自述轮＝同一决策两个发起者            | 双发射器（β 案根因）以新形态复活                         |
