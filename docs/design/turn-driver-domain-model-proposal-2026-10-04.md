## 1. 缺的是什么对象

产品层已把"谁在什么时候开口"写成 C1–C13（ADR-018 accepted），其中 **C13 单一推进点**是本提案的锚。领域侧没有承载它的东西：

| 代号   | 缺口                                                                                          | 现状表述能力                                                             |
| ------ | --------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------ |
| **G1** | 没有 **Turn（模型轮）** 这一等公民——领域里只有 Task（目标推进单元）、Message、PendingDecision | 「上一轮已经作废了，为什么它还在改状态」这句话**无法成立**，因为没有主语 |
| **G2** | 没有**驱动权**的归属——"谁有资格发起下一个模型往返"无人持有                                    | C13 是产品承诺，领域侧无对应物＝**承诺没有持有人**                       |
| **G3** | 没有 **TurnInput（轮输入）** 值对象——`send(text, opts)` 是调用形态，不是领域概念              | 「排队／打断／折入／拒绝」四态（C7）无法被讨论，只能被 if-else           |

共同后果：**轮次归属在产品里可被要求、在领域里不可被表达、在实现里只能被抢**（谁先 ++ 谁说话）。

> **精确说法（v1.2 校正）**：不是领域"从没用过轮这个字"，而是**这个字被当形容词用了四处、却没有本体**——`00 §4`「上一轮工具失败」、`02 §4.2`「本轮自推进」、`04 §3.1` `proposed?: // 本轮输出结构化提议`、`04 §3.6`「本轮待执行动作」；更有一个**已命名的值对象 `TurnProgress`（"单轮进展"）**，其字段实际判定的是**一次往返**（加 Task 级累积量）。隐性概念比缺失更危险：人人以为已有定义。⇒ 本次进化同时是**补本体**与**收词汇**。

## 2. 通用语言（ubiquitous language）

| 术语                     | 定义                                                                                                                                      | 用户可见对应                                 |
| ------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------- |
| **模型轮 Turn**          | 搭档的一次完整"开口"：自准入起至收口或作废止，其间由唯一驱动消费者推进                                                                    | 一条搭档气泡（含多段产出与工具卡）；"处理中" |
| **往返 Round**           | Turn 内的一次模型往返——一次 Gateway 往返及其触发的工具执行（领域侧只记**归属与终态**，字节归 Gateway、动作事实归 ToolRegistry/Workspace） | 气泡内的续写、工具执行条                     |
| **驱动消费者 Driver**    | 持有租约、有权发起下一个 Round 的执行体                                                                                                   | 不可见（领域内部）                           |
| **驱动租约 DriverLease** | `{turnId, generation}`——推进资格；`generation` 递增即整体作废                                                                             | 不可见                                       |
| **轮输入 TurnInput**     | 待准入的输入：载荷＋来源标记＋归属绑定（**≠ 决策点"确认意图"**，见 §6 词汇收口）                                                          | 用户气泡、卡片点击、系统触发                 |
| **准入 Admission**       | 仲裁点对 TurnInput 的裁决（五态，§5）                                                                                                     | 排队中徽标、失败态、重提示                   |
| **作废 Void**            | 使某 Turn 的租约失效的单点动作（显式打断或抢占）                                                                                          | 停止按钮生效；被打断轮留下残值（C9）         |
| **收口 Settle**          | Turn 的终局（五终态，§4）                                                                                                                 | 气泡定格、"处理中"消失                       |

**粒度阶梯（词汇单源化后的唯一分层）**：`Task ⊃ Turn ⊃ Round ⊃ 动作（工具/消息级）`——Timeline 的记录单位**仍叫"步骤"**（其"全步骤统一记录"职责不变，`03`／`02 §4.8`），它在轮次维度上**挂靠** `turnId`；本模型不接管事件排序（见 §6）。

**关系约束**：`Task 1—N Turn`（I-T12）；`Turn 1—N Round`（I-T11）；`Turn 0—1 活动决策点实例`（I-T15）；`TurnInput N—1 Turn`。

## 3. 本体判定：Turn 落在哪一层（F1＝已裁）

**判定：Turn 是 Conversation 聚合内的实体（非聚合根），与会话级 PENDING 同宿主。**

判据（`00 §2` BC 职责边界判定表）：

1. 「谁推进下一轮」是**推进决策**，推进决策归 Conversation（判定表第一行：Conversation 决定「能不能动」）；
2. 轮次资格与会话级单一 PENDING 必须在**同一事务边界**内检查——`00 §3.2 要点 2` 的"用户决策是下一个状态的唯一输入"，其"下一个状态"若无轮次身份，就是无主语的真命题；
3. 与既有选型一致：`04 §1.1:14` 已定 Task 与 pending「结构合并」以免双聚合同步开销。

**明确否掉**：Turn 作聚合根（无独立事务边界需求，且恢复/持久化会被迫另立一套与 Problem/task-log 竞争的存档）；Turn 作 Message 属性（把资格挂在呈现上＝`00 §3.2 要点 5` 已裁的"UI 现象代理领域状态"）。

**层级名统一（互审 P1）**：**容器＝Conversation**；Task 是被 Turn 绑定的**引用**（I-T12），`Task 1—N Turn` 是**关联**而非包含——不在图上再画一层，避免与 `04 §1.1:14` 的结构合并选型叠出第三套父写关系。

## 4. Turn 生命周期

```
TurnInput ──[submitTurnInput 仲裁（串行 I-T13）]──→ 准入裁决（§5）
   ├ 立即成轮 ─→ Turn(turnId=++唯一源, generation=1) : Running
   └ 排队      ─→ QueuedInput（会话队列；可撤回/编辑/重排＝C3）→ 到「回合边界」再走准入
Running: 每个 Round 前复核租约（generation 等值）
   ├─ 产出推进（工具执行 / 结构化提议 / 证据 / 提问）→ 继续 Running（新增 Round）
   ├─ 请求瞬态失败且有重放预算 → 同 Turn 新增 Round（I-T11：不新开轮、不违终态唯一）
   ├─ 决策点弹出（deriveDecisionPoint 非 none）→ Suspended（等人——不计 busy，ADR-013）
   ├─ 无可进一步推进且非挂起 → Settled{Completed}
   ├─ 零产出（请求 done 而无内容）→ Settled{Empty}
   ├─ 请求失败（重放预算尽／被中止）→ Settled{Failed}
   └─ 显式打断 或 被抢占 → Voided（generation++，租约失效；残值保留 C9）
每个 Turn 恰好一个终态（I-T4）
```

**挂起态的三种出口——必须逐族分写（v1.2 的核心修正）**：

| 出口                                                               | 事实                 | 领域动作                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      | 依据                                                                                                                                        |
| ------------------------------------------------------------------ | -------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| **① 确认卡落定**（goal/plan/resolution 族）                        | 用户对决策点做主     | `Suspended → Settled{Resolved}`，随后**新 Turn** 由搭档开口（C1/C13）；**不恢复挂起前的动作**（`00 §3.4`：决策改变状态，动作跟随状态重新生成）                                                                                                                                                                                                                                                                                                                                                                                                                                                | `00 §3.4`＋ADR-018 C1                                                                                                                       |
| **② 授权批复**（窗内记录被允许／规则命中）                         | 同一条记录被二次执行 | `Suspended → Running`，**同轮续跑**——不套①的"不留复活"律（那是确认卡族的规则）                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                | `00 §3.4`＋ADR-017 裁定 4（`argsFingerprint` 等值必同一动作）                                                                               |
| **③ 待授权期用户发**新**指令**（非批准语）**＝F7 已裁 D 降序重排** | 焦点换人，不是决定   | **两步串行，缺一即死锁**：①**移出焦点**——窗内该未决记录 `pending → queued`（**决定轴不变：不 approved、不 denied、不 expired、不 superseded**，ADR-017 的可决集 `DecidableApprovalState={queued,pending}` 本就含二级），槽随之释放（`windowResolved`），对话流留**换焦回执**（"这条先放一放，测完再问你要不要写"级——C3 按条可见、C13a 有痕）；②**再准入**——原轮 `Settled{Superseded}`（I-T17），新指令 `AdmittedNow`（不排队＝`02 §4.12`＋ADR-013 裁定 2 的"直接处理"）；③该轮终态且无活决策点时 `drainQueued` 把它升回 `pending`，**授权卡重新呈现，用户仍是决定者**（ADR-017 存续可决不损） | 焦点轴可动、决定轴不可代答；依据 `00 §3.2 要点 5`（冻结判据恒为槽）＋`conversationState.ts:88/443`（queued 本就可决、drainQueued 已在重算） |

> **引证更正（自我否证）**：v1.1 把②③压成一句"待授权期打字＝批准入口或补充信息，不产新轮"，并引 ADR-019 Decision 2「D4 直送＝执行已批准动作、不新增轮」作第三源——该括注确是我落笔（已随 ADR-019 accepted），但它说的是**出口②（批复续跑）**，被我拿去否证**出口③（新指令成轮）**＝张冠李戴；`02 §4.12` 的原文只说"可直接处理"，**从未裁定落在哪个轮**——这层未裁现列为待裁项 F7（§10 末）。互审两轴各打中一半（不变量轴：I-T9 会否证待授权直送；单源化轴：批复不该被写成新轮），合起来才看清是**三种情形而非一种**。ADR-019 的括注已就地更正。
>
> **I-T9 随之改写**：PENDING 冻结的是**执行**（工具不放行、模型动作无效），不是**准入**——准入侧的规则由 `02 §4.12` 投递时机承载。v1.1 把 I-T9 写成"不准入新轮"正是误伤③的根因。

**要点四条**：**续链不是新轮**（自推进／工具链多步／强制推进都是同 Turn 内的 Round）；**批复不是新轮**（②同轮续跑）；**Voided／Superseded 不撤销已完成**（残值保留可查 C9，回滚是另一件事）；**busy 是派生量**（I-T5，终态无需"释放"）。

## 5. TurnInput 与准入（G3 的答案）

```
TurnInput {
  payload: Text | CardEcho | SystemTrigger
  source:  'user-input' | 'decision-followup' | 'nudge-progress'
         | 'nudge-reconcile' | 'recovery-interrupt'
  role:    'instruction' | 'supplement'   // 新指令 vs 补充信息（C2/C2b）——用角色标记，不新增第六个准入态
  binding?: DecisionAnswer {kind, instanceId}   // ADR-015 答复携带
  //  授权批复不进 TurnInput 通道：它经 approvalDecided 写窗内记录（ADR-017 四入口的单一收敛函数），
  //  其驱动效果＝同轮续跑（§4 出口②）。卡片回声也不单独成条（F4）：折入 decision-followup 的呈现标记。
}

submitTurnInput(input) → AdmissionResult
  AdmittedNow(turnId)      // 立即成轮（含 §4 出口③的取代式成轮）
| Queued(position, role)   // 排队至下一个「回合边界」（V1 唯一非即时终）；role='supplement' 者按 C2b 携带进下一轮
| Rejected(reason)         // 有痕拒绝——仅对内意图；对用户输入永不（C3／C13a）
| Folded(turnId)           // 折入现役轮＝C7「转向」——V1.5
| DerivedExecution(turnId) // 派生为有身份的子执行——V2（I-T16）
```

**「回合边界」是本模型的唯一定义词**（引 §4.5 C13，不另释）：现役轮进入终态（含 Superseded）、被作废、或处于可让位的挂起态之时；**排队衔接义务以该词为准**，不再使用"收口后自动转发"的并行说法。

**来源与准入的对应（V1 射程）**：

| source                              | V1 准入默认                                                                                                                                                                                                                                                                                                     | 说明                                                                                                                                     |
| ----------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| `user-input`                        | 有 Running 轮 → `Queued`；无 Running 轮且无活 pending → `AdmittedNow`；**因确认卡而 Suspended** → `Queued`（按 C2 判为 `role='supplement'`，不成轮）；**因授权而 Suspended** → §4 出口③（**先把该未决记录移出焦点 pending→queued 并释放槽**，再原轮 Superseded ＋ `AdmittedNow`；决定轴不写值，卡待槽空时重弹） | 命中批准词且窗内恰一可决者**不产 TurnInput**——走 `approvalDecided`（§4 出口②），属 ADR-017 四入口，不归本模型                            |
| `decision-followup`                 | `AdmittedNow`                                                                                                                                                                                                                                                                                                   | 确认卡落定后的搭档自述轮；无用户气泡（C1）。**卡片点击只产这一条 TurnInput**（F4：回声作为呈现标记折入——一次交互至多一个驱动输入，I-T7） |
| `nudge-progress`／`nudge-reconcile` | `AdmittedNow`（须无 Running）＋**必附披露条**（C4）                                                                                                                                                                                                                                                             | 催推进／对账引导。**触发条件仍是缺口 G7**——本批只给来源与准入默认，不发明阈值                                                            |
| `recovery-interrupt`                | 先 `Void` 现役轮，再 `AdmittedNow`                                                                                                                                                                                                                                                                              | 显式恢复打断（ADR-013）——唯一合法的抢占发起方                                                                                            |

**抢占**（先例：Codex `abort_all_tasks(Replaced)` 在 `start_task` 之前同函数内）：`Void/终态化现役轮 → AdmittedNow(新输入)` 是**仲裁点内的一个串行步骤**（I-T13），`generation++` 同步生效。**禁止**发起方自行宣告作废。

## 6. 身份 doctrine（四轨正交；F2／F3 已裁）

| 身份                    | 语义单位           | 签发者                                    | 单调性来源                                   | 消费方                                 |
| ----------------------- | ------------------ | ----------------------------------------- | -------------------------------------------- | -------------------------------------- |
| **turnId**              | 一次开口           | 仲裁器（准入成轮的**唯一** ++ 点）        | I-T3；**准入归属的身份**（**不充当排序键**） | 租约、Timeline 关联、归属取证、a13/a14 |
| **generation**          | 同一轮的第几代资格 | 作废动作 `Void`                           | 单调递增，CAS 比较                           | 每个 Round 前的租约复核                |
| **decisionInstanceSeq** | 决策点**实例**     | `setPending`（ADR-015，不动）             | kind／结构签名变化才 +1                      | 答复寻址与 stale 门                    |
| **requestId**           | 授权请求记录       | main `needApproval` 分支（ADR-017，不动） | 跨进程跨重启唯一                             | 执行核验、journal 对账                 |

四轨回答四个不同的问题：_哪一轮_／_这轮还有效吗_／_答复打的是哪张卡的哪一次呈现_／_批准的是窗里哪一条_。**R3「身份 doctrine 分裂」的病根不是有多套身份，而是缺第一轨**——于是渲染层私有游标 `sid` 长期代行 turnId＋generation 双职。

**「两序不互推」（v1.2 新增，纠正 v1.1 的"turnId 即序数"）**：`02 §4.8`＋ADR-016 已裁「序号与排序归 **Timeline 的 `seq`**，领域记录不带序号身份」。本模型不得复活那个被溶解的写法——分工钉死：**事件与呈现的排序＝`seq` 的职责；`turnId` 只回答归属**；两者互不推导（`seq` 单调即可，不要求与 turnId 对齐；turnId 有洞（被拒的输入不成轮）也不影响 `seq` 连续）。

- **F2（已裁）**：`turnId`/`generation` 为**唯一**轮次资格来源；渲染层游标退役为纯呈现投影（更名，不删），判据可机验＝**其值不得进入任何准入或 stale 判定路径**。跨重启：`turnId` 取持久会话内最大值续号，`generation` 随新轮重置为 1，不复用、不回拨。
- **F3（已裁）**：stale 判定**不复合化**（`kind + instanceId` 归决策点寻址，`turnId` 归轮次归属）——单源的正解是**每个判定只有一个权威输入**，不是把所有身份叠在一起比。

**词汇收口两条（F5／F6）**：

- **F5 Round**：轮内一次往返原名 Step，与 `03`／`02 §4.8` Session Timeline BC 的**记录单位"步骤"**（更细粒度，一次动作一条）撞词——两个粒度同词＝第二权威。改称 **Round**；既有值对象 **`TurnProgress` 改名 `RoundProgress`**（其字段实际判定往返粒度，其中 `hasPlannedFiles`/`remainingCount` 属 Task 级）。

### F7 已裁（2026-10-04 用户认可）＝选项 D「降序重排」

**裁定结果**：待授权期用户发新指令 ＝ **焦点轴换人**，不是决定轴作答。落点见 §4 出口③与 I-T17/I-T18；`00 §3.2 要点 2`（不变量 1 的冻结射程）**一字未改**，C 选项失去存在理由。

四选项为何只有 D 成立（同一条场景走四遍的结论）：

| 选项                       | 本质动作                                                              | 判决                                                                                                                 |
| -------------------------- | --------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| A 解算成 `superseded` 终态 | 用**决定轴的值**解决**焦点轴的问题**                                  | ❌ 系统替用户"决定"了一条他没决定的东西——直接撞上 C2 精神与我们刚钉的不对称理由（措辞匹配只做 allow、永不触发 deny） |
| B 同轮续跑、不释放槽       | 承认焦点不换却想推进                                                  | ❌ **唯一会真死锁**的一个：用户不点卡，新指令永远动不了（C2a 死锁族第三次复发）                                      |
| C 冻结粒度收窄到单条记录   | 改不变量 1 射程去救焦点问题                                           | ❌ 范畴错误，且代价最大（动唯一措辞源）——D 出现后无必要                                                              |
| **D 降序重排**（**已采**） | 只在焦点轴动手：pending→queued、槽释放、推进、槽空时 drainQueued 换回 | ✅ 决定轴不损（存续可决）、C3/C13a 满足（换焦可见留痕）、不变量 1 不动                                               |

**根因升级**：D 之所以是"最小正确解"，是因为 queued/pending 本来就**不是决定态**——`conversationState.ts:88` 的 `DecidableApprovalState={queued,pending}` 说明可决性不区分二级，而 `:443` 的 `drainQueued` 每次转换都在重算它 ⇒ **它是被物化下来的派生态**。这个发现超出轮次射程，已立为缺口 **G10**（进化文档 §3D：等待项的焦点轴与优先律未本体化，五处同构各造词汇）。
