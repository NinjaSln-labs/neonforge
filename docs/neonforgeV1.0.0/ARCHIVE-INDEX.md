## 1. 为什么旧树必须停笔（不是它做错了，是它长错了形状）

旧树的问题不是"有 bug 要修"，而是**九轮修订逐层叠加、每轮只加不核**——于是同一件事有 2–4 个措辞处，彼此互斥却都还在文中：

- **北极星曾有四个互斥定义**：`07:13` 每周完成写入数／`07:30` 解决确认率（逐字"非写入"，同文件 17 行内互否）／`D0 §1.2` 表"问题关闭率＋二次委托率"／`.agents/product-marketing.md:102` 二次委托率。
- **顶层依据住在权威层之外**：`D0:11` 逐字"依据 `.scratch/neonforge-v1/project-alignment.md`（用户裁决终版）"；`00-product-reference:4` 把现行竞品依据指向本机 `F:\neonforge-competitors\…`。
- **原则与"柱"数被复述改过**：`§1.2` 是六条原则，我在这几天的文里通篇写"四柱"——**复述时改动了事实，再把改动过的事实当证据继续推**（ADR-025 P7）。同批还有一次**假发现**：我断言映射表缺第 6 行并动手补行，核对原文证实该行一直在（误因用行首形状 grep 推断缺行）。
- **概念账本**：五路清点 161 条 ⇒ **已详设 49／半成品 61／需扩展 15／纯呈现 6／空头 3**；面向用户的可验收承诺 11 条里 **3 条全空头＋2 条半空头**。旧树给出的"已经完成"的读感与这个数字不符。

⇒ 继续在旧树上改词，只会新增第三十处补丁层。**重构必须是新树，旧树必须是底稿。**

## 3. 新树的三条硬纪律（写在这里，因为它约束此后所有笔）

1. **不回写旧树**。旧文的错、旧文的假行、旧文的补丁注，**一律留在原样**。要更正 → 新树里写新的；旧树只被引用，且引用必须带 `@be6e299`。
2. **新树里每个名词落笔即过两问**：①**移除后谁兜底**②**它属于哪根轴**（等待／推进／焦点／授权／作用域／任务／产物／证据／呈现）。答不出的，只能以 `⏳需详设 H-xxx` 存在，**不得写成陈述句**——半成品的显式标记就是本次重构与上一次的分界。
3. **感觉词未成谓词前，不得进入不变量条文**（`假推进`／`高危`／`越界`／`沙箱`／`同签名`／`仓内`）。这五条里四条是我自己这两天用过却没定义的词。
