# 安全/可用性事件响应 Runbook（初版，2026-11-19）

> 性质：内部处置流程草稿，不是法律/合规意见；未做真实演练。
> 关联：`ai-risk-register-2026-11-19.md`、`threat-model-2026-11-19.md`、ADR-012/015/016。

## 1. 严重级别

| 级别  | 判定                                                                | 响应目标                       |
| ----- | ------------------------------------------------------------------- | ------------------------------ |
| SEV-1 | 凭据泄漏、未授权外发/删除、注入导致真实副作用、发布包被篡改         | 立即止血；负责人 15 分钟内响应 |
| SEV-2 | 高权限工具误执行、审批链路失效、Provider 长时间不可用、项目文件损坏 | 1 小时内响应                   |
| SEV-3 | 单任务失败、可回滚的写入错误、评估/文档错误陈述                     | 当日响应                       |
| SEV-4 | 体验退化、无数据影响的告警                                          | 下一工作日                     |

## 2. 角色

- **事件负责人**：统一决策与对外口径。
- **工程处置**：停止任务、隔离进程/容器、恢复快照。
- **安全取证**：保留日志、确认范围与凭据暴露。
- **产品沟通**：向用户说明影响与补救，不承诺未验证结论。
- 单一角色可兼任，但 SEV-1 需至少两人复核。

## 3. 首步处置

1. **止血**：暂停 Agent 循环/工具执行；必要时停止应用或撤销授权规则；评估容器立即 `docker stop`。
2. **隔离**：断外网检索/Provider（如疑泄漏）；移除可疑扩展/MCP。
3. **取证**：保留 `neonforge-gate.jsonl`、审批审计、timeline 事件、`.nf-bak` 快照、适配器/容器日志；不要先清理现场。
4. **范围判定**：确认是否涉及项目根外路径、凭据、外部副作用（邮件/共享/日历）、发布产物。
5. **恢复**：用快照回滚被改文件；重新生成凭据（若泄漏）；验证审批规则与计划清单。
6. **复盘**：24 小时内填写复盘模板；更新风险登记册与威胁模型。

## 4. 常见场景

| 场景               | 立即动作                                             | 恢复/验证                                   |
| ------------------ | ---------------------------------------------------- | ------------------------------------------- |
| Key 泄漏           | 撤销/轮换 Key；检查日志与仓库历史；停止相关 Provider | 重新配置环境变量/本机凭据文件；确认无新调用 |
| 未授权写入/删除    | 停止 Agent；定位工具调用与审批来源                   | 用 `.nf-bak` 回滚；核对计划清单与授权审计   |
| 注入导致外部副作用 | 停止外发工具；保留注入内容与调用链                   | 通知受影响方；收紧 `ask`/`deny` 规则；复测  |
| 扩展/MCP 扩权      | 禁用扩展；撤销注册                                   | 审计权限清单；重新安装可信版本              |
| Provider 故障      | 切换 Provider/模型；保留已完成结果                   | 验证超时/退避；记录能力卡模型差异           |
| 发布包完整性       | 下架产物；校验签名/哈希                              | 重新构建与签名；发布说明                    |

## 5. 证据清单

- 时间线：用户操作、模型请求、工具调用、审批裁决、执行结果。
- 授权：规则快照、`approvalSource`（user/auto/delegate）、拒绝记忆。
- 文件：快照路径、回滚结果、diff。
- 评估：容器镜像摘要、能力卡、原始日志（敏感内容脱敏后保存）。
- 凭据：只记录“已轮换/未轮换”，不在事件单写值。

## 6. 演练计划

- 每季度一次桌面演练（tabletop）：模拟 Key 泄漏、未授权删除、注入外发。
- 每半年一次恢复演练：从快照回滚 + 重新配置 Provider + 验证审批边界。
- 演练记录：时间、场景、发现、改进项、负责人；未完成前不得声称“已演练”。

## 7. 复盘模板

```text
事件 ID / 级别 / 时间线
影响范围（数据/凭据/外部副作用/发布）
根因（直接原因 / 系统性原因）
现有控制为何未阻止
处置是否及时、取证是否完整
改进项（负责人/截止日期）
风险登记册与威胁模型更新项
对外沟通口径
```
