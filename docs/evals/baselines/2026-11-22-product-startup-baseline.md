# 证据卡：NeonForge 产品级启动性能基线（2026-11-22）

> 本卡是**产品级性能基线**，不是外部 Agent 能力基准，也不是 SLO 达成声明。
> 测量对象是真实 Electron 产品（主进程 + preload + 渲染器），在 WSL2 + `xvfb` 无头软件渲染环境运行；结论只适用于同环境纵向比较。

## 测量方法

- 独立运行器 `evals/perf/run-startup-benchmark.cjs` 启动真实 `apps/desktop/dist/main/main.js`；`electron-startup.cjs` 在 Electron 主进程中记录阶段时间，完成后输出一行 `NF_PERF_RESULT` JSON 并退出。
- 无显示环境自动使用 `xvfb-run`；所有运行固定软件渲染参数，保证同机可比。
- 冷启动隔离应用数据；不清理操作系统文件缓存，因此“冷”只是应用层冷启动，不是首次安装。
- 首屏判定：渲染器出现 `.nf-start`（假 Key 使 App 走启动页）或 `.nf-config`；本批全部为 `.nf-start`。
- IPC：渲染器通过 `window.neonforge` 连续调用 `config.hasKey` / `budget.get` 各 30 次（先预热 3 次），记录单次往返耗时。
- 内存：`app.getAppMetrics()` 的 working set（含共享页，**不可相加当作唯一内存**）+ Linux `/proc/<pid>/smaps_rollup` 的 PSS 逐进程求和；另记录主进程 RSS 与渲染器 JS heap。

## 结果：启动阶段（毫秒，相对 Electron 主进程入口）

| 阶段                           | 冷启动 p50 | 冷启动 p95 | 热启动 p50 | 热启动 p95 |
| ------------------------------ | ---------: | ---------: | ---------: | ---------: |
| `app_ready`（`app.whenReady`） |      155.1 |      178.5 |       88.0 |       94.0 |
| `window_created`               |      206.8 |      232.5 |      142.6 |      157.3 |
| `did_finish_load`              |      413.6 |      449.9 |      344.2 |      373.2 |
| **`ready_screen`（首屏可见）** |  **440.0** |  **464.1** |  **361.8** |  **404.5** |

- 20/20 冷启动与 10/10 热启动均成功完成测量，无失败/异常。
- `wallMs`（运行器从 spawn 到进程退出，含 `xvfb-run` 与退出清理）：冷 p50 1222 / p95 1266；热 p50 1136 / p95 2939。热启动 p95 的 2939 ms 是**进程退出清理慢**的离群值（对应内部 `durationToEmit` 仍约 1.0 s），不应作为启动延迟。
- 早先构建后第一次探索性运行（未计入正式 20 次）首屏 653.5 ms；正式冷启动 p50 440 ms 已受益于操作系统文件缓存，因此不能把 440 ms 当作“首次安装”数字。

## 解释

- 在 WSL2 + xvfb 软件渲染下，NeonForge 从 Electron 主进程入口到启动页可见的 p50 为 **440 ms**（冷）/ **362 ms**（热），p95 为 **464 ms** / **405 ms**；距离 SLO 提案的 3 秒尚有余量，但这不是 macOS 目标机结论。
- 启动页 IPC 往返在亚毫秒级（本机、空载、无并发），表明 preload/IPC 收敛路径没有显著固定开销；不能据此推断工具执行或流式对话延迟。
- 空载总 PSS 约 **272 MB**（冷）/ **267 MB**（热），其中渲染器约 100 MB、Browser 约 124 MB；这是启动页基线，未覆盖项目打开、Monaco 大文件、长会话或工具执行。
- working set 合计约 516 MB 明显高于 PSS，是因为各进程共享页被重复计数；不要把 516 MB 当作唯一内存或产品“占用”。

## 限制

- **环境不代表目标平台**：WSL2 + xvfb + 软件渲染 + `--disable-gpu`；macOS/Windows 的 GPU 合成、签名、keychain 与窗口恢复路径不同。SLO 提案要求在 macOS 目标机重复 20 次，本卡未完成该要求。
- **冷启动定义有限**：每次新应用数据，但不清理 OS 文件缓存；首次安装/首次下载模型后的首跑会更高。
- **场景有限**：假 Key 进入启动页，不进入配置页、项目工作区、会话流式输出或工具执行；未测首 token、审批等待、长会话内存、任务成功率。
- **样本量**：20/10 次单机运行，p95 是粗分位数；没有置信区间或多机对比。
- **退出阶段噪声**：`wallMs` 包含进程退出清理，出现过 2.9 s 离群；阶段指标更接近启动延迟。
- **不是官方成绩或 SLO 达成**：无外部对照，不代表用户感知端到端时延。

## 安全与边界

- 仅使用假 Key 与隔离的临时用户数据；环境变量在运行前剔除敏感键；原始 JSONL/构建日志只落 `.scratch/`（不进入仓库）。
- 未上传任何会话内容、文件路径或凭据；无网络模型调用。
