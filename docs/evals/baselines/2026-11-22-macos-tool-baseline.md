## 与 WSL2 基线的对照（p95，毫秒）

| 工具     | WSL 主进程内 | macOS 主进程内 | WSL 端到端 | macOS 端到端 |

| `read`   |         9.57 |          66.86 |       8.80 |        66.70 |
| `search` |         6.87 |          65.31 |       7.90 |        85.90 |
| `write`  |        23.40 |         221.74 |      24.00 |       239.80 |
| `edit`   |        26.88 |         235.54 |      23.60 |       236.30 |
| `bash`   |        11.73 |          73.16 |      10.70 |        73.20 |

- macOS 上读/检索约 65 ms、写/编辑约 215 ms、bash 约 71 ms，约为 WSL 的 7–10 倍。
- 差值接近一个固定量级，不像 CPU 单次运算差异；更可能是 macOS 文件系统/快照/进程路径的固定开销（本卡不据此做根因断言）。
- 写/编辑仍约为读的 3 倍（写前快照 + 变更集记录），与 WSL 的结构性比例一致。
- SLO 提案面向 macOS 目标机：只读 p95 提案 ≤200 ms，本机 66.9 ms；写入 p95 提案 ≤500 ms，本机写入 239.8 ms。均低于提案，但本卡 fixture 约 3 KB、缓存热、顺序调用；**不是 SLO 达标声明**，也不能外推到大项目/冷缓存。

## 解释

- macOS 主进程与端到端两条路径都稳定（3/3 进程、0 失败），说明工具执行器与 IPC 在目标机上功能正常、无政策拦截。
- macOS 的固定开销显著高于 WSL；若后续要做性能优化，应先分清文件系统、快照、变更集和 Electron 进程路径的贡献，而不是直接改实现。
- 端到端与主进程内几乎无差，IPC 不是瓶颈；这点与 WSL 结论一致。

## 限制

- **单一机型/版本**：2018 MacBook Pro、macOS 15.8.3；不代表 Apple Silicon 或新机型。
- **fixture 很小且缓存热**：3 KB 文件、顺序调用、无并发、无大文件/冷缓存/磁盘竞争。
- **未覆盖审批卡**：`approved:true` 模拟已批准；不含授权卡显示、用户点击或 `ask`/deny/delegate 路径。
- **未覆盖网络/MCP/扩展工具**；只测 5 个核心工具。
- **有背景负载**：运行期 load average 约 1.97/1.61/1.57。
- **样本量**：每工具 90 次；p95 为粗分位数，无置信区间。
- **不覆盖跨平台等价性**：macOS 与 WSL 的计费/文件系统路径不同，不能把差异归因于单一因素。
- **不是 SLO 达成**：提案阈值面向目标机，但本卡场景有限。

## 安全与边界

- 隔离临时 fixture 与 userData；假 Key、剔除敏感环境变量；不读取真实凭据。
- 原始 JSONL 只在 Mac 与宿主 `.scratch/`（gitignored）；未上传文件路径、会话内容或凭据。
- 未调用外部模型或网络工具。
