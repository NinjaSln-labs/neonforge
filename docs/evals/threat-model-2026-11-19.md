# NeonForge 威胁模型（初版，2026-11-19）

> 范围：NeonForge 桌面 AI 工作台（Electron main/preload/renderer、ToolRegistry、Provider、Web 检索、扩展/MCP）。
> 性质：内部威胁建模，不是渗透测试报告或安全认证；未做独立红队验证。
> 关联：`ai-risk-register-2026-11-19.md`、ADR-015/016/017、`2026-11-19-neonforge-approval-boundary.md`。

## 1. 资产

| 资产 | 说明 | 主要影响 |
|------|------|----------|
| 项目文件 | 用户工作区源码、配置、产出物 | 完整性、机密性、可用性 |
| 凭据 | Provider Key、搜索 Key、MCP 凭据 | 机密性、账户滥用 |
| 会话与决策记录 | 目标/方案/授权/拒绝记忆、工具审计 | 机密性、完整性、可追责性 |
| 执行环境 | 本机 shell、进程、端口、剪贴板、浏览器 | 可用性、横向移动 |
| Provider 账户 | 模型调用额度与账单 | 财务、可用性 |
| 扩展/MCP | 第三方工具与外部服务 | 权限扩散、供应链 |
| 发布产物 | 安装包、签名、更新通道 | 完整性与用户信任 |

## 2. 信任边界

1. **renderer ↔ main**：renderer 不直接执行文件/命令；IPC 经 `ipcSchema` 校验，授权由 main 二次裁决。
2. **main ↔ 本机资源**：ToolRegistry 按风险/规则/`requiresApproval` 控制写、命令、网络与打开动作。
3. **模型/provider ↔ 工具调用**：模型输出视为不可信输入；工具参数修复不等于授权。
4. **工具/网页输出 ↔ 模型**：外部内容可携带提示注入；不因内容中的指令扩大权限。
5. **扩展/MCP ↔ ToolRegistry**：扩展工具受来源标记与权限边界约束（ADR-017）。
6. **Web 检索 ↔ 网络**：外网开关、探测门控、SSRF DNS/IP 校验、自有端点覆盖。
7. **评估 harness ↔ 产品**：评估门是 Python monkey-patch，与产品 Electron 审批链路分离。

## 3. 对手模型

- **恶意/被污染的模型或 Provider**：返回恶意工具调用、诱导越权、伪造完成声明。
- **恶意网页/工具输出**：提示注入、伪造系统消息、诱导读取或外发数据。
- **恶意扩展/MCP**：借注册工具扩权、访问未授权资源、供应链投毒。
- **本机攻击者**：读取配置/凭据、篡改项目文件、利用符号链接或路径穿越。
- **粗心/疲劳用户**：连续批准高风险动作、忽略授权卡警告。
- **供应链攻击者**：npm/Electron/依赖或更新通道被篡改。

## 5. 关键攻击路径

1. **网页注入 → 模型工具调用 → 产品授权**：注入内容进入上下文后，模型可能请求外部副作用；防线是 `ask`/`deny` 与 main 二次裁决，而不是模型自觉。
2. **恶意扩展 → ToolRegistry → 本机资源**：扩展工具若被错误授予高权限，可能绕过用户预期；需权限清单与撤销流程。
3. **路径解析 → 文件系统**：`realpath`/symlink 边界是主防线；Windows 路径差异仍需实测。
4. **评估门 → 产品结论**：Python 门控与 Electron 审批链路是两套实现，不能互相背书。

## 6. 缺口

- 无独立渗透测试/红队；AgentDojo 只是模型级注入信号，且攻击族仍有限。
- 无 SBOM、依赖漏洞扫描与更新签名验证的成文流程。
- 无真实人类审批可用性数据（误解率、疲劳度、拒绝率）。
- 扩展/MCP 权限清单与撤销流程未成文。
- Windows/Linux 路径语义与安装包完整性未实测。
- 事件响应与回滚演练缺失。

## 7. 评审

- 触发：新增工具、扩展权限模型、Provider/搜索端点、发布流程变更。
- 例行：与风险登记册同步月度复审；每次外部基准或产品审批改动后核对 T-03/T-06/T-10。
