# SUS / HEART 用户研究套件（初版，2026-11-19）

> 状态：**尚未执行**；本文是可复用的研究脚本与问卷，不是用户数据。
> 目的：为 NeonForge 桌面工作台建立可用性基线（SUS）与产品指标（HEART）。
> 关联：`governance-gap-assessment-2026-11-18.md` 第 4 项、`ai-risk-register-2026-11-19.md` R-07/R-14。
> 另见：`ai-walkthrough-2026-11-19.md` 是 **AI 辅助启发式走查 + 脚本化 UI 断言**，只覆盖界面路径，不产生 SUS/HEART 数据，不能替代本套件。

## 1. 研究设计

- 样本：8-12 名目标用户（开发者 / 小团队知识工作者）；不招募本项目开发者。
- 时长：60-75 分钟/人；远程或现场均可。
- 形式：主持人读脚本 → 用户完成 5 个任务 → SUS 问卷 → 半结构访谈。
- 记录：任务完成率、完成时间、授权卡次数、误解点、SUS 分数、访谈要点。
- 不做：A/B 对比、眼动、录屏（除非单独同意）。

## 2. 知情同意与隐私

- 说明目的、流程、时长、可随时退出；不评价个人能力。
- 仅收集匿名 ID、任务结果、SUS 分数与去标识化笔记；不收集项目内容、Key、邮箱。
- 录屏/录音需单独勾选；默认不录。
- 数据保存在本机受控目录，研究结束后 30 天内删除原始记录；汇总结果才可入库。
- 不在仓库写入任何参与者个人信息。

## 3. 任务脚本

每个任务记录：开始/结束时间、是否完成、授权卡次数、是否需要提示、关键误解。

| #   | 任务                     | 成功标准                     | 观察点                             |
| --- | ------------------------ | ---------------------------- | ---------------------------------- |
| 1   | 首次配置 Provider 与模型 | 完成配置并成功发出一条消息   | 是否理解 Key/模型选择；错误恢复    |
| 2   | 提出目标并确认目标卡     | 目标确认卡出现并确认         | 是否理解“确认后才执行”             |
| 3   | 查看方案清单并确认执行   | 方案确认卡出现；清单文件可读 | 是否检查文件清单；是否理解授权范围 |
| 4   | 触发一次文件写入授权     | 授权卡出现；允许/拒绝各一次  | 是否看懂工具与参数；拒绝后的行为   |
| 5   | 验收交付包并解决确认     | 交付包可打开；解决确认完成   | 是否理解完成证据；是否知道如何回滚 |

可选任务 6（时间允许）：重启应用后复开任务，观察确认状态与进度提示。

## 4. SUS 问卷（标准 10 题）

采用 5 点 Likert：1=非常不同意，5=非常同意。中英文可并列展示。

1. 我愿意经常使用这个系统。 / I think that I would like to use this system frequently.
2. 我觉得这个系统不必要地复杂。 / I found the system unnecessarily complex.
3. 我觉得这个系统容易使用。 / I thought the system was easy to use.
4. 我认为我需要技术人员帮助才能使用这个系统。 / I think that I would need the support of a technical person to be able to use this system.
5. 我觉得系统里的各种功能整合得很好。 / I found the various functions in this system were well integrated.
6. 我觉得这个系统有很多不一致的地方。 / I thought there was too much inconsistency in this system.
7. 我认为大多数人能很快学会使用这个系统。 / I would imagine that most people would learn to use this system very quickly.
8. 我觉得这个系统用起来很笨重。 / I found the system very cumbersome to use.
9. 我对使用这个系统很有信心。 / I felt very confident using the system.
10. 在使用这个系统之前，我需要先学很多东西。 / I needed to learn a lot of things before I could get going with this system.

### 计分

- 奇数题：得分 = 回答 − 1；偶数题：得分 = 5 − 回答。
- 10 题得分相加 × 2.5 = SUS 分数（0-100）。
- 报告：中位数、四分位距、样本量与任务完成率；不预设“合格线”。行业常引用 68 作为参考，但不作为本项目的通过标准。

## 5. HEART 指标

| 维度         | 指标                                 | 采集               | 目标/用法      |
| ------------ | ------------------------------------ | ------------------ | -------------- |
| Happiness    | SUS、信任模式满意度、授权卡困扰度    | 问卷 + 访谈        | 建立基线       |
| Engagement   | 每周任务数、确认点到达率             | 本地事件（需同意） | 观察使用深度   |
| Adoption     | 首次配置完成率、首个交付包完成率     | 任务 1/5           | 发现上手障碍   |
| Retention    | 第 2 周回访/再次使用                 | 问卷或访谈         | 观察留存       |
| Task success | 任务完成率、时间、授权次数、回退次数 | 任务 1-5           | 主要可用性指标 |

## 6. 访谈提纲

1. 哪个步骤最让你犹豫？为什么？
2. 授权卡上的信息够不够做决定？缺什么？
3. 你如何判断任务真的完成了？
4. 如果误删/误改，你知道怎么恢复吗？
5. 你会向同事推荐吗？会/不会的原因？
6. 如果只能改一件事，你改什么？

## 7. 分析计划

- 定量：任务完成率、时间中位数、授权次数、SUS 中位数/IQR。
- 定性：按主题聚类（配置、确认、授权、完成证据、恢复）。
- 输出：一页结果摘要 + 原始匿名数据位置（不入库）；不写个人姓名/邮箱。
- 决策：每个主题给出“保持/修改/待验证”，并关联风险登记册 R-07。
