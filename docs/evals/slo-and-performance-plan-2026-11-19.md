# 产品级 SLO 与性能测量计划（初版，2026-11-19）

> 性质：指标定义与测量计划，不是已验证的 SLO；当前没有产品级基线数据。
> 关联：`governance-gap-assessment-2026-11-18.md` 第 2 项、`ai-risk-register-2026-11-19.md` R-12。

## 1. 目标

- 给 NeonForge 桌面工作台建立可重复的产品级性能指标，而不是只引用模型/基准延迟。
- 指标优先本地采集、默认不上传云端；采集需用户同意并说明保留期限。
- 先建基线，再定 SLO 阈值；本文的阈值只是**待验证提案**。

## 2. 指标定义

| 指标 | 定义 | 采集点 | 现状 |
|------|------|--------|------|
| 冷启动时间 | 进程启动到主窗口可交互 | Electron main 时间戳 + renderer ready | 未测 |
| 首 token 延迟 | 用户发送到首个流式 token | renderer 请求时间 → gateway 首块 | 未测（BFCL 延迟是模型级，不是产品） |
| 工具执行延迟 | 工具调用进入到结果返回 | ToolRegistry 执行前后 | 部分单测有耗时，但非基准 |
| 审批等待时间 | 授权卡出现到用户决定 | renderer 授权卡事件 | 未测 |
| 长会话内存 | 30/60/120 分钟会话的 renderer/main RSS | Electron 进程指标 | 未测 |
| 任务成功率 | 目标确认 → 交付包 → 解决确认完成率 | timeline/状态机 | 未测 |
| 错误率 | 工具失败/模型失败/崩溃占比 | timeline + 日志 | 未测 |

## 3. 测量方法

- **冷启动**：在 macOS 目标机重复 20 次，记录 p50/p95；区分首次安装与热启动。
- **首 token**：本地 Magpie 与远端 DeepSeek 分开记录；流式与非流式分开；记录模型/Provider/日期。
- **工具延迟**：固定 fixture 项目，read/write/edit/search/bash 各 30 次；记录 p50/p95 与失败。
- **审批等待**：受控用户研究或模拟点击；记录卡出现到决定的时间与误解点（与 SUS/HEART 共用）。
- **长会话**：固定脚本 30/60/120 分钟，记录 RSS、事件循环延迟、工具失败。
- **任务成功率**：用固定任务集（目标/方案/授权/交付）做端到端运行；当前只有 L1/L3 测试，不是产品级任务成功率。

## 4. 待验证的 SLO 提案

| 指标 | 提案 | 说明 |
|------|------|------|
| 冷启动 p95 | ≤ 3 秒 | macOS 目标机、热启动另计 |
| 首 token p50 / p95 | ≤ 2 秒 / ≤ 5 秒 | 本地 Magpie；远端 Provider 另定 |
| 只读工具 p95 | ≤ 200 ms | 固定 fixture |
| 写入工具 p95 | ≤ 500 ms | 含快照 |
| 审批卡出现 | ≤ 100 ms | renderer 事件到可见 |
| 崩溃率 | 0（每 100 次会话） | 先统计再定阈值 |

- 以上不是承诺值；基线采集后再调整。

## 5. 埋点与隐私

- 优先使用本地 timeline/日志与受控测试；不上传会话内容、文件路径或 Key。
- 如需匿名指标，必须明确字段、保留期限与退出方式。
- 性能日志与评估日志分开，避免把模型延迟混入产品指标。

## 6. 当前结论

- 已有：BFCL 单题延迟、AgentDojo 单题延迟、部分工具单测耗时；这些是模型/评估信号，不是产品 SLO。
- 缺失：冷启动、首 token、审批等待、长会话内存、产品级任务成功率。
- 下一步：先实现本地埋点与固定 fixture 基准，再采集基线；未采到基线前不对外承诺 SLO。
