## 2. 核心域声明：Conversation BC（目标驱动）

**为什么是核心域**：搭档的差异化价值 = 目标驱动的执行（确认驱动推进、防只说不做、宿主强制边界）——这是与其它工具/代理区别的壁垒。

**核心职责**：

| 职责 | 说明 |
|------|------|
| 目标状态机 | Goal → Plan → Resolution——三个确认点驱动状态转换（2026-08-16 更名：方案/解决）|
| 确认点管理 | 目标/方案/解决三处用户确认——结构化确认卡（确认/拒绝带原因）；决策点=状态×提议×动作属性确定性派生（A0 §3.6）|
| 推进保障 | 确认后防只说不做（ProgressGuarantee——强制推进：产出/提议/证据，pending 恒不强制）；失败释放（诊断修正）；任务完成度（计划写完/解决确认释放）|
| 推进门控 | 确认点未确认 → 模型活动边界限制在该确认点（不越级推进）|
| 宿主强制边界 | 计划清单（写文件边界）+ 拒绝回填边界（模型回到边界内）|
| **问题台账（会话外生命周期）** | Problem 聚合（2026-08-15 补建模 M3）——跨会话问题记录/断点续做/复跑——见 02 §4.13 |

**核心域衡量指标**（2026-08-16 同步——对齐 07 v1.1 确认交互指标组）：目标确认到方案批准的转化率（用户是否理解并确认）；方案批准到产出率（确认后是否真正产出）；解决确认率（证据对账通过占比——07 v1.1）；授权卡滞留率/方案修改率（确认交互质量——07 v1.1）。

## 3. 支撑域

### 3.1 Capability BC（能力/环境）

**职责**：
- 环境检测（事实来源）——一次检测（runtime/依赖/工具链/宿主 runtime）
- 能力视图（从环境推导——ready/missing/failed——不独立二次检测）
- 能力检查（模型/系统查询能力状态）
- Ledger 回填（执行结果 → 能力状态自学习）

**与 Conversation 的关系**：Conversation 在确认点后调用能力检查（确认目标 → 检查达成目标所需能力 → 给方案）；环境快照注入系统提示（模型开箱即知）。

### 3.2 Workspace BC（工作区）

**职责**：
- 项目文件操作（read/write/edit）
- 写入快照/回滚（安全闭环）
- 计划清单（approve-files 批准文件集合——宿主强制边界的数据源）
- **授权裁决 + 任务级信任**（授权架构 v4——preApproval 规则引擎 deny>allow>ask fail-closed；任务级信任集合「允许并记住」；信任边界=文件路径类+沙箱内；新目标确认 clearTrust 任务边界）

**与 Conversation 的关系**：Conversation 的推进门控读取计划清单（写文件边界）；写操作经 Workspace 执行（快照/回滚）。

### 3.3 Delivery BC（数字交付）

**职责**：
- 交付包（DeliveryPackage）——产物清单 + 变更预览 + 验收对照 + 状态（「问题已解决」的可验证呈现）
- DoD 对齐（动手前用用户的话复述问题 + 验收标准——「什么叫解决」前置）——**V2（2026-08-15 裁决——V1 以解决确认卡（证据对账）+交付包为闭环——2026-08-16 语义更新）**
- 确认关闭（交付 ≠ 解决——验收打勾 → 用户确认关闭 = 问题终态；「还要改」继续调整）
- 快照回滚（写前快照 .nf-bak——交付不满意恢复原样）

**与 Conversation 的关系**：解决确认卡（证据对账——完成声明+系统核验） = 交付确认入口（模型完成声明 → 交付包呈现 → 用户确认解决/还要改带原因——2026-08-16 语义更新）。

### 3.4 Session Timeline BC（会话时间线）

**职责**：单会话所有步骤统一记录（用户/搭档/工具/授权/确认/状态——时间顺序完整）——可观测性（分析一步到位、断点续做、审计）。

**与 Conversation 的关系**：Conversation 所有状态转换/工具执行发布事件 → Timeline 记录。

## 4. 通用域

| BC | 职责 |
|----|------|
| Gateway（模型网关）| DeepSeek API 通信、流式解析、tool_choice 传递（推进保障输出——2026-08-16）、工具调用修复 |

## 6. 核心域演进方向

1. **确认点扩展**：能力缺失/装依赖等决策点结构化（当前对话式 → 确认卡）
2. **推进门控强化**：确认点未确认的模型活动边界细化（每确认点的允许动作清单）
3. **推进保障自适应**：ProgressGuarantee 决策从规则演进到任务级自适应（模型行为历史）
4. **宿主边界可配置**：计划清单粒度（文件级 → 目录级 → 工具级——用户可调）
