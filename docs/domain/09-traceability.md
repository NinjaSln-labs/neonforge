# 09 — 产品 ↔ 领域追溯矩阵（无阶段·目标驱动版）

> version: v3 · 2026-08-16（v2 · 2026-08-07）
> 对照：产品（目标驱动的搭档交互——确认卡/推进保障/宿主边界）↔ 领域 A0 总纲 **v4.0**（无阶段·目标驱动版——2026-08-16 意图确认重设计：确认点更名方案/解决、推进保障、证据对账、触发权在系统）

## 1. 追溯矩阵

| 产品陈述 | 领域元素（A0 v4.0） | 直接/精化/偏离 | 洞察或同构说明 |
|----------|--------------------|----------------|----------------|
| 「用户说想法 → 搭档澄清目标 → 用户确认」（目标驱动） | 确认点 GoalConfirmed（§3.1——目标确认卡）| **直接** | 目标确认是推进的原点——用户确认才进入执行 |
| 「用户确认方案后才动手」（方案批准） | 确认点 PlanConfirmed（§3.1——方案确认卡，原 ExecutionConfirmed——2026-08-16 更名）| **直接** | 未批准方案 → 不产生 write/edit/bash（推进门控——结构性）|
| 「搭档做完汇报 → 用户确认解决」 | 确认点 ResolutionConfirmed（§3.1——解决确认卡，原 AchievementConfirmed——2026-08-16 更名；完成=声明+证据+对账——§4.2）| **直接** | 未确认解决 → 不收敛（推进保障保持）；无证据不对账 |
| 「确认/拒绝按钮」（结构化确认） | 确认卡（§3.2——确认/拒绝三态——行业共识）| **直接** | 对齐 OpenHands/Cline/Codex——非确认词匹配 |

| 「错误要抛出来，模型自己修正」 | 执行保障失败感知（§4——工具失败释放强制）| **精化** | 失败释放 → 模型可停下诊断（required 压制诊断是反模式）|

| 「环境检测准确，路径一致」 | 环境注入（§6——环境快照注入模型——项目根/runtime 显式）| **精化** | 模型开箱即知环境（不需要猜路径/探索确认）|
| 「信任阶梯——允许并记住」（授权不烦）| 授权裁决 + 任务级信任（§4.8——允许并记住→沙箱内自动；clearTrust 任务边界）| **直接** | 授权疲劳解法——一次批准本任务内不再问（信任不跨任务）|
| 「交付包——验收对照确认关闭」（交付即闭环）| Delivery BC（§4.9——交付≠解决——closed 需用户确认关闭）| **直接** | 交付包（产物+验收对照+快照回滚）——解决确认卡（证据对账）=交付确认入口（2026-08-16）|
| 「起服务不用猜端口」 | 服务管理（§4.10——ServiceRegistry 记忆端口/PID/URL——动态端口分配）| **精化** | start-server 返回真实地址——模型不用猜端口（坑 67 终结）|
| 「输入不打断（排队衔接）」 | 输入衔接（§4.12——模型产出中发送→排队→当前轮完成自动发送）| **直接** | 打断=显式停止按钮（对齐 Claude Code Esc/Cursor）|
| 「能力缺了什么要问」 | 能力缺失征求用户（§6——装依赖/换方案——决策类确认点）| **直接** | 能力检查后缺失 → 对话征求（不擅自装）|
| 「出问题能追溯（重复命令/打断）」 | 会话时间线（§2 Timeline BC——全步骤统一记录）| **直接** | 可观测性——分析一步到位 |
| 「问题 = 一等公民（台账/复跑/断点续做）」 | Problem 聚合（§4.13——问题生命周期/快照 goal·decisions·authorized·pending；断点续做 V1=消息+台账、状态机不跨重启）| **直接** | 问题台账（7 态状态机/复开复跑）——2026-08-15 M3 补建模 |
