# 09 — PRD ↔ 领域追溯矩阵

> version: v1 · 2026-07-31
> 来源：prd-driven-ddd 技能方法（可追溯映射，非 1:1 照搬）
> 对照：产品 D0（`docs/product/00-product-design.md`）↔ 领域 A0 总纲（`docs/domain/00-domain-authority.md`）
> 用途：锁定「产品说 A → 领域做成 B」，差异显式；实现时按此追溯，防漂移。

---

## 1. 追溯矩阵

| PRD 陈述（D0） | 领域元素（A0 总纲） | 直接/精化/偏离 | 洞察或同构说明 |
|----------------|--------------------|----------------|----------------|
| 「用户说想法 → 搭档分析出方案」（§1.1 三步工作流） | AgentChain（§3 模板 1 single-agent：analyst） + ContextEngine（§5 LSP 三层） | **精化** | 分析=analyst 角色 + ContextEngine 精准上下文；产品「分析」一步在领域拆为 Agent 角色 + 上下文管线两个职责 |
| 「用户确认方案」（§1.1） | AgentChain 用户确认闸门（§3：V1 单 Agent 链 + 确认） | 精化 | 产品确认步 = 链中人工闸门；V1 不做多 Agent 并行（对齐 D0 §11 范围） |
| 「改动不直接写入」（§1.2 原则 2） | ChangeSet（proposed→accepted→applied）+ DiffApply 原子 apply（§7 V1 矩阵） | **直接** | 写入模型 = 领域聚合状态机，产品 UI 即状态呈现 |
| 「透明不炫技，推理过程可见」（§1.2 原则 3） | ReasoningViz（§2 Layer 2，reasoning_content 捕获分级展示） | **直接** | 产品「🧠 怎么看这个问题的」动效 = ReasoningViz 呈现 |
| 「安静，不弹窗打扰」（§1.2 原则 4） | EventBus 通知机制（§6：通知走总线，非模态提示条） | **同构** | 非功能约束落地为领域通信规则（只发通知、不打断） |
| 「1M 上下文从容」（D0 §非功能/领域 §5） | 1M 预算（§5：固定前缀/LSP/对话/推理/余量）+ Compaction（100条/200K） | **直接** | 预算表即领域上下文策略的量化权威 |
| 「多任务可排队」（§3.6 串行队列） | AgentChain 单链 + 任务队列（§3/§7：V1 串行） | 精化 | 产品任务队列 = 链的调度层；同文件后继任务基于前一写入版本（领域不变式） |
| 「新建项目一键安装预览」（§3.7 非技术闭环） | ShellAgent（§2 Layer 1：命令执行沙箱）+ Workspace | 精化 | 产品「安装并预览」= ShellAgent 执行 install/dev + Workspace 接入预览 |
| 「@引用文件优先看」（§3.9） | ContextEngine Layer 1（LSP 定位）+ 引用优先级 | 精化 | 产品 @引用 = 上下文注入的显式优先级提示 |
| 「推理四档」未在产品设置出现（§9 设置仅语言/视图/提醒） | ThinkingLevel 四档（§2 Layer 2） | **偏离（有意）** | 产品 V1 不暴露 ThinkingLevel UI（后台默认 basic）；领域能力先于产品 UI——领域为 V2 UI 预留，产品矩阵标注「无 UI 后台」 |
| 「本轮用量折叠」（§3.3 M6） | TokenTracker（§2 通用支撑） | 直接 | 用量统计进折叠行，不进 StatusBar（产品 UI 权威） |
