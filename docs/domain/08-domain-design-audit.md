## 审计项

### 1. 确认点完整性（通过——会话级单一 PENDING 扩展）

| 确认点/决策点 | 设计 | 状态 |
|--------|------|------|
| GoalConfirmed | 用户确认目标（确认/重新描述）——未确认只澄清 | ✓ |
| ExecutionConfirmed | 用户确认执行（确认/修改方案）——未确认不动手 | ✓ |
| AchievementConfirmed | 用户确认解决（已解决/还要改）——未确认不收敛 | ✓ |
| **授权卡**（工具级）| 用户批准/拒绝工具——**不批准则后续无法继续——影响任务推进** | ✓（会话级 pending 覆盖）|

**单一 PENDING（会话级——2026-08-07 领域定论）**：三确认点 + 授权卡 → **统一会话级「等用户决策」状态（Conversation 聚合承载）**——pending 下模型动作全部无效（做了白做——所有工具都不放行）——用户决策是下一个状态的唯一输入。

**Major 1 ✅ 已闭合（00 §3.4——修正）**：pending（等用户决策）下**所有工具都不放行**——模型后续任何动作无效（做了白做——不执行不生效）——用户决策是下一个状态的唯一输入——用户「是」→ 模型根据决策重新做。

### 2. 推进门控（通过——会话级 pending + Task 子状态机）

**会话级单一 PENDING**（Conversation 聚合承载）：任何卡弹出 → 会话冻结（模型动作全部无效）→ 用户是/否 → 状态推进/回退。

**Task 降级为会话内子状态机**：只管三个任务级确认点（clarifying → goal-confirmed → executing → achieved-reported → resolved）——**不承载 pending**（工具级授权等待是会话级 pending 的一部分）。

**调研交叉验证（2026-08-07）**：对齐决策状态机类（OpenHands AWAITING_USER_CONFIRMATION/USER_CONFIRMED/USER_REJECTED + brightlume 等待态约束跳转 + 自主性停止点 + Medium exactly once）；**Reddit/FSM 活动状态机（working/waiting——UI 层呼吸条）是不同层——非领域 PENDING 对照**；OpenHands 多等待态（input vs confirmation）为粒度先例——我们统一单一 PENDING（来源=卡类型——场景适配：等待都是「等用户是/否」）。

### 3. 执行保障（通过）

| 规则 | 设计 |
|------|------|
| 确认后无产出 | forceTool=true（required——防只说不做）|
| 工具失败 | 释放（auto——模型诊断修正——required 压制诊断是反模式）|
| 计划写完 | 释放（模型可收敛——写 1 文件 ≠ 任务达成）|
| 达成确认 | 释放（用户确认解决——对话收敛）|

### 4. 宿主强制边界（通过）

计划清单（追加语义/显式可见/拒绝带边界）——模型漂移防护（行业共识）。

**Major 2 ✅ 已闭合（00 §3.5 + 05 §4）**：门控优先级显式——PENDING（等用户决策）是状态机冻结（先——所有动作无效，不管清单）；计划清单是文件级边界（后——用户确认执行后逐文件核对——拒绝带边界）。pending 时不进入清单判定。

### 5. 能力环境（通过）

环境=事实来源（一次检测）→ 能力=语义视图（推导）——Ledger 回填（自学习）——环境快照注入模型。

### 6. 结构化确认（通过）

确认卡（确认/拒绝按钮）——对齐 OpenHands USER_CONFIRMED/USER_REJECTED、Cline allow/always/reject。

**Minor 1**：拒绝动作的后续语义——「重新描述/修改方案/还要改」是拒绝后的引导——应标准化（拒绝 → 模型收到拒绝事件 → 重试/调整）。

### 7. 时间线（通过）

全步骤统一记录（JSONL）——崩溃保留已写行。

**Minor 2**：时间线事件类型与确认点事件（goal/execution/achievement confirmed+rejected）应完整（当前已列）。

**Minor 3**：多会话隔离（session 字段）——跨进程 seq 冲突（进程内自增）——需全局唯一（ts+进程 id）。

### 8. 授权与信任（通过——2026-08-07 补文档后审计）

授权裁决（deny>allow>ask fail-closed——main 进程）+ 任务级信任（允许并记住→沙箱内 write/edit 自动）——信任边界（只文件路径类——bash 永不；只沙箱内——沙箱外永不）+ 任务边界清除（新目标确认 clearTrust）+ 授权记录可回溯（时间线+TrustLadder）。

**审计**：与单一 PENDING 一致（授权卡=会话级 pending 来源——批准结果进信任集合）——无冲突。

### 9. 数字交付（通过——2026-08-07 补文档后审计）

Delivery BC（交付包/DoD 对齐/确认关闭/快照回滚）——交付 ≠ 解决（closed 需用户确认关闭）——达成确认卡 = 交付确认入口。

**审计**：交付确认与达成确认卡统一（会话级 pending——用户已解决/还要改）——无冲突。

### 10. 服务管理 + 错误契约 + 输入衔接（通过——2026-08-07 补文档后审计）

服务管理（ServiceRegistry/端口分配/失败检测/命令识别单源）、错误契约（errorType 分类/bash 错误回填/失败感知）、输入衔接（排队——不打断——打断=显式停止）。

**审计**：服务工具/错误契约/排队衔接是技术层机制——与领域确认点无冲突（排队衔接是输入时机——非状态机变更——符合领域「输入不打断」约束）。
