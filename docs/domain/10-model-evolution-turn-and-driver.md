## 1. 基线：现行模型已经给了什么

现行领域模型（`docs/domain/00–09`，ADR-001～017 累积）在**"等什么"**上有完整本体：

| 已有本体                       | 载体                                                                              | 强度                                            |
| ------------------------------ | --------------------------------------------------------------------------------- | ----------------------------------------------- |
| 会话级单一 PENDING（状态机）   | `00 §3.2`（不变量 1 **唯一措辞源**）＋`04 §1.2` Conversation 聚合成员 `pending`   | 有身份（`decisionInstanceSeq`）、有转换、有事件 |
| 决策点实例寻址                 | ADR-015（双概念：槽 kind × 实例 seq；单一身份门；`restorePending`）               | 可机验                                          |
| 授权窗口（ApprovalWindow）     | ADR-017（`requestId` 不透明身份＋main journal 三判＋规则三档）                    | 跨进程跨重启可证                                |
| 推进的**判定**（不算推进什么） | `00 §4/§4.1`（ProgressGuarantee 档位表；TurnProgress 值对象；StuckDetector 同源） | 有 VO、有服务                                   |
| 完成证据对账                   | `00 §4.2`（CompletionClaim/CompletionEvidence；无证据不对账）                     | 不变量级                                        |
| 问题台账跨会话生命周期         | `02 §4.13`／`04 §1.5` Problem 聚合＋快照                                          | 有聚合                                          |

**一句话诊断**：**「等人」有本体，「谁在推进」没有本体。** 现行模型能精确回答"这张卡是哪一次呈现、这条批准是哪一条记录"，却回答不了"这条正在改会话状态的产出属于哪一次开口、它还有没有资格改"。

## 2. 隐性概念清点（名字已在用，本体从未定义）

这是本次进化最需要在落位时处理的层——**隐性概念比完全缺失更危险**：人人以为"轮"已经存在，于是每份文档各自用它，粒度还不一样。

| #   | 已存在的"轮"用法                                                     | 出处                                                            | 实际粒度（本次裁定）                                                                                                                                                                                                                                   | 落位处置                                                                                                                                                          |
| --- | -------------------------------------------------------------------- | --------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| H1  | 值对象 **`TurnProgress`**，注释逐字"单轮进展"                        | `src/domain/agentLoop.ts:24`；`00 §4.1` 点名                    | 它的字段（artifactProduced／sideEffectSucceeded／readNewFile／isQuestion／proposed／providedEvidence／needsApproval）判定的是**一次模型往返**＝本模型的 **Step**；其中 `hasPlannedFiles`／`hasRemainingPlanned`／`remainingCount` 是 **Task 级**累积量 | **术语收口**：改名 `StepProgress`，或在 `04 §3.1` 显式标注"粒度＝Step，跨往返部分属 Task"。二者择一，禁止留着同名异指——本次裁决准绳是单源化，同名异指正是双源歧义 |
| H2  | 「**上一轮**工具失败→释放强制」                                      | `00 §4` 表行／`02`（失败感知）／`04 §3.1` 字段 `lastToolFailed` | "上一轮"＝**上一个 Step**（同 Turn 内前一次往返），不是上一个 Turn                                                                                                                                                                                     | 文档改词为"上一步"，或加注；实现语义不变                                                                                                                          |
| H3  | 「**本轮**输出结构化提议（算推进）」「**本轮**待执行动作的属性列表」 | `04 §3.1`／`§3.6` 参数形状注释                                  | 同上＝Step                                                                                                                                                                                                                                             | 同 H2                                                                                                                                                             |
| H4  | 「确认点**内部**的自主工作——模型自动执行工具链，直到下一个确认点」   | `02 §4.2` 自推进                                                | 这就是 **Turn 的行为**，但没有名字，于是实现把它实现成"另一条会自己 ++ 的链"（`maybeContinue` 续链）                                                                                                                                                   | §4 提案裁定：**续链不是新轮**——自推进＝同 Turn 内的 Step 序列。落位时 `02 §4.2` 改引本模型                                                                        |
| H5  | 渲染层私有游标 `sessionRef/sid` 同时充当"轮次标识"与"取消令牌"       | 实现                                                            | 代职＝缺第一轨（turnId）的症状                                                                                                                                                                                                                         | ADR-021 F2：游标退役为纯呈现投影，判据可机验                                                                                                                      |

⇒ **本次进化的真正靶心**：不是"补一个新概念"，而是**把已经在五份文档里被当形容词使用的"轮"，升格为有名有姓、有生命周期、有唯一签发点的领域实体**。

### 3B 我自己的三条误报（v1 说过头，v2 已改）

① **G6**「压缩无承载」过宽——阈值与流程在 `07-api-gateway §5`（100 条/200K 触发、保留 20 条、基线重建）与 `04 §5` 已有，真缺只剩 C11 可见性与"压缩不得吞决策内容"；② **R5**「分工未成文」过宽——`02 §4.8` 与 `06 §1.3c` 已裁两半；③ **§5 对账表把 §3.6 判"闭合"是误判**——I-T13/I-T14 管 **TurnInput 准入序**，不是 **Task 队列对象序**，拿前者代偿后者正是 N2。

⇒ 三条同一成因：**正向对账只对着 §4.5 一族扫，没对着 §3.x／§4.3／§4.4 扫**（偏视）。已把互审固化为**双向核**（产品→领域 且 领域→产品）。

### 3C 待裁项 F7（本进化唯一未闭合的接缝）

「待授权期用户发**新指令**」的**轮次归属**：现行文本只说"可直接处理"（`02 §4.12`＋ADR-013 裁定 2），**从未裁定它落在哪个轮**；而 `00 §3.2 要点 5`（窗含 pending 记录⇒槽仍为 approval）＋要点 2（pending 下模型动作一律无效）使"直接处理"若直接成新轮＝**假推进**。三解（**A** 有痕解算→释放槽→原轮 Superseded→新轮准入，v1.3 现采用／**B** 同轮续跑不释放槽，但用户不点卡就永久冻结＝C2a 死锁族复发／**C** 冻结粒度收窄到单条记录）与代价见提案 §10 末。**选 C 要修订不变量 1 的冻结射程＝触唯一措辞源，不属合作负责人可自裁范围。**

**判定：本批补的是真缺（G1–G3 全部有产品承诺悬空作证据），但"补全"不成立——G4–G8 是真漏，其中 G5 是我自己写不变量时当场暴露的（不变量挂在未定义词上）。**

## 7. 结论

1. **补的是真缺**：G1–G3 每一条都有产品承诺（C13／C3／C7／C12）正悬空无持有人，且能在现行五份文档里指出"轮"被当形容词用了 4 处＋一个已命名的 `TurnProgress` VO 无定义域——这不是投机性建模，是**给已在使用的词补本体**。
2. **没补全，且比 v1 承认的更多**：G4／G5／G6(残余)／G7／G8／R5 残余，**＋互审新增 N1 写盘审核态机／N2 任务队列对象序／N3 现实世界等待清单／N4 失败包／N5 上下文喂给／N6 闲置提醒**。N1/N2/N3 与 G4 同级——它们不是轮次族的洞，而是**写盘、任务次序、现实世界等待**三条 V1 主流程在领域里从来没有本体，不能以"呈现层概念"豁免。
3. **v2 修订次序**：①先裁 **F7**（决定 §4 出口③与 I-T9/I-T17 写法）→ ②补 **N2 TaskQueue ＋ G4 Message 生命周期**（V1 主路径、涉持久化）→ ③走 §6 落位批 → ④N1/N3/N4/N5/N6 与 G5/G6(残余)/G7/G8、R5 残余各立缺口票，不夹带——避免补洞变成第二轮范围蔓延。
4. **直答「是不是补全了」：没有。** G1–G3 补得实（每条都有产品承诺悬空作证据，且能指出"轮"被当形容词用了四处＋一个名实不符的 `TurnProgress` VO）。但互审又打出 6 条漏报＋我自己 3 条误报。**本轮把「谁在推进」钉死了；「推进在改什么」（N1）与「推进的容器次序」（N2）仍是空白。**
