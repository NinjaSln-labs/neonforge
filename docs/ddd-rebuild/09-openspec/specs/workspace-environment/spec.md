## Requirement: 项目打开与初始化

系统应允许用户打开已有项目或从零创建一个真实项目目录；不得覆盖已有目录。

### Scenario: 打开已有项目

- **Given** 用户选择一个已有目录
- **When** 打开项目
- **Then** 该目录成为当前工作区根
- **And** 文件树可列出项目内文件

### Scenario: 从零创建项目

- **Given** 用户输入一个问题或标题
- **When** 选择从零开始
- **Then** 系统创建项目目录与最小骨架（README、搭档须知）
- **And** 不在需求/技术栈未确定时创建工程文件

### Scenario: 同名目录已存在

- **Given** 目标项目目录已存在
- **When** 创建新项目
- **Then** 系统自动追加序号，绝不覆盖已有目录

### Scenario: 回写项目标题

- **Given** 用户确认了目标
- **When** 系统更新项目标题
- **Then** README 首行与工程包名按安全名规则更新
- **And** 目录名保持不变，避免路径断裂

## Requirement: 计划清单持久化

系统应将已批准的计划清单作为跨重启的权威数据保存；追加必须幂等，任务边界必须清空。

### Scenario: 追加批准文件

- **Given** 计划清单已有若干文件
- **When** 用户批准新的文件清单
- **Then** 新文件并入清单，重复文件不重复
- **And** 批准标记置为真

### Scenario: 空清单批准

- **Given** 批准清单为空
- **When** 系统收到批准请求
- **Then** 清单保持不变，批准标记不改变

### Scenario: 任务边界重置

- **Given** 用户确认了新目标
- **When** 任务边界开始
- **Then** 计划清单被清空，批准标记置为假
- **And** 写前快照在任务边界被清理

### Scenario: 跨重启恢复

- **Given** 用户之前已批准过文件
- **When** 应用重启
- **Then** 计划清单与批准标记被恢复

### Scenario: 清单存储损坏

- **Given** 计划清单存储文件损坏或缺失
- **When** 系统加载清单
- **Then** 返回空清单，不阻断应用启动
- **And** 后续批准操作可重建存储

## Requirement: 环境与能力

系统应检测项目环境事实，并将能力以“就绪/缺失/不可用”呈现；能力检测不得重复执行同一环境探测。

### Scenario: 环境就绪

- **Given** 项目有 package.json 与已安装依赖
- **When** 检查能力
- **Then** 返回 node runtime、包管理器、工具链与能力清单
- **And** 铺开的环境信息注入搭档上下文

### Scenario: 能力缺失

- **Given** 项目需要某项外部能力但未安装
- **When** 检查能力
- **Then** 该能力状态为“缺失”，并给出安装建议
- **And** 搭档被引导先补齐能力再继续

### Scenario: 能力不可用

- **Given** 运行时存在于 PATH 但执行失败
- **When** 检查能力
- **Then** 该能力状态为“不可用”，与“未安装”区分

### Scenario: 环境签名变化

- **Given** 项目环境之前已检测过
- **When** 依赖或运行时发生变化
- **Then** 系统重新检测并更新环境快照

### Scenario: 同一环境的能力检测

- **Given** 同一次检查中已完成环境探测
- **When** 生成能力视图
- **Then** 复用环境事实，不重复执行相同探测

## Requirement: 服务生命周期

系统应管理开发服务器：启动、检查、停止；每个项目最多一个服务；只停止自己启动的进程。

### Scenario: 启动服务

- **Given** 项目环境已就绪且没有运行中的服务
- **When** 搭档或用户启动服务
- **Then** 系统分配端口、启动服务并记录实际地址
- **And** 返回真实端口与地址

### Scenario: 重复启动

- **Given** 该项目已有运行中的服务
- **When** 再次启动
- **Then** 系统直接返回已有服务的地址与端口，不重复启动

### Scenario: 检查服务

- **Given** 服务已启动
- **When** 检查服务状态
- **Then** 系统探测实际地址并返回运行中/未运行
- **And** 不通过任意命令执行来检查

### Scenario: 停止服务

- **Given** 服务由 NeonForge 启动
- **When** 停止服务
- **Then** 系统终止该服务进程并释放端口
- **And** 用户自己的进程不受影响

### Scenario: 服务启动失败

- **Given** 启动命令不在允许的服务命令范围，或环境缺少依赖
- **When** 启动服务
- **Then** 系统返回明确错误，释放已分配端口
- **And** 不留下孤儿进程

## Requirement: 端口管理

系统应为本项目分配可用端口，避开宿主保留端口与其他已分配端口。

### Scenario: 分配端口

- **Given** 项目尚未分配端口
- **When** 启动服务
- **Then** 系统从可用端口区间分配一个未被占用的端口

### Scenario: 复用端口

- **Given** 项目已分配过端口且未释放
- **When** 再次需要端口
- **Then** 复用同一端口

### Scenario: 保留端口冲突

- **Given** 服务实际落到了宿主保留端口
- **When** 系统检测到冲突
- **Then** 系统终止该服务并拒绝占用
- **And** 返回可执行的换端口引导

### Scenario: 释放端口

- **Given** 服务已停止或启动失败
- **When** 释放端口
- **Then** 该端口可被其他项目重新分配
