# Spec · 会话时间线（session-timeline）

> Bounded Context：BC-06 会话时间线
> 聚合：A8 Timeline
> 本 Spec 只描述业务规则与不变量；JSONL/文件细节见 `../../design.md`。

---

## Requirement: 事件注册表

系统应维护唯一的事件类型注册表，每种事件有稳定类型名、分类与展示规格；未注册类型不得被写入时间线。

### Scenario: 注册事件

- **Given** 领域发生状态转换
- **When** 系统产生事件
- **Then** 事件类型必须存在于注册表
- **And** 事件带有摘要与可选详情

### Scenario: 未注册事件

- **Given** 代码试图写入未注册的事件类型
- **When** 系统校验
- **Then** 该事件被拒绝（开发期暴露）而不是静默落盘

### Scenario: 事件规格演进

- **Given** 事件注册表新增类型
- **When** 旧版本时间线被读取
- **Then** 未知类型按“未知事件”降级展示
- **And** 不导致读取失败

## Requirement: 状态差异派生

系统应只根据聚合状态的前后差异派生事件，保证同一次转换不重复产生同一事件。

### Scenario: 目标确认

- **Given** 目标从未确认变为已确认
- **When** 状态转换
- **Then** 派生“目标已确认”事件
- **And** 同时派生的“待决策已清除”不会重复

### Scenario: 决策置位

- **Given** 会话从一个决策点切换到另一个决策点
- **When** 状态转换
- **Then** 派生旧决策清除与新决策请求事件
- **And** 同一决策内容不重复派生

### Scenario: 无变化转换

- **Given** 前后状态完全相同
- **When** 派生
- **Then** 不产生任何事件

### Scenario: 拒绝带原因

- **Given** 用户拒绝一个决策点
- **When** 状态转换
- **Then** 派生“决策被拒绝”事件并附原因分类
- **And** 不把拒绝记为确认

## Requirement: 事件追加与查询

系统应按会话追加事件、保持单调序号，并支持按会话查询与过滤；坏行不得阻断查询。

### Scenario: 追加事件

- **Given** 一次会话已有若干事件
- **When** 追加新事件
- **Then** 序号单调递增且事件写入该会话的时间线
- **And** 写入失败不影响主流程

### Scenario: 查询会话

- **Given** 某会话有时间线
- **When** 用户查询
- **Then** 按顺序返回该会话事件
- **And** 支持按类型/关键字过滤

### Scenario: 坏行容错

- **Given** 时间线文件中存在无法解析的行
- **When** 查询
- **Then** 跳过坏行并返回其余事件
- **And** 不重写或截断原文件

### Scenario: 会话隔离

- **Given** 存在多个会话的时间线
- **When** 查询一个会话
- **Then** 只返回该会话的事件，不串流

## Requirement: 事件去重

系统应为可重复派生的状态事件计算稳定去重键，避免同一事实被记录多次。

### Scenario: 同一事实重复派生

- **Given** 同一状态事实在一次回合中被多次派生
- **When** 系统计算去重键
- **Then** 只保留一条事件
- **And** 去重键由事件类型与关键标识组成

### Scenario: 不同事实相同类型

- **Given** 同类型事件描述不同对象
- **When** 去重
- **Then** 两条事件都被保留

---

## Requirement: 聊天日志导出

系统应支持把对话导出为聊天日志，导出内容不包含密钥；导出文件固定覆盖而不是无限追加。

### Scenario: 导出对话

- **Given** 一次会话有完整消息
- **When** 用户导出
- **Then** 生成聊天日志文件，包含角色与内容
- **And** 不包含任何密钥或凭据值

### Scenario: 重复导出

- **Given** 同一会话已导出过
- **When** 再次导出
- **Then** 新导出覆盖旧导出，避免重复堆积

### Scenario: 导出失败

- **Given** 目标路径不可写
- **When** 导出
- **Then** 返回明确错误，不产生半截文件

## 校验

- [x] Requirement 粒度：注册、派生、追加查询、去重、导出各自独立
- [x] 每个 Requirement 的 Scenario 数 ≤ 5（注册 3、派生 4、追加 4、去重 2、导出 3）
- [x] 单一事件注册表（ADR/AGENTS 规则）被明确表达
- [x] Scenario 未渗入 JSONL 路径等技术细节
