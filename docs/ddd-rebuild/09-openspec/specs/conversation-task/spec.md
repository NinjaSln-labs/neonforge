# Spec · 会话与任务（conversation-task）

> Bounded Context：BC-01 会话与任务
> 聚合：A1 Task
> 本 Spec 只描述业务规则与不变量；IPC/存储/框架细节见 `../../design.md`。

---

## Requirement: 目标提议与确认

系统应允许搭档提议一个目标，但只有在用户明确确认后，目标才成为本次任务的边界；模型不能自行确认。

### Scenario: 搭档提议目标后等待用户确认

- **Given** 会话尚未确认目标
- **When** 搭档提交目标提议，包含一句话目标与关键假设
- **Then** 会话进入 `goal` 待决策状态
- **And** 目标不被视为已确认，工具仍不能执行副作用

### Scenario: 用户确认目标

- **Given** 会话处于 `goal` 待决策状态
- **When** 用户确认目标
- **Then** 目标被确认，计划与解决确认被重置
- **And** 本次任务的计划清单、产出文件、文件批准标记、拒绝记忆被清空
- **And** 发出目标已确认与待决策已清除的领域事件

### Scenario: 用户拒绝目标且未给原因

- **Given** 会话处于 `goal` 待决策状态
- **When** 用户拒绝目标但没有提供拒绝原因
- **Then** 系统拒绝该决策并报告“拒绝必须带原因”
- **And** 目标保持未确认

### Scenario: 目标确认后的新目标提议

- **Given** 当前目标已确认
- **When** 搭档提交新的目标提议
- **Then** 系统仍产生 `goal` 决策点，视为“换目标/新任务”提议
- **And** 用户确认后按任务边界重置；用户拒绝则维持原任务

## Requirement: 方案提议与确认

系统应允许搭档在目标确认后提议执行方案；方案只有经用户确认后才形成写入边界与计划清单。

### Scenario: 目标未确认时提议方案

- **Given** 目标尚未确认
- **When** 搭档提交执行方案
- **Then** 系统拒绝该方案提议，并引导先确认目标
- **And** 不产生 `plan` 决策点

### Scenario: 方案提议只产生决策点，不产生写入边界

- **Given** 目标已确认且方案未确认
- **When** 搭档提交包含文件清单的执行方案
- **Then** 会话进入 `plan` 待决策状态
- **And** 计划清单保持为空，方案中的文件不自动获得写入许可

### Scenario: 用户确认方案

- **Given** 会话处于 `plan` 待决策状态，且决策内容包含方案提议
- **When** 用户确认方案
- **Then** 目标被视为已确认，方案被确认
- **And** 计划清单由该方案的文件的并集派生（追加、去重、忽略空白）
- **And** 系统将计划清单与“方案已确认”同步到执行侧

### Scenario: 用户拒绝方案

- **Given** 会话处于 `plan` 待决策状态
- **When** 用户拒绝方案并给出原因（方向/范围/复杂度/信息不足/修改/其他）
- **Then** 方案保持未确认
- **And** 被拒方案中的文件不加入计划清单
- **And** 系统记录拒绝原因，供搭档吸收后重新提议

### Scenario: 方案确认后批量批准文件

- **Given** 目标与方案均已确认
- **When** 用户批准一批文件
- **Then** 批准的文件追加到计划清单，重复文件不重复
- **And** 空文件清单不产生任何变化

## Requirement: 完成声明与证据核验

系统应要求搭档在声明完成时提供可核验证据；没有系统可复核证据或计划文件未全部产出时，不进入“解决确认”。

### Scenario: 无证据的完成声明

- **Given** 目标与方案已确认
- **When** 搭档提交完成声明但没有验证证据
- **Then** 系统不产生 `resolution` 决策点
- **And** 系统要求搭档补充证据后重新提交

### Scenario: 系统可代跑证据通过

- **Given** 搭档提交完成声明，至少一条验证命令是系统可代跑的命令，且输出与声明一致
- **When** 系统完成核验
- **Then** 完成声明被视为证据充分
- **And** 会话进入 `resolution` 待决策状态，等待用户确认“问题已解决”

### Scenario: 计划文件未全部产出

- **Given** 计划清单非空
- **When** 完成声明提交时仍有计划文件未被实际产出
- **Then** 完成声明被拒绝，缺失项包含“计划未产出”
- **And** 即使部分证据通过，也不能进入解决确认

### Scenario: 不可代跑证据（含外网只读）

- **Given** 验证命令不是系统可代跑命令，或是指向外网的网络读取命令
- **When** 完成声明提交
- **Then** 该证据被标注为“未经系统核验”，但仍可列出
- **And** 系统不自动执行外网命令；只有本机/本地网络的只读证据可被自动代跑
- **And** 如果没有任何可代跑证据，完成声明不通过

### Scenario: 遗留问题不阻塞解决确认

- **Given** 完成声明包含遗留问题清单，且证据充分
- **When** 系统核验
- **Then** 遗留问题作为知情项保留，不单独否决完成声明
- **And** 用户仍可在解决确认时看到这些遗留问题

## Requirement: 无进展对话保护

系统应检测“同决策点重复、pending 期间文本回复、连续拒绝、总轮次过多”的对话，并按梯度介入；不得让用户陷入无限协商。

### Scenario: 同决策点重复置位

- **Given** 会话连续多次在同一类决策点上置位
- **When** 达到软阈值
- **Then** 系统向搭档注入“不要用文本替代结构化确认”的引导
- **And** 达到强阈值时，系统直接产生强制澄清决策点，本回合不再调用模型

### Scenario: pending 期间用户连续打字

- **Given** 会话存在待决策点
- **When** 用户连续发送文本回复而不是点确认卡
- **Then** 系统累计文本回复次数
- **And** 达到阈值后升级为强制澄清

### Scenario: 连续拒绝同一决策点

- **Given** 用户连续拒绝同一决策点
- **When** 连续拒绝次数达到 2
- **Then** 系统产生强制澄清决策点
- **And** 用户点“重新描述”后，连续拒绝计数被重置

### Scenario: 总回合软上限

- **Given** 一次会话已进行了大量回合
- **When** 回合数达到软上限且仍无收敛
- **Then** 系统触发强制澄清，避免无限循环

## Requirement: 会话恢复

系统应支持在应用重启后恢复最近的完整会话与决策内容快照；半截流式消息不得被持久化。

### Scenario: 恢复完整消息

- **Given** 会话中存在完整完成的用户/搭档消息
- **When** 应用重启并加载会话
- **Then** 完整消息、工具调用完整状态与决策内容快照被恢复

### Scenario: 不保存半截流式消息

- **Given** 搭档消息仍在流式输出
- **When** 会话被持久化
- **Then** 该半截消息不被写入存档，已有完整消息不受影响

### Scenario: 存档损坏

- **Given** 会话存档无法解析
- **When** 应用启动
- **Then** 系统忽略损坏存档并回到空会话
- **And** 不阻断用户开始新会话

### Scenario: 新会话清空

- **Given** 用户开始新会话
- **When** 系统执行新会话动作
- **Then** 旧会话存档被清除，问题台账不被误删（问题台账是独立存储）
