# Spec · 执行与信任（execution-trust）

> Bounded Context：BC-02 执行与信任
> 聚合：A3 ToolInvocation（与 A1 Task 的门控协作）
> 本 Spec 只描述业务规则与不变量；IPC/存储/框架细节见 `../../design.md`。

---

## Requirement: 工具目录与风险分级

系统应把可执行动作区分为只读、低风险文件操作、高危命令执行，并按风险决定是否需要用户授权。

### Scenario: 只读观察

- **Given** 动作是只读观察（读取、搜索、符号查询、能力检查）
- **When** 搭档请求执行
- **Then** 系统自动放行，不弹授权卡

### Scenario: 低风险文件操作

- **Given** 动作是写入或编辑文件
- **When** 搭档请求执行
- **Then** 系统要求用户授权，除非该文件已在批准清单内或命中任务信任
- **And** 写入前必须保留原文件快照，支持回滚

### Scenario: 高危命令

- **Given** 动作是执行本机命令
- **When** 搭档请求执行
- **Then** 系统默认要求用户逐次授权
- **And** 只读命令可自动放行，但必须经过动作属性判定

### Scenario: 未知工具

- **Given** 请求的工具不在工具目录中
- **When** 系统收到执行请求
- **Then** 系统拒绝执行并返回“未知工具”

## Requirement: 授权与信任阶梯

系统应支持逐次授权、允许并记住、批量批准文件与低危委托；拒绝必须被记住，并在同一任务内对同类动作短封。

### Scenario: 用户批准单次动作

- **Given** 工具卡处于待授权状态
- **When** 用户批准
- **Then** 该动作以已授权状态执行
- **And** 工具卡显示执行结果

### Scenario: 用户拒绝动作

- **Given** 工具卡处于待授权状态
- **When** 用户拒绝并给出原因
- **Then** 动作不执行
- **And** 系统记住该工具与动作对象，在任务边界内对同类动作直接拒绝

### Scenario: 允许并记住与批量批准文件

- **Given** 用户希望同一文件在本次任务内不再重复授权，或方案已确认后搭档请求批准一批文件
- **When** 用户选择“允许并记住”或批准这批文件
- **Then** 该文件/这批文件进入任务信任集合（批量批准同时加入计划清单）
- **And** 后续写入这些文件不再逐个弹卡

### Scenario: 低危委托

- **Given** 用户已开启低危委托
- **When** 搭档请求低风险文件操作
- **Then** 系统可自动授权
- **And** 高危命令、清单外文件、沙箱外文件永不因委托自动放行

### Scenario: 任务边界重置

- **Given** 用户确认了一个新目标
- **When** 任务边界开始
- **Then** 信任集合、文件批准标记、拒绝记忆被清空

## Requirement: 动作属性与只读判定

系统应以“动作属性”而不是模型自评来决定放行/询问/拦截；只读判定必须 fail-closed，任何可能产生写副作用的形态都不得被当作只读。

### Scenario: 只读命令链

- **Given** 一条命令由多个段组成
- **When** 任一段可能是危险命令且不是只读形态
- **Then** 整条命令被视为高危，要求授权

### Scenario: 只读命令的只读参数形态

- **Given** 危险命令以只读参数形态出现（版本查询、帮助、查找可执行文件）
- **When** 判定动作属性
- **Then** 该段可被视为只读

### Scenario: 文件写入形态

- **Given** 命令包含原地修改、执行子命令、删除文件、输出到文件等写副作用形态
- **When** 判定动作属性
- **Then** 该动作被视为高危，必须授权

### Scenario: 网络只读

- **Given** 命令是只读网络请求（GET/HEAD，且无上传/落盘/写远端标志）
- **When** 目标是本机地址
- **Then** 可自动放行
- **And** 目标是外网时要求授权

### Scenario: 空命令或未知形态

- **Given** 命令为空或无法确认只读
- **When** 判定动作属性
- **Then** 按高危处理（fail-closed）

## Requirement: 读取边界

系统应区分项目内读取与项目外读取；项目内自动，项目外必须由用户授权。

### Scenario: 读取项目内文件

- **Given** 文件位于当前项目根内
- **When** 搭档请求读取
- **Then** 系统自动放行

### Scenario: 读取项目外文件

- **Given** 文件位于当前项目根外
- **When** 搭档请求读取
- **Then** 系统要求用户授权
- **And** 用户拒绝时文件内容不被读取

### Scenario: 不存在的文件

- **Given** 搭档请求读取一个不存在的文件
- **When** 文件位于项目根内
- **Then** 系统可返回同目录下的文件名提示，帮助搭档定位
- **And** 文件位于项目根外时不得列出目录内容

---

## Requirement: 沙箱与快照

系统应以项目根作为路径基准与信任边界；写入前保留快照，用户可回滚；沙箱外写入必须逐次授权。

### Scenario: 路径规范化

- **Given** 搭档给出相对路径、绝对路径或误带项目目录前缀的路径
- **When** 系统解析目标路径
- **Then** 路径被规范化为项目根基准
- **And** 不产生双重嵌套路径

### Scenario: 写入前快照

- **Given** 用户批准写入或编辑一个已存在的文件
- **When** 系统执行写入
- **Then** 原文件内容被保存为快照
- **And** 用户可在工具卡上回滚

### Scenario: 回滚

- **Given** 文件存在写入前快照
- **When** 用户选择回滚
- **Then** 文件恢复为快照内容
- **And** 工具卡状态变为“已回滚”

### Scenario: 无快照回滚

- **Given** 文件是新创建的，没有旧内容快照
- **When** 用户选择回滚
- **Then** 系统返回“无可恢复内容”，不伪造成功

### Scenario: 沙箱外写入

- **Given** 目标文件位于项目根外
- **When** 搭档请求写入
- **Then** 系统必须逐次请求用户授权，不得因任务信任或低危委托自动放行

## Requirement: 取消与进程清理

系统应允许用户随时停止正在执行的命令；退出应用时必须清理自己启动的进程，且不得误杀非自己记录的进程。

### Scenario: 用户停止当前命令

- **Given** 有正在执行的本机命令
- **When** 用户点击停止
- **Then** 当前命令的进程组被终止
- **And** 工具卡显示“已停止”

### Scenario: 无活动命令时停止

- **Given** 没有正在执行的本机命令
- **When** 用户请求停止
- **Then** 系统返回“无活动命令”，不产生副作用

### Scenario: 应用退出清理

- **Given** 应用退出或关窗
- **When** 执行清理
- **Then** 只终止 NeonForge 自己记录的进程
- **And** 用户自己的进程不受影响

### Scenario: 无效进程标识

- **Given** 进程标识缺失或不是正数
- **When** 系统执行清理
- **Then** 系统跳过该标识，不得向当前进程组发送终止信号
