# UI 组件规格

> 每个可复用 UI 组件的所有状态、尺寸、行为和用法。
> 组件命名采用 BEM 风格：`nf-{component}__{element}--{modifier}`

---

## 1. Button（按钮）

### 变体

| 变体 | 类名 | 用途 |
|------|------|------|
| Primary | `.nf-button--primary` | 主要操作（继续、发送、确认全部） |
| Secondary | `.nf-button--secondary` | 次要操作（调整、取消、稍后） |
| Ghost | `.nf-button--ghost` | 最低优先级（换个方案、我知道了） |
| Icon | `.nf-button--icon` | 纯图标（关闭、折叠、切换视图、发送） |
| Link | `.nf-button--link` | 文字链接（打开已有项目、从零开始、+ 新任务、显示代码） |

### 色值

| 变体 | 背景 | 文字 | 边框 |
|------|------|------|------|
| Primary | `--nf-blue` (#6366F1) | #FFFFFF | none |
| Secondary | `--nf-bg-input` (#262044) | `--nf-text-primary` | `--nf-border` |
| Ghost | transparent | `--nf-text-secondary` | none |
| Icon | transparent | `--nf-text-secondary` | none |
| Link | transparent | `--nf-blue` | none |

(hover: 各背景亮度 +5%.)

### 尺寸

| 尺寸 | 高度 | 水平 padding | 字号 | 适用 |
|------|------|-------------|------|------|
| `sm` | 28px | 12px | 12px | 标签、任务状态 |
| `md` | 36px | 16px | 14px | 标准按钮 |
| `lg` | 48px | 24px | 16px | 强调按钮（继续、全部接受） |

### 状态

| 状态 | 触发 | 视觉 |
|------|------|------|
| default | 初始 | 见色彩表 |
| hover | 鼠标悬停 | 背景加深 5% |
| active | 鼠标按下 | 背景加深 10%，scale 0.98 |
| focus | Tab 聚焦 | 2px 蓝色外框（`box-shadow: 0 0 0 2px --nf-blue`） |
| disabled | 不可操作 | opacity 0.4, cursor not-allowed |
| loading | 操作进行中 | 文字替换为 16px spinner, 按钮保持原宽度 |

### 间距

相邻两个按钮间距：8px
按钮组（逐处态示例：[全部接受并写入] [全部拒绝]；摘要态用 [逐处审查]）：两个按钮间距 8px，和上方内容间距 16px。

## 2. Input（输入框）

### 变体

| 变体 | 用法 |
|------|------|
| Standalone | 独立输入框（启动页、新建项目页） |
| Inline | 搭档对话框底部输入框 |
| Expandable | diff 批注输入框（初始隐藏，点击出现） |

### 尺寸

| 属性 | Standalone | Inline | Expandable |
|------|-----------|--------|------------|
| 宽度 | 520px 固定 | 100% | 100% |
| 最小高度 | 48px | 36px | 36px |
| 最大高度 | 120px（自动扩高） | 120px | 72px |
| 字号 | 16px | 14px | 14px |
| 行高 | 1.5 | 1.5 | 1.5 |

### 状态

| 状态 | 视觉 |
|------|------|
| default | border: 1px solid `--nf-border`, 背景: `--nf-bg-input` |
| hover | border-color 加深 |
| focus | border: 1px solid `--nf-blue`, box-shadow: 0 0 0 3px rgba(59,130,246,0.15) |
| disabled | opacity 0.4 |
| error | border: 1px solid `--nf-red` |

### 附加元素

**Inline 输入框右下角：**
- 发送按钮（Icon 变体）：输入框有内容时显示（opacity 0→1, 0.15s），无内容时隐藏（opacity 1→0）
- 按钮图标：↑（箭头向上）

**占位文字：**
- Standalone: "用自然语言描述..."
- Inline: "告诉搭档你想做什么..."

## 3. MessageBubble（消息气泡）

### 变体

| 变体 | 对齐 | 背景 |
|------|------|------|
| User | 靠右 | `--nf-bubble-user`（浅蓝） |
| Partner | 靠左 | `--nf-bubble-partner`（浅灰） |

### 尺寸

| 属性 | 值 |
|------|-----|
| 最大宽度 | 85% |
| padding | 8px 12px |
| 圆角 | 12px |
| 字号 | 14px |
| 行高 | 1.5 |
| 消息间距 | 12px |

### 动画

**搭档消息出现：**
- opacity 0→1, translateY(4px→0)
- duration: 0.15s, ease-out
- 每条消息按段落分割，段落间隔 0.3s
- 多条消息连续出现时，最后一条滚动到视口底部（smooth scroll）

**用户消息出现：**
- 瞬间显示，无动画

### 分段显示逻辑（搭档消息）

- 搭档的每条回复先按空行分割为段落
- 每段间隔 0.3s 依次显示
- 短段落（< 50 字）：整段同时出现
- 长段落（> 50 字）：逐句出现，句间隔 0.15s
- 用户在此期间点击其他地方或打字 → 剩余段落立刻全部显示

## 4. BreathBar（呼吸光条）

### 用途

显示搭档的活跃状态。仅一条，位于对话区顶部。

### 尺寸

- 宽：100%（对话区宽度）
- 高：2px

### 状态

| 状态 | 颜色 | 动画 |
|------|------|------|
| idle（搭档未激活） | — | 隐藏（height: 0, opacity: 0） |
| working（分析/修改中） | `--nf-blue` | opacity 在 0.4↔1.0 循环，周期 2s, ease-in-out |
| waiting（等待用户确认） | `--nf-amber` | opacity 在 0.4↔1.0 循环，周期 1s（更快，暗示"需要你"） |

## 5. TaskItem（任务列表项）

### 结构

```
┌─────────────────────────────────┐
│ ●  修 Bug #42          48px     │
│    修改中 · 2/3 文件   ─────    │
└─────────────────────────────────┘
```

- 总高：48px
- 左侧：状态圆点（12px）+ 内边距 8px
- 标题：14px, font-weight 600
- 副标题：11px, `--nf-text-secondary`
- 圆点和标题垂直居中

### 任务状态

| 状态 | 圆点 | 颜色 | 含义 |
|------|------|------|------|
| executing | ● 实心 | `--nf-blue` | 当前正在执行（分析或修改） |
| review | ◉ 半实心 | `--nf-blue` | 待审核 |
| queued | ○ 空心 | `--nf-text-secondary` | 排队等待执行 |
| done | ✓ | `--nf-green` | 已完成并写入 |
| cancelled | ✗ | `--nf-text-secondary` | 已取消 |

**选中态独立于任务状态：** 用户点击任务列表项 → 背景变为 `--nf-bg-selected`，左侧 3px `--nf-blue` 竖条。选中态不代表任何任务状态——用户可以选中任何状态的任务查看详情。

### 交互

| 行为 | 反馈 |
|------|------|
| hover | 背景色变为 `--nf-bg-hover` |
| 点击 | 切换到该问题。交付包和产物区更新。 |
| 选中态 | 背景色 `--nf-bg-selected`（比 hover 更深） |

## 8. DiffView（Diff 视图）

### 结构

```
┌──────────────────────────────────────┐
│ 审核改动: 文件 1/2                    │  顶部导航
│ ◀ 上一文件    下一文件 ▶              │
├──────────────────────────────────────┤
│                                      │
│  src/payment.ts                      │  文件名
│  ─────────────────────────────────   │
│                                      │
│  第 42 行                             │  行号
│  - 旧代码（红色背景，rgba红色0.15）     │  删除行
│  + 新代码（绿色背景，rgba绿色0.15）     │  新增行
│                                      │
│  ─────────────────────────────────   │
│                                      │
│  改动 2/4                            │  当前位置
│                                      │
│  [✓ 接受] [✗ 拒绝] [💬 批注]         │  操作按钮
│                                      │
├──────────────────────────────────────┤
│ [全部接受并写入] [全部拒绝]                  │  底部批量操作
└──────────────────────────────────────┘
```

> 底部次按钮按模式不同：
> - 摘要态：[全部接受并写入] [逐处审查]
> - 逐处态：[全部接受并写入] [全部拒绝]

### 默认摘要视图

Diff 审核的默认入口。搭档修改完成后先展示改动摘要，而非逐处。

```
┌──────────────────────────────────────┐
│ 改动摘要                              │
│ src/payment.ts · 2 处改动            │
│ src/routes.ts  · 2 处改动            │
│ 共 2 文件，4 处改动                    │
│ ─────────────────────────────────── │
│ [全部接受并写入]（主按钮，primary lg）  │
│ [逐处审查]（次按钮，secondary lg）      │
└──────────────────────────────────────┘
```

- 点「全部接受并写入」→ ConfirmStrip 滑出 → 确认 → 原子 apply
- 点「逐处审查」→ 进入逐处模式（见下方）

### 逐处审核逻辑

- 当前改动自动滚动到视口中央
- 当前改动行的背景色增强 10%（比其余改动更突出）
- 操作当前改动后，自动滚动到下一处，平滑滚动（behavior: smooth）
- 当前文件全部审核完 → 自动跳到下一文件

### 批注输入框

- 点击 💬 后，当前改动下方滑出输入框（max-height 0→36px, 0.2s）
- 占位："这里改成什么？"
- Enter 发送 → 输入框替换为"已告诉搭档，正在改..."
- 搭档返回新 diff → 输入框消失，新 diff 替换

### 确认条（ConfirmStrip，非模态）

```
┌────────────────────────────────┐
│                                │
│  确认写入全部 4 处改动？             │
│                                │
│  [写入]      [取消]         │
│                                │
└────────────────────────────────┘
```

- 在 diff 视图底部，非模态，不遮罩
- 和 diff 内容在同一层级
- 出现：opacity 0→1, 0.15s, ease-out

## 9. FileTree（文件树）

### 结构

```
📁 src/
  ├─ 📁 components/
  │   ├─ 📄 Button.tsx
  │   └─ 📄 Modal.tsx
  ├─ 📁 utils/
  │   └─ 📄 helpers.ts
  └─ 📄 index.ts
```

- 宽：240px（默认），可折叠至 0
- 折叠动画：width 过渡 0.2s
- 展开时在代码编辑器左侧
- 文件树顶部有一个"折叠"按钮（← 图标）

### 文件状态标记

| 状态 | 视觉 |
|------|------|
| 正常 | 无标记 |
| 搭档正在修改 | 文件名旁蓝色圆点 ●（12px, `--nf-blue`） |
| 修改完待审核 | 文件名旁绿色圆点 ●（12px, `--nf-green`） |
| 文件新建中 | 文件名旁闪烁的蓝色圆点 + 文件项从上方"落入"（见下方动画） |

### 新文件出现动画

```
新文件从父目录下方出现:
  transform: translateY(-8px) → 0
  opacity: 0 → 1
  duration: 0.4s
  easing: cubic-bezier(0.34, 1.56, 0.64, 1)  ← 弹性效果
```

同级目录中的已有文件不受影响。

## 16. ConfirmStrip（确认条）

### 用途

Diff 审核中「全部接受并写入」的确认操作。非模态，不打断用户。

### 结构

```
┌──────────────────────────────────────────────┐
│  确认写入全部 4 处改动？                        │
│  [写入] [取消]                                 │
└──────────────────────────────────────────────┘
```

- 位置：Diff 视图底部，宽度 100%
- 背景：`--nf-bg-panel`，上边框 1px `--nf-border`
- 不遮罩、不居中、不影响其他区域操作
- 按钮：主按钮 [写入]（primary md）、次按钮 [取消]（secondary md），间距 8px
- 出现：opacity 0→1，translateY(4px→0)，0.15s，ease-out
- 消失：opacity 1→0，translateY(0→4px)，0.1s

## 意图确认组件（2026-08-16 新增——第 6 轮产品文档审计 #1；规格依据：`intent-confirmation-domain-design.md` §3.2 值对象；S3 实现前置）

### 方案卡（PlanCard——PlanProposal 渲染）

```
┌──────────────────────────────────────────┐
│ 💡 执行方案                             │
│ 一句话方案：用 Three.js 搭 3D 射击游戏    │
│ ─────────────────────────────────────── │
│ 📄 文件清单（4）                         │
│   - package.json   项目配置+依赖         │
│   - index.html     游戏入口              │
│   - src/main.js    游戏逻辑              │
│   - src/style.css  样式                  │
│ ⚠️ 我的假设（3）                         │
│   - 用 Three.js（浏览器 3D 引擎）        │
│   - 第一人称+准星（你未指定，我按常见做） │
│   - 60 秒倒计时计分（可改）              │
│ ✅ 验证计划（2）                         │
│   - npm install && npm run dev 能起服务  │
│   - 打开页面能开枪、打中加分             │
│ ─────────────────────────────────────── │
│ [批准并执行] [修改方案] [重出]           │
└──────────────────────────────────────────┘
```

- 数据源：PlanProposal（summary/files[{path,reason}]/assumptions/verificationPlan）
- **假设清单必须显式呈现**（用户确认的是「看到全部假设并接受」——A0 §3.6/§5）
- 按钮语义（2026-08-16 设计 §3.4）：批准并执行 → confirm；修改方案 → reject(kind='modify')+修正内容输入；重出 → reject+重提议引导
- 出现：模型输出方案提议（proposal.plan 事件）且决策点=plan 时；会话级 PENDING 冻结生效
- 交互：批准后 plannedFiles 由 PlanProposal.files 派生（追加语义 A0 §5）

### 解决确认卡（ResolutionCard——完成声明+证据对账渲染）

```
┌──────────────────────────────────────────┐
│ 🎯 搭档说解决了——请对账                 │
│ 声明：游戏做好并在浏览器打开             │
│ ─────────────────────────────────────── │
│ ✅ 证据（系统核验）                      │
│   - npm test → 2 passed（系统代跑 ✓）    │
│   - curl localhost:5190 → 200（系统代跑 ✓）│
│ ⚠️ 未核验：服务截图（需你确认）          │
│ 对照你的目标：                           │
│   - 能开枪打中目标 ✅ → 你验证打中了？    │
│   - 有得分显示 ✅ → 你看到分数了？       │
│ ─────────────────────────────────────── │
│ [确认解决] [还要改（带原因）]            │
└──────────────────────────────────────────┘
```

- 数据源：CompletionClaim+CompletionEvidence（verification/diffs/pendingQuestions）
- **无证据不对账**：verifyCompletion 未通过（证据空/未核验项/pendingQuestions 非空）→ 卡不弹，回填「缺验证」引导（completion.evidence_missing 事件）
- 证据呈现分级：系统核验通过（✓）/未核验（⚠️ unverifiable——提示用户自行判断）
- 按钮语义：确认解决 → confirm（resolution 确认——问题台账关闭联动）；还要改 → reject(kind)+原因

### 拒绝原因选择器（RejectReasonPicker）

```
┌──────────────────────────────┐
│ 为什么不行？（可选原因）       │
│ ( ) 方向不对（不是我要的）     │
│ ( ) 范围太大/太小              │
│ ( ) 太复杂（换个简单做法）     │
│ ( ) 信息不全（还有没说的）     │
│ ( ) 其他：________________    │
│ [确认拒绝]  [取消]            │
└──────────────────────────────┘
```

- 数据源：RejectReason（kind: direction/scope/complexity/missing-info/modify/other + text + target）
- 出现：确认卡/授权卡上的拒绝类按钮（重新描述/修改方案/还要改/拒绝授权）点击时展开（非模态层）
- modify 由「修改方案」类按钮直接触发（不经过选择器——kind 固定）
- 提交后：decision.resolved 事件携带 RejectReason → 回填模型（Cline denial reason/Deep Code「不要绕过」方向）+ actionGate 同轮同类短封（授权拒绝）
- 交互：必选一项（kind）或自由文本（other）——「确认拒绝」才生效；取消不提交

| RejectReasonPicker | RejectReason | decision.resolved（reject+kind）| S3 |
