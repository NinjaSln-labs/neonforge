## 一、视觉原则（v2）

1. **对话是店面**：第一眼是「说出你的问题」+ 场景卡片——不是工程目录/编辑器
2. **问题为一等公民**：问题台账（左）状态可见；交付包（右）产物+验收对照
3. **行动可见**：agent 行动节点链（思考→执行→待确认）靛→紫→橙流动——签名元素
4. **色彩有能量**：深紫底 + 三 accent 霓虹（靛/紫/橙）——非中性黑，有生命力
5. **克制**：大胆只在签名（行动节点/聚焦渐变），其余安静

- 色彩：`--nf-bg #120F1E` · `--nf-bg-panel #1A1530` · `--nf-bg-elevated #262044` · 靛 `#6366F1` · 紫 `#A855F7` · 橙 `#FF8A00` · 暖白 `#F3F0FF`（2026-08-16 第 18 轮审计 #1：原 --nf-elevated——03 终版名 --nf-bg-elevated）

## 一、视觉原则

### 1.1 四个设计目标

| 目标 | 用户感受 | 实现手段 |
|------|---------|---------|
| **安静** | "不累眼睛" | 暗色为主，减少高对比区域，大面积中性色 |
| **层次** | "知道该看哪里" | 三层深度：背景<面板<浮层，用亮度差而非边框区分 |
| **聚焦** | "搭档在工作，我能感知到" | 蓝色作为唯一强调色，只在搭档相关处出现 |
| **熟悉** | "和 VS Code 差不多" | 编辑器区域复用 VS Code 暗色主题，降低迁移成本 |

### 1.2 配色策略

整个应用只用暗色主题。浅色不做。

**为什么只有暗色：** 写代码的人绝大多数用暗色主题。双主题维护成本高，分散精力。把一种做到极致。

**蓝色克制使用：**
- 搭档相关：按钮主色、呼吸光条、消息中的文件引用
- 聚焦态：输入框聚焦边框
- 链接和交互提示
- **不在**：大面积背景、普通文字、装饰元素

蓝色在整个界面中的面积占比不超过 3%。它是一种信号，不是一种风格。

## 三、三层深度

### 3.1 深度模型

暗色主题下，层次靠亮度差而非阴影：

```
Layer 0 — 应用背景      #1E1E1E   最暗，最远
Layer 1 — 面板背景      #252526   稍亮
Layer 2 — 输入框/卡片    #2D2D2D   交互区域
Layer 3 — 浮层(弹窗等)   #2D2D2D + 阴影  最前
```

视觉规律：**越靠近用户的界面元素越亮。**

### 3.2 各界面元素在哪一层

| 元素 | 层级 | 背景色 |
|------|------|--------|
| 窗口背景 | L0 | `#1E1E1E` |
| 标签栏 | L0 | `#1E1E1E` 更深区域 |
| 搭档面板 | L1 | `#252526` |
| 详情面板 | L1 | `#252526` |
| 文件树 | L1 | `#252526` |
| 状态栏 | L1 | `#252526` |
| 编辑器 | L0 | `#1E1E1E` |
| 消息气泡（搭档） | L2 | `#2D2D2D` |
| 消息气泡（用户） | L2 | `#1A3A5C`（有色彩，跳出来） |
| 输入框 | L2 | `#2D2D2D` |
| 任务列表 | L1 | 继承面板 |
| 任务项（选中） | L2 | `#094771`（蓝色半透明） |
| 通知卡片 | L3 | `#2D2D2D` + 阴影 |
| 确认条（ConfirmStrip） | L1 | `#252526` |
| 快捷指令下拉 | L3 | `#2D2D2D` + 阴影 |

### 3.3 不靠边框分割

面板之间用 1px 线分割（`#3E3E3E`），但同一面板内的区块尽量不用线，用间距和背景色差区分。

比如：消息之间隔着 12px，不用分割线。详情面板的推理过程和修改计划用间距（16px）+ 轻分割线（1px `#2D2D2D`，比面板背景仅亮一点）。

### 10.3 颜色使用原则（给设计师）

- **蓝色 `#3B82F6`** — 唯一强调色。只在需要"用户看这里"时用。其他地方不用。
- **绿色 `#22C55E`** — 成功/确认。不要和其他颜色混用。
- **红色 `#EF4444`** — 错误/拒绝/删除。不要用在警告场景。
- **琥珀 `#F59E0B`** — 仅警告/等待。不要用在错误。
- 四种强调色各有明确语义，不互换。
