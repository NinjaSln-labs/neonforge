## 一、产品定义

### 1.1 这是什么

一个桌面应用。用户打开项目，和一个叫"搭档"的 AI 一起写代码。

用户说想法 → 搭档分析出方案 → 用户确认 → 搭档动手改 → 用户审核 → 完成。

### 1.2 核心原则（所有设计决策的源头）

1. **搭档不是工具。** 用第一人称"我"，称用户为"你"。像人一样说话。
2. **每一步用户都可控。** 搭档不替用户做决定。改动不直接写入文件。
3. **透明不炫技。** 搭档在想什么、看了什么文件，用户能看到。但不说技术术语。
4. **安静，只在必要时提醒。** 不用弹窗打断用户。确认用面板内提示条。主动提醒默认关闭。
5. **上手不学。** 不需要注册、不需要学 IDE 指令、不需要记快捷键。

**原则 → 设计映射表（专家评审补强：原则执行可验证，防「审了结构没审原则」）**

| 原则 | 落地设计（§对应） | 反例（违规即缺陷） |
|------|------------------|-------------------|
| 1 搭档不是工具 | 第一人称措辞（§7.1 句式表）、「搭档」称呼贯穿全文 | 出现"系统/助手/模型"等工具化自称；用 🎉😂 等违规 emoji（§7.2） |
| 2 每一步可控 | 写入模型（§3.5：接受=暂存、写入=原子 apply）、三步工作流（§4.1）、任务圆点状态（§3.6） | 任何绕过审核直接写文件的路径；无确认的自动执行 |
| 3 透明不炫技 | 推理动效时间轴（§3.4）、「本轮用量」折叠（§3.3）、@引用/搭档须知（§3.9） | 推理过程不可见；面向用户出现技术术语（LSP/缓存/KV 等） |
| 4 安静 | 非模态提示条（§3.5）、主动提醒默认关闭（§9 设置）、错误用面板内横幅 | 弹窗/模态打断；默认开启的打扰式提醒 |
| 5 上手不学 | 无需注册（§1.3）、快捷键为可选增强（§6）、非技术视图（§3.8）、输入<5 字给芯片（§3.2） | 首次使用强制教程/引导流程；核心操作依赖快捷键 |

**使用规则**：审计/评审时按本表逐原则核查——发现反例即记缺陷（级别按影响）；新增设计若与任一原则冲突，需先改原则或显式豁免。

**实现期核查（专家评审补强）**：每个工程切片（tickets 01-08）完成后，对照本表核查本片涉及交互——凡触发「反例」即算缺陷需修；切片完成标准中附「原则核查」勾选项。

**原则间冲突裁决记录（专家评审补强）**：
| 冲突 | 裁决 | 落点 |
|------|------|------|
| 「5 上手不学」vs「2 每步可控」（非技术用户想一键接受 vs 每步审核） | 非技术视图（§3.8）以「全部接受并写入」为主路径（改动说明先行），逐处审查为可选项——可控性保留在"写入前有摘要+可拒绝"，不牺牲上手 | §3.8 |
| 「4 安静」vs「2 每步可控」（可控需要反馈 vs 不打扰） | 反馈走非模态提示条/状态栏，不弹窗 | §3.5/§4.3 |

### 1.3 首次使用前提

NeonForge 需要 DeepSeek API Key 才能工作。首次打开时：

- 如果本地已有有效 Key：自动检测，直接进入启动页
- 如果没有：显示简洁配置页（粘贴 Key → 验证 → 进入）
- 网络不通：提示"无法连接，请检查网络"，提供 [跳过（离线不可用）]

原则的「不需要配置」指不需要学 IDE 操作，不是零依赖。

### 1.4 用户

两类用户，一套体验：

- **会写代码的人** — 看到代码编辑器、文件树、diff。主打效率。
- **不会写代码的人** — 看到页面预览、功能描述。主打可理解。

### 3.3 主工作区


**呼吸光条位置（修复审计 Minor 2）：**

在搭档面板顶部（不是消息上方）。working 态蓝色周期 2s，waiting 态琥珀色周期 1s。

**状态栏：**

```
🟢 就绪 │ main │ 待审核: 4 处
```

- 显示：状态、分支名、改动状态（待审核 N 处 / 已暂存 N 处）
- 「接受」= 暂存改动（N=处改动），不立即写入
- 「全部接受并写入」= 原子 apply 到文件系统

**详情面板底部（修复审计 M6）：**

折叠行，默认收起：
```
▸ 本轮用量
  （展开后：12K tokens │ 缓存命中 87%）
```

### 3.4 搭档的分析展示

**推理动效时间轴（以视觉规范 `product/05-visual-spec.md` §6.1 为权威）：**

```
t=0.0s   详情面板从右侧滑入（0.25s），呼吸光条→蓝色
t=0.3s   "🧠 怎么看这个问题的" 标题出现
t=0.5s   文件列表逐项出现（每项 0.1s）
t=1.3s   停顿
t=1.6s   "排除了这些可能" 逐项出现（每项 0.1s）
t=2.3s   停顿
t=2.6s   "确认"出现，结论文字蓝色
t=3.0s   推理展示完毕
t=3.2s   "📝 修改计划"出现
t=3.8s   分析展示完毕，呼吸光条→amber，按钮出现
```

用户在此期间点击其他地方或打字 → 剩余动画立刻全部显示。

### 3.5 Diff 审核

**默认审核模式（修复审计 M5）：**

用户点待审核任务或搭档改完后：

1. **先展示改动摘要**：哪些文件、几处改动、每处简述
2. 底部按钮：主按钮「全部接受并写入」、次按钮「逐处审查」
3. 用户点逐处审查 → 进入逐处模式（同原规格）

**写入时机（修复审计 M3）：**

- 逐处点 ✓ 接受 = 暂存（标记为已确认，不写文件）
- 点「全部接受并写入」或逐处审完点「写入文件」= 一次性原子 apply
- 状态栏显示「待审核: N」→ 接受后「已暂存: N」→ 写入后清零

**全部接受确认（修复审计 M1）：**

不用弹窗。diff 视图中出现确认提示条：

```
┌──────────────────────────────────────────────┐
│  确认写入全部 4 处改动？                        │
│  [写入] [取消]                                 │
└──────────────────────────────────────────────┘
```

提示条在编辑器底部，不遮挡，不模态。

**完成状态：**

```
✅ 改动已写入文件。
```

无 🎉，无庆祝动画。

### 3.6 任务列表

**多任务模型（修复审计 C5）：**

V1 采用**串行执行队列**：

- 可创建多个任务。同时仅一个在执行（分析/修改）
- 其他排队。当前任务审核完成后自动开始下一个
- 涉及同一文件：后续任务基于前一任务写入后的新版本执行
- 用户可拖动任务调整队列顺序

任务状态圆点重新设计（修复审计 Minor 10）：

| ● 蓝色实心 | 当前正在执行 |
| ◉ 蓝色半实心 | 待审核 |
| ○ 灰色空心 | 排队中 |
| ✓ 绿色 | 已完成 |
| ✗ 灰色 | 已取消 |

### 3.7 新建项目

**非技术闭环（修复审计 C2）：**

第四步完成态：

```
项目已创建。

[一键安装并预览]

（安装依赖 → 启动 → 应用内预览）
- 安装失败 → 展示错误 + [重试] [查看详情] [跳过]
- 端口占用 → [换个端口] [取消]
- 权限不足 → 提示文件夹权限
```

- 点击按钮后，自动执行 install + dev
- 进度显示在按钮位置（"正在安装依赖..." → "正在启动..."）
- 启动后在主工作区出现应用内预览面板
- 非技术用户不需要打开终端

### 3.8 非技术用户视图

审核模式（修复审计 M5）：

```
搭档改了你的博客首页：

改动说明:
· 标题字体变大了
· 文章卡片现在是两栏
· 加了"阅读更多"按钮

[全部接受并写入] [不满意，告诉搭档...]
```

点「不满意」展开输入框（批注等价）。默认展示摘要，接受为主路径。

### 3.9 上下文控制（修复审计 M2）

V1 提供最小上下文控制：

**@引用文件：**
- 搭档输入框输入 `@` → 弹出最近文件列表
- 选择 → 文件名以蓝色标签出现在输入框
- 搭档优先看被 @引用的文件

**搭档须知（项目规则）：**
- 项目根目录 `.neonforge` 文件
- 用户编辑自然语言：约定、技术栈、风格
- 搭档每次分析自动读取
- 文件树右键"创建搭档须知"可生成模板

### 4.2 状态变化表

| 阶段 | 呼吸光条 | 状态栏 | 任务圆点 | 用户下一步 |
|------|----------|--------|----------|------------|
| 分析中 | 蓝 working | — | ● | 等待分析结束 |
| 等确认方案（仍 ●，光条琥珀） | 琥珀 waiting | — | ● | [继续] / [调整] |
| 修改中 | 蓝 working | — | ● | 等待改完 |
| 待审核 | — | 待审核: N | ◉ | 摘要或逐处审核 |
| 已暂存 | — | 已暂存: N | ◉ | ConfirmStrip → 写入 |
| 已写入 | — | 清零 | ✓ | 下一任务或结束 |

## 六、快捷键

| 快捷键 | 作用 |
|--------|------|
| `Enter` / `Cmd+Enter` | 焦点在输入框 → 发送（两者等效） |
| `Enter` | 焦点在 Diff 改动区 → 接受当前改动 |
| `Cmd+Enter`（Diff 焦点） | 无效（不发送、不接受） |
| `Cmd+N` | 新任务 |
| `Cmd+E` | @引用当前文件 |
| `↑/↓` | Diff：上/下一个改动 |
| `Delete` | Diff：拒绝当前改动 |
| `Space` | Diff：打开/发送批注 |
| `←/→` | Diff：上/下一个文件 |
| `Esc` | 关闭详情面板 / 取消当前操作 |
| `Cmd+,` | 打开设置 |

## 十一、版本范围

**V1 包含：**

- 首次配置页（API Key）
- 启动页（打开项目 + 从零开始）
- 主工作区（搭档面板 + 代码编辑器 + 文件树）
- 搭档三步工作流
- Diff 审核（默认摘要→全部接受，可选逐处）
- 写入模型（接受=暂存，写入=原子 apply）
- 多任务串行队列
- 新建项目（应用内一键安装并预览）
- 非技术用户视图
- @文件引用 + 搭档须知
- 深色主题（仅深色）
- 设置（语言 / 默认视图 / 提醒开关）

**V1 明确不做：**

- Inline 代码补全
- 多 Agent 并行（Worktree 隔离）
- 插件市场
- Git GUI
- 社交/协作
- 闲聊/画图
- Web 版
- 浅色主题
- 多语言（只做中文和 English）
