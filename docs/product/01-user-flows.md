# 用户旅程图

> 版本：v2.2（v2.0 起始——2026-08-16 bump 对齐 D0 v2.2）
> 对应产品设计规范 `product/00-product-design.md` v2.2（定位重定义：AI 问题工作台——帮用户解决当前的问题）。
> v2 核心变化：问题闭环流（说问题→DoD（DoD 对齐 ⏸ V2——2026-08-15 裁决；V1 以解决确认卡（证据对账）+交付包为可验证闭环）→方案→授权→交付→关闭）
> v2.2（2026-08-16 同步）：方案确认=可审阅方案卡（文件+假设+验证计划，批准/修改/重出）；解决确认=证据对账（模型完成声明必须附证据，不足不弹卡）；拒绝操作带原因选项。、三区布局（会话|对话|产物）、问题台账/交付包、信任阶梯 L1-L4。
> 阅读方式：从上到下是主流程，向右是分支。

## Flow 0：首次配置（API Key）

```
应用首次打开
  │
  ├─→ 检测到有效 API Key
  │     │
  │     └─→ 启动页（Flow 1）
  │
  ├─→ 未检测到有效 Key
  │     │
  │     └─→ 首次配置页（S0）
  │           │
  │           └─→ 用户粘贴 Key + 点击"验证并开始"
  │                 │
  │                 ├─→ 验证成功 → 启动页（Flow 1）
  │                 ├─→ 验证失败 → 输入框变红 + "验证失败，请检查 Key"
  │                 ├─→ 网络不通 → 横幅 + [重试] [跳过（离线不可用）]
  │                 └─→ 验证中 → 按钮 spinner
  │
  └─→ 后续启动 → 检测 Key。过期时搭档对话中提示更新。
```

## Flow 1：启动页 → 打开已有项目

```
启动页
  │
  ├─→ 点击「打开已有项目」
  │     │
  │     └─→ 系统文件选择器
  │           ├─→ 选择了文件夹 → 加载项目（骨架屏）→ 主工作区（Flow 3）
  │           └─→ 取消 → 回到启动页
  │
  ├─→ 输入文字 + 回车
  │     │
  │     ├─→ 少于 5 个字 → 显示二选一芯片：
  │     │     ┌────────────────┐  ┌─────────────────────┐
  │     │     │ 🆕 新建一个项目  │  │ 📂 打开文件夹改这个   │
  │     │     └────────────────┘  └─────────────────────┘
  │     │        │                        │
  │     │        └─→ Flow 4               └─→ 文件选择器 → Flow 3
  │     │
  │     └─→ ≥ 5 个字，可识别为"从零构建" → Flow 4
  │
  └─→ ≥ 5 个字，无法识别意图 → 仍出二选一芯片
  │
  └─→ 点击「从零开始」→ Flow 4
```

## Flow 3：主工作区 — 核心交互（v2 三区：会话 | 对话 | 产物）

```
主工作区（三区：左会话 / 中对话 / 右产物）
  │
  ├─→ 对话区输入「当前的问题」+ Enter（零学习成本，说人话）
  │     └─→ 问题闭环流（Flow 5：分析→DoD（DoD 对齐 ⏸ V2——2026-08-15 裁决；V1 以解决确认卡（证据对账）+交付包为可验证闭环）→方案→授权→交付→关闭）
  │
  ├─→ 会话区（左）：问题台账
  │     ├─→ 新建问题（＋新会话）
  │     ├─→ 历史问题/交付物/复开入口（「上次那个再跑一遍」= 一等操作）
  │     └─→ 问题状态可见（理解中/方案待确认/执行中/待你操作/已交付/已关闭/失败可恢复）
  │
  ├─→ 产物区（右）：工程 / 产物 Tab
  │     ├─→ 工程：文件树（查看 agent 动的文件）
  │     └─→ 产物：交付包（产物 + 做了什么 + 验收对照 + 下一步；开发者可展开 diff）
  │
  ├─→ 交付包操作
  │     ├─→ 验收对照逐项打勾 → 「确认问题关闭」/「继续调整」
  │     ├─→ 超出数字能力部分 → 分步指导（不装能）
  │     └─→ 开发者：diff 审核 → 接受/拒绝（写入模型，L3 授权）
  │
  ├─→ 失败/暂停
  │     ├─→ 失败包（发生了什么/影响/回滚/下一步）
  │     └─→ 半成品可带走 + 断点续做（V1 限制：消息+台账恢复、状态机不跨重启——V2 会话快照，2026-08-15 裁决）
  │
  ├─→ 手动编辑代码（会写代码的用户，可选能力，不影响搭档）
  └─→ Cmd+, → 设置
```

## Flow 4：新建项目

```
新建项目页（描述想法）
  │
  └─→ 输入 + 点击「开始」
        │
        └─→ 搭档分析方案
              │
              └─→ 方案展示页
                    │
                    ├─→ [可以] → 逐步搭建 → 逐文件审核 → 搭建完成
                    ├─→ [调整] → 输入意见 → 重新出方案
                    └─→ [换个方案] → 不同思路出方案
        │
        ▼
  搭建完成
        │
        └─→ [一键安装并预览]
              │
              ├─→ 成功：安装依赖 → 启动 → 应用内预览 → 主工作区（Flow 3）
              │
              ├─→ 安装失败（npm install 报错）
              │     └─→ 展示错误 + [重试] [查看详情] [跳过（仅编辑代码）]
              │
              ├─→ 端口被占用
              │     └─→ "端口 N 被占用。换个端口？" [换个] [取消]
              │
              └─→ 权限不足
                    └─→ "没有写入权限。请检查文件夹权限。"
```

## Flow 5：问题闭环流（v2 核心）

```
用户说出「当前的问题」（对话入口，说人话）
  │
  ▼
① 分析（L1 只读自动）
  ├─→ 过程可见（推理/行动节点，用户可跳过）
  ├─→ DoD 对齐：用用户的话复述问题 + 验收标准（"什么叫解决"）（DoD 对齐 ⏸ V2——2026-08-15 裁决；V1 以解决确认卡（证据对账）+交付包为可验证闭环）
  ├─→ 超出数字能力 → 直接告知：产物 + 分步指导（不装能）
  │
  ▼
② 方案确认（方案卡——PlanProposal：文件清单+假设+验证计划，2026-08-16 升级）
  ├─→ [批准并执行] / [修改方案（带原因）] / [重出]
  │
  ▼
③ 执行（L3 分步授权）
  ├─→ 逐项授权（写入/命令）+ 快照（可回滚）
  ├─→ 发现问题 → 暂停告知 → 确认继续
  ├─→ 网络断开/失败 → 失败包（发生了什么/影响/回滚/下一步）
  │
  ▼
④ 交付包
  ├─→ 产物 + 做了什么 + 验收对照（逐项打勾：怎么验/不对点哪里）
  ├─→ 下一步 / 复跑入口
  ├─→ 开发者：diff 审核（Flow 6：接受/拒绝 → 写入，L3 授权）
  │
  ▼
⑤ 用户确认问题关闭（交付 ≠ 解决，以关闭为终态；解决确认=声明+证据对账——模型完成声明附可核验证据，证据不足不弹「已解决」卡、引导补证据）
  ├─→ 已关闭 → 问题台账归档（可复开/复跑）
  └─→ 继续调整（拒绝带原因——RejectReasonPicker：方向/范围/复杂度/信息不全/其他）→ 回到②/③
```

**开发者扩展**（异常修复/0-1 交付）：
- 异常修复：授权分析 → 定位 → 方案确认 → 修复 → 充分测试 → 授权部署（备份→热更新→复核）→ 反馈
- 0-1 交付：无阶段确认驱动——目标确认 → 能力检查 → 方案批准 → 动手产出 → 解决确认（证据对账）（无固定阶段；确认卡推进——每步可确认、迭代可 demo）

## Flow 6：Diff 审核

```
进入审核 → 默认展示改动摘要
  │
  ├─→ 底部：[全部接受并写入]（主按钮）[逐处审查]（次按钮）
  │
  ├─→ [全部接受并写入]
  │     │
  │     └─→ 确认条（非模态）：
  │         "确认写入全部 N 处改动？" [写入] [取消]
  │           ├─→ 写入 → 原子 apply → "✅ 改动已写入文件"
  │           └─→ 取消 → 回到摘要
  │
  ├─→ [逐处审查]
  │     │
  │     └─→ 逐处模式
  │           ├─→ [✓ 接受] → 暂存 → 状态栏「已暂存: N 处」→ 下一处
  │           ├─→ [✗ 拒绝] → 丢弃 → 下一处
  │           ├─→ [💬 批注] → 输入 → 搭档只改此处 → 新 diff
  │           ├─→ 键盘 ↑↓ ← → Enter Delete Space
  │           └─→ 全部审完 → [写入文件] → ConfirmStrip（同「确认写入全部 N 处改动？」）→ 原子 apply
  │
  └─→ 任务标记完成 ✓

中断：
  ├─→ 切换任务 → 进度保留
  └─→ 文件被外部修改 → 提示 → 重新生成 diff（已暂存保留）
```

## Flow 7：任务队列（串行）

```
主工作区
  │
  ├─→ 用户创建任务 → 加入串行队列
  ├─→ 同一时间仅一个任务在执行（分析/修改）
  │
  ├─→ 当前执行中 ● → 分析 → 修改 → 完成 → 用户审核时队列暂停
  ├─→ 排队中 ○ → 等待前一个任务审核完成
  ├─→ 待审核 ◉ → 审核完成后 → 写入 → 标记 ✓ → 下一个开始
  │
  └─→ 涉及同一文件 → 后续任务基于前一任务写入后的版本执行
```

## Flow 8：应用生命周期

```
应用启动
  │
  ├─→ 检测 API Key
  │     ├─→ 有 → 继续
  │     └─→ 无 → Flow 0
  │
  ├─→ 检测是否有上次意外关闭的项目
  │     ├─→ 有 → 自动恢复 + 搭档提示进度
  │     └─→ 无 → 启动页
  │
  ├─→ 应用关闭（有未写入暂存）
  │     └─→ "有 N 处改动已暂存但未写入，关闭后保留" [关闭] [取消]
  │
  ├─→ 应用崩溃 → 下次启动自动恢复
  │
  └─→ API Key 过期 → 搭档提示更新
```

## 关键决策点

| 决策点 | 选项 | 后果 |
|--------|------|------|
| 首次打开 | 有/无 Key | 直接启动页 / 配置页 |
| 启动页输入模糊 | 新建项目 / 打开文件夹 | 明确路径 |
| 分析后 | 继续 / 调整 | 动手 / 重新分析 |
| Diff 审核 | 全部接受并写入 / 逐处审查 | 快速 / 精细 |
| 逐处接受 | 暂存 | 不写入，等确认 |
| 写入前确认 | 写入 / 取消 | 原子 apply / 回到审核 |
| 安装失败 | 重试 / 详情 / 跳过 | 修复 / 诊断 / 仅编辑 |
| 关闭应用（有暂存） | 关闭 / 取消 | 保留 / 继续 |
| 新建任务 | 加入队列 | 等待当前任务结束 |
