## 一、覆盖度核查

| 场景 | 覆盖 | 说明 |
|------|------|------|
| 空目录主链路（read 找不到→回复）| ✅ | |

| 真实项目 read | ✅ | |
| 多轮对话（连续 3 条）| ✅ | 已验证会话隔离 |
| 纯文本（无工具）| ✅ | |

| **write 工具授权 → 真实写文件** | ❌ 缺 | 05 执行层核心能力（diff 写入有单独 A4 但 write 工具授权未测）|

## 二、断言可靠性

1. **[高] 断言弱（假通过风险）**——`waitSettle` 只判「最后消息无'处理中' + 非空 + 状态栏就绪」——**不验证**：
   - 工具卡片是否按预期出现/状态（done/error/need-approval）
   - 模型回复内容是否与请求相关（答非所问也算 PASS）
   - 关键事件序列（tool-call → done 是否发生）
   - 证据：`if (!lastText.includes('处理中') && lastText.trim() && busy === 0 && sb.includes('就绪')) break`——无内容质量/事件断言
2. **[中] 无事件级验证**——未断言「工具调用发生」「done 事件到达」「续聊触发」——纯 UI 文本判断
3. **[低] 无回归基准**——不比较历史基线（只有通过/失败），无法发现「通过但行为退化」

## 三、维护性

1. **[中] 硬编码路径**——`EMPTY_DIR='/tmp/nf-e2e-test'`、`REAL_PROJ='.../apps/desktop'`——换机/换项目需改码
2. **[中] Key 依赖**——`NF_TEST_KEY` 环境变量（无默认/无文档）——CI 或他人无法直接跑
3. **[低] 脚本重复**——e2e-realtime 是 e2e-suite 的单场景子集——可合并
4. **[低] 结果不可追踪**——无报告文件/时间戳——只 console 输出

## 四、建议

1. **技能化**：把「NeonForge 自测规范」做成 SKILL.md（`e2e-self-test` 技能——触发词：跑 E2E/自测/验证全链路）——规定：覆盖矩阵（12 场景）+ 断言标准（事件级 + 内容级）+ 运行命令（`NF_TEST_KEY=... node e2e-suite.mjs`）+ 门禁（改完必跑）
2. **补场景**：write 授权写入、授权后续聊、空回复、Key 失效、超时、上下文保留（6 个缺口）
3. **强化断言**：事件级（工具调用发生/done 到达/续聊触发）+ 内容级（回复含关键语义）
4. **合并脚本**：e2e-realtime 并入 e2e-suite（单场景参数化）；加结果报告文件（.scratch/test-results/ 时间戳）
5. **配置化**：路径/Key 读 config（默认 + 可覆盖）
